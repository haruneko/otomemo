# 字余りのとき音符を割るか — 「音楽的に成立する割り方」の定義・候補の出し方・実現可能性

- 作成: 2026-07-30
- **何の判断のための文書か**：作詞補助（design #31）で句が**字余り**（モーラ数 > 範囲内の音符数）になったとき、**音符を割って（増やして）モーラを収める操作を作るかどうか**を決める材料。求められる水準は「**音楽的に成立する割り方を候補として出せる**」こと。それが立たないなら「**割る機能そのものを作らず、余りは切り捨てる**」が結論になる。どちらでもよい＝正直に判定する。
- 方法：既存の理論・実測 doc の読み直し＋**同梱コーパス統計 `RHYTHM16_DATA`（`apps/api/src/music/motifModelData.ts:5`・POP909由来 2,882パターン / 延べ 17,748小節）の新規集計**＋現行 `flowLyric` のモンテカルロ実測（4,000句×5条件）＋候補生成器のプロトタイプ実測。外部Web調査は行っていない（既存 doc の出典に依拠）。
- 著作権：コーパスからは**統計のみ**（onset パターンの出現回数・位置分布）。リテラルな旋律は一切扱わない。

---

## 0. 結論（先出し）

**見込み＝「条件つきで作る」。** 音楽的に成立する割り方を候補として出す見込みは**立つ**。

理由の芯は3つ：

1. **「どこで割るか」は既存資産だけで決まる。** 実測すると、実曲が1つの音符を1回割るとき、割り位置は**その区間内で拍の重みが最も強い位置 75.8%／2番目に強い位置 16.0%＝上位2階層で 91.8%**（厳密 91.77%・本doc §2-2）。「重み」は `packages/music-core/src/syncopation.ts:23` `metricWeights` がすでに計算できる。＝**割り位置の候補は列挙できるし、実測で裏が取れる**。
2. **出した候補は「実在するか」を照合できる。** 割った結果の1小節 onset パターンは、`RHYTHM16_DATA` の 2,882 パターンに**そのまま引ける**。プロトタイプでは字余り1〜4に対し候補 10〜358本、うち**コーパス既出パターンだけでできた候補が 38〜80%**（§3-3）。＝「機械が作った珍しい形」と「実曲にある形」を分けて人に見せられる。
3. **現行の貪欲法は、上の物差しで測ると明確に不成立**（§2-4）。＝直すべき対象がはっきりしている。

条件（これを満たさないなら作らない）は §4-3 に3つ。最大のものは **4/4 の16分格子に限る**ことと、**貪欲法 `flowLyric` の中身をそのまま残さない**こと。設計含意（§5）＝design §31-5 が結論待ちにしている「音符を割る操作を残すか」に対する答えは「**残す＝候補提示版として作る**」（推し・採否はオーナー裁定）。

## 1. 前提の確認（既存の決めと、いま起きていること）

### 1-1. 現況

- 字余りの言い分けは実装済み＝`phraseStatus`（`packages/music-core/src/lyric.ts:283`）が `{kind:"字余り", count:N}` を返す。**機械は詰めない・削らない・止めない**（design §31-5）。
- 読みを写す `placeMoras`（同 `:207`）は**音符を1つも増やさない**＝モーラが余れば**書かない**。つまり**現状すでに「余りは切り捨て」で動いている**。本doc が問うのは「その上に割る操作を足すか」。
- 音符を割るのは `flowLyric`（同 `:143`）1本だけ。呼び元は3つ＝`apps/web/src/components/PianoRoll.tsx:499`（ボタン「流し込む」・ラベルは `:501`）・`apps/api/src/mcp.ts:961`（`set_lyric`）・`apps/api/src/music/generate.ts:762`（詞先メロ）。
- **design §31-5 の現行の決め（2026-07-30 改訂・コミット済み）**：句の面が配線された画面では**常設の「流し込む」ボタンとかな欄は退役**する。ただし**退役の実施は歌詞パネルの実装と同時**（先に外すと音符を割る唯一の口が消えるため、それまで常設のまま据え置き）。そして**音符を割って合わせる操作を残すかどうかは、「音楽的に成立する割り方を候補として出せるか」の研究の結論待ち**＝出せる見込みが立たないなら操作ごと作らず余りは切り捨て。残す場合の名前は**仮称のまま**（§31-11 裁定待ち16）。
  → **本doc はこの「結論待ち」を埋めるための材料**。§5 は「既に決まっていることの見直し」ではなく、**§31-5 が待っている結論（作る／作らない／条件つき）を証拠から埋める**位置づけ。
- **オーナー裁定**：「っ」「ー」にも音符を立てる。＝`flowLyric` / `placeMoras`（全モーラに1音符）が正で、**`prosody.ts:97` `roleOf`（ー=tie・っ=rest）と `lyricsPlan.ts:30` `isOnsetMora`（ー・っ を onset から外す）は裁定と食い違っている**。割る機能を作る/作らないに関わらず、この2本は裁定側へ寄せる必要がある（§4-2 の穴3）。

### 1-2. この文書が比べている選択肢（4つのうち2つに絞った理由）

`docs/research/2026-07-14-jp-prosody-melody-rules.md` §2.2 と R-07（同 `:94,188`）は、字余りの標準処理を**3つ**挙げている。それに「何もしない」を足した4つが選択肢の全体で、本doc が比べているのは①と④：

| 選択肢 | 中身 | 本doc での扱い |
|---|---|---|
| ① 16分などへ細分化して詰め込む | 音符を割る | **本doc の主題**（§2〜§4） |
| ② 弱拍側で隣接音符に**2モーラ相乗り**（1音符複数モーラ） | 音符を増やさずに収める | **本doc の外**（下記） |
| ③ 特殊拍をタイ吸収 | 「ー」「っ」を前の音符へ吸わせる | **却下**。オーナー裁定「っ・ー にも音符を立てる」と正面から衝突する |
| ④ 何もしない＝余りは切り捨て | 現状（`placeMoras` の挙動） | **①の対抗案**（§4-3） |

**②を本doc の外に置く理由**（落としたのではなく、独立した設計課題として立てるべきという判断）：

- 器が全部「1音符=1モーラ」前提でできている。`placeMoras` の契約3（design §31-2）が「範囲内の音符へ頭から**1対1**」、`noteHighLow`（`lyric.ts:235`）も `kanaEditForNote`（同 `:485`）も同じ1対1で音符とモーラを突き合わせる。②を入れると**この1対1が崩れる**ので、「どの音符に何モーラ載せたか」を保存するデータが要る。それは design §31-1 が「あとで足すだけ」と書いている `alloc?:` の枠であって、**まだ無い**。
- しかも②は**すでに制御されない形で存在している**。`flowLyric` は割り切れなくなると「残りのモーラを最後の音符に連結」する（`lyric.ts:169-172`）。実機で再現すると**1つの音符に10モーラが載る**（§5 の再現実験）。＝②をやるなら「どの音符に・何モーラを・なぜ」を決める設計が要る＝本doc の問い（割り位置の音楽的成立）とは別の問いになる。
- ②は「音符を増やさない」ので、`placeMoras` の不変（音符は増えない）とは両立する。**有望さは否定していない**＝別途立てる価値のある案として残す。

## 2. 「音楽的に成立する割り方」の定義

### 2-1. 定義の形（何を守れば成立と見なすか）

割り方 = 「どの音符を、どの位置で、いくつに割るか」。成立条件を**硬い条件（守れないと候補にしない）**と**柔らかい条件（守れないと下位に沈めるが消さない）**に分ける。硬さの語彙は `docs/research/2026-07-14-jp-prosody-melody-rules.md` §6 の H/S/P に合わせる。

| # | 条件 | 硬さ | 根拠（実測 or 文書） |
|---|---|---|---|
| C-1 | 新しい onset は**16分格子の上**に置く（4/4）。格子外（32分・付点の半分など）を作らない | **H** | 語彙・採取・指標が全部16分格子前提（§2-3） |
| C-2 | 割り位置は**その区間内の拍の重みの上位2階層**（`metricWeights`）に限る | **H** | 実測 75.8%＋16.0%＝**91.8%**（§2-2） |
| C-3 | 割った各断片は**下限音価以上**。下限は拍でなく**実時間（テンポ込み）**で決める | **H** | 現行の下限は 0.25拍固定でテンポを見ない（§2-4・穴1） |
| C-4 | **句末の着地音を割らない**（＝句末音／句平均 の比を落とさない） | **S**（強い） | 実POP 中央値 **1.31倍**・句最終音が最長 27.0%（`2026-07-21-melody-note-value-and-harmonic-rhythm.md` §1.2/§1.3） |
| C-5 | 割った後の**句内音価の変動係数 CV** が帯 **0.50–0.70** に残る | **S** | 同doc §5.1 の受入帯（実装テストの帯） |
| C-6 | 割った後の1小節 onset パターンが**コーパス既出**（`RHYTHM16_DATA` に有る） | **S** | 既出/未出は事実として言える（§3-3） |
| C-7 | 元の句の**ノリ**（`lhlSyncScore` の perBar・`noriTargetBand` の帯）から大きく外れない | **P**（並べ替えのみ） | `2026-07-14-syncopation-sweet-spot.md` §6-2「審判にしない」。実測では**ほとんど散らない**＝主軸にならない（§2-5） |
| C-8 | 新しい音符が**特殊拍（っ・ー）に強いアタックを当てない**／**語を分断しない** | **S** | 同prosody doc A-09・A-10。判定の材料は `analyzeMoras` の `kind` と `reading.words` |
| C-9 | 割ってできた音符の**音高**は既定で直前と同音（同音反復） | **S** | `MOVE_TRANS_DATA` 実測：次が同音＝**23.6%（単独最頻）**・直前が同音なら次も同音 **37.1%** |

**C-8 が効く理由（割り方の話がリズムだけで閉じない）**：`placeMoras` はモーラを音符へ**頭から1対1**で載せる。だから**割る位置を1つ変えるだけで、それ以降のモーラと音符の対応が全部1つずれる**。「っ」が強拍の新音符に当たるか、語の途中で新しいアタックが立つかは、リズム単体では判定できない。＝**候補の評価は（音符列, モーラ列）の対で行う**必要がある。これは定義上の要点で、実装の形も決める。

### 2-2. 割り位置の実測（新規集計・本doc の中核）

**集計の手続き（これがそのまま再現手順）**：`RHYTHM16_DATA`（1小節16枠の onset パターン → 出現回数）から、次を満たす組を全部集める。

1. slot `s` に onset がある。
2. slot `s+g` に onset がある。**ただし `s+g == 16` のときは「次の小節の頭」とみなして常に onset 扱いにする**（パターンは1小節ぶんしか無いため。この前提が無いと g=16＝小節まるごとの音符が1件も成立しない）。
3. `s` と `s+g` の間に onset が**ちょうど1個**ある（＝実曲が「長さ g の音符を1回割った」形に相当）。

`g ∈ {2,4,6,8,12,16}`・各パターンの出現回数で重み付け。**n = 57,240**。

**割り位置の重み階層（区間内で何番目に強い拍か）**

| 階層 | 前提2あり（n=57,240） | 前提2なし＝小節内だけ（n=45,457） |
|---|---|---|
| **1位（区間内で最強）** | **75.82%** | **77.51%** |
| 2位 | 15.95% | 14.75% |
| 3位 | 7.36% | 6.92% |
| 4位 | 0.86% | 0.82% |
| **上位2階層** | **91.77%** | **92.26%** |

→ **上位2階層で 91.8%**。前提2（小節をまたぐ音符を数えるか）を落としても 92.3% で、**結論は前提の取り方に依存しない**。これが C-2 の根拠。

**「中点で割る」との比較**（どちらの規則がよく当たるか）

| 規則 | 一致率 |
|---|---|
| 区間内で最も強い拍位置 | **75.8%** |
| ちょうど中点（等分割） | 68.7% |
| 両方が一致するケース | 64.4% |
| どちらでもない | 19.9% |

開始位置で層別すると性格が分かれる：

| 音符の開始位置 | n | 中点 | 最強拍 |
|---|---|---|---|
| 強拍（4分の頭） | 30,046 | 69.1% | 75.9% |
| 8分裏 | 20,034 | 65.3% | **80.1%** |
| 16分裏 | 7,160 | **76.5%** | 63.4% |

→ **音符が16分裏から始まっているとき（＝食っているとき）だけ、中点等分のほうが強い**。実曲は食いを解消して強拍へ寄せるのでなく、**食ったままの格子で等分する**。＝「常に最強拍へ寄せる」だけの規則は、シンコペした句の性格を壊す（§2-5 と対応）。

**1拍（4slot）の音符を1回割る場合の内訳**（開始 slot 別・「1個だけ割る」ケースの中の比率）

| 開始 slot（拍） | 割らない | 1個割る | 2個以上 | 割り位置 top3 |
|---|---|---|---|---|
| 0（0.00拍） | 24% | 55% | 21% | +0.50拍 **89%** / +0.75拍 8% / +0.25拍 3% |
| 2（0.50拍） | 17% | 62% | 21% | +0.50拍 **91%** / +0.25拍 5% / +0.75拍 3% |
| 4（1.00拍） | 25% | 60% | 15% | +0.50拍 **90%** / +0.25拍 6% / +0.75拍 4% |
| 8（2.00拍） | 35% | 50% | 15% | +0.50拍 **92%** / +0.75拍 5% / +0.25拍 3% |
| 1（0.25拍） | 4% | 34% | 62% | +0.50拍 58% / +0.25拍 27% / +0.75拍 16% |
| 3（0.75拍） | 7% | 35% | 58% | +0.50拍 61% / +0.25拍 27% / +0.75拍 12% |
| 7（1.75拍） | 7% | 41% | 52% | +0.50拍 52% / +0.75拍 **27%** / +0.25拍 20% |

**食い（アンティシペーション）型の割り方**：最強拍そのものでなく、**その16分（1 slot）1つ手前**に置く割り方が **5.30%** ある（前提2の有無によらず同値）。

⚠ **測った定義と、引用しうる先行記述の細分は違う**。`2026-07-14-syncopation-sweet-spot.md:141` が挙げるロック/ポップの定型は「拍頭を**8分**先取り」（*Anticipatory Syncopation in Rock: A Corpus Study*）で、**8分単位**の先取りを指す。ここで測った 5.30% は **16分単位（1 slot）の先取り**であって同じものではない。＝先行記述は「先取り型という割り方の家族が実在する」ことの傍証にはなるが、5.30% という値の出典ではない（値は本doc の新規集計）。少数だが**性格が違う候補**なので、候補群に1本入れる価値がある（§3-2 の家族B）。

**参考：隣接する音価の比（前/後）**：1.00 が 49.4%・0.50 が 14.3%・2.00 が 12.7%・0.33 が 4.4%・3.00 が 3.9%。＝等分が半分、残りは**2倍/半分**が主。3:1（付点＋16分）は 4.4%＋3.9%。**割り方の音価比は {1:1, 1:2, 2:1} でほぼ足りる**（C-2 の帰結と整合）。

**参考：slot ごとの onset 出現率**（どの位置が「置いてよい位置」か）：0=71.0% / 2=54.6% / 4=58.0% / 6=49.9% / 8=55.9% / 10=42.4% / 12=50.6% / 14=44.4%（以上8分位置）、16分裏は 12.0〜19.0%。＝**16分裏は置けるが3〜4倍薄い**。

### 2-3. 16分格子が「硬い条件」である理由（C-1）

リポジトリの器がすべて16分格子でできている：

- `RHYTHM16_DATA`＝1小節16枠（`motifModelData.ts:3`）。`RHYTHM68_DATA`＝6/8を12枠（同 `:8`）。
- リズムパーツは16文字の `x/.` 文字列（`apps/api/src/music/rhythmParts.ts:10`・検証 `isValidPartPattern` は `/^[x.]{16}$/`）。
- 既存メロからのパターン採取 `extractRhythmPart`（同 `:96`）は `Math.round(rel / 0.25)` で**最寄りの16分へ丸める**（同 `:105`）。
- シンコペ指標 `lhlSyncScore`（`syncopation.ts:66`）も `Math.round(t / cellLen)` で**セルへ丸める**（同 `:78`）。
- 詞先メロの計画 `layoutOnsets`（`apps/api/src/music/lyricsPlan.ts:53`）は 4分→8分→16分の3段階しか持たない。

→ 格子外の onset を作ると、**エラーにならずに黙って別の位置として読まれる**（採取・指標・パーツ化がすべて丸める）。これは「機械が黙って嘘をつく」形なので硬い条件にする。

### 2-4. 現行の貪欲法 `flowLyric` が上の定義でどう不成立か

`flowLyric`（`packages/music-core/src/lyric.ts:143`）の割り方は1行で言える＝**「割ったときの半分が 0.25拍以上である音符のうち、いちばん長いものを半分に割る」を音符数がモーラ数に届くまで繰り返す**（同 `:149-164`）。

#### (a) 実例1＝句末の着地が最初に潰れる（C-4 違反）

2小節8拍の句（8分中心＋句末2拍の着地。`x.x.x.x.x...x... | x.x.x.x.x.......`）に字余り1を入れる：

```
元:      start 0, 0.5, 1, 1.5, 2, 3, 4, 4.5, 5, 5.5, 6      句末音 dur=2拍
字余り1: start 0, 0.5, 1, 1.5, 2, 3, 4, 4.5, 5, 5.5, 6, 7   句末音 dur=1拍
```

**最長音＝句末の着地音**なので、貪欲法は**まずそこを割る**。実POPは句末音を句平均の**1.31倍**に伸ばす（`2026-07-21-melody-note-value-and-harmonic-rhythm.md` §1.3・監査是正後の値。**タスク指示にあった 1.45 は同doc がタイ結合前の値として訂正済み**）。しかも句最終音が最長＝27.0%・最長音が末尾1/4にある＝34.1% なので、「最長を割る」規則は**構造上ここを狙い撃ちする**。

#### (b) 実例2＝16分格子から外れる（C-1 違反）

付点音価を含む句（`rhythmicContrast` rc≈0.5 を推奨設定とした場合、付点音価は 15.8%＝同doc §5.1）：

```
元:      start 0, 0.75, 1.5, 2, 3.5, 4, 5, 5.75, 7
         dur   0.75, 0.75, 0.5, 1.5, 0.5, 1, 0.75, 1.25, 1
字余り2: start 0, 0.75, 1.5, 2, 2.75, 3.5, 4, 5, 5.75, 6.375, 7
                                                    ^^^^^ 16分格子の外（32分位置）
```

`start=5.75, dur=1.25` の音符を半分にすると `0.625` になり、新しい onset が **6.375拍**＝32分格子に落ちる。`flowLyric` の下限判定は「半分が 0.25拍以上か」しか見ておらず、**位置が格子に乗るかを見ていない**。0.75拍の音符（実POP の 6.2%＝同doc §1.1）を割ると必ずこうなる。

#### (c) 全体の実測（モンテカルロ 4,000句×5条件）

コーパスの実 onset パターンを2小節ぶん引いて句を作り（＝実在する音価分布）、`flowLyric` の分割部をそのまま移植して字余り量を変えた：

| 字余り | 16分格子から外れた onset | 句末音を割った句 | 句内CV | 句末音/句平均 | syncPerBar |
|---|---|---|---|---|---|
| 1 | 1.6% | 21% | 0.726 → **0.500** | 1.42 → 1.20 | 1.85 → 2.27 |
| 2 | 3.7% | 29% | 0.725 → **0.422** | 1.39 → 1.19 | 1.84 → 2.43 |
| 3 | 6.2% | 34% | 0.732 → **0.350** | 1.44 → 1.15 | 1.88 → 2.52 |
| 4 | 8.4% | 40% | 0.729 → **0.306** | 1.42 → 1.11 | 1.87 → 2.48 |
| 6 | 13.0% | 46% | 0.737 → **0.280** | 1.44 → 1.14 | 1.85 → 2.27 |

読み取り：

- **CV が帯の下へ抜ける**。受入帯は 0.50–0.70（同doc §5.1）。字余り2以上で 0.42 以下＝**「音価が一律で機械的」という耳FBの状態そのものに戻る**。理屈も単純で、長い音符から順に半分にする＝**音価を揃える操作**だから、繰り返すほど一様化する。
- **句末/句平均が 1.4 → 1.1 台**＝コーパス中央値 1.31 を下回る。着地が消える。
- **格子外 onset が字余り量に比例して増える**（最大13.0%）。
- **`flowLyric` は「割れない」で止まることがほぼ無い**（割り切れず残った句 0%）＝下限16分に当たる前に、上の3つが先に壊れる。＝**「16分下限があるから安全」は成り立たない**。

#### (d) 定義に照らした判定

| 条件 | 現行 `flowLyric` |
|---|---|
| C-1 16分格子 | **違反する**（付点・食いの音符で必ず） |
| C-2 重みの上位2階層 | **見ていない**（位置は「半分」でしか決まらない） |
| C-3 テンポ込みの下限 | **見ていない**（0.25拍固定・テンポ引数なし） |

### 2-5. ノリ（シンコペ）が並べ替えに効くかは、元の句がシンコペしているかで変わる

**⚠ 訂正（2026-07-30・独立監査の指摘を受けて再測）**：初稿はここで「候補間で syncPerBar は散らない＝C-7 は順位付けに寄与しない」と一般化していたが、**それは検証に使った句が1本（しかも元から syncPerBar=0.00）だったことによる誤り**。食った句で測り直すと散る。以下が測り直した結果。

`lhlSyncScore` + `noriMeter`（`syncopation.ts:66,168`）で、C-2 に従う候補群（§3-2 家族A）の syncPerBar を測る。正規化は `SYNC_REF=10`（同 `:122`）。

| 句 | 元の syncPerBar（norm） | 字余り2の候補（44〜49本）の散らばり | 字余り3の候補（148〜156本） |
|---|---|---|---|
| **句A＝素直**（onset が全部8分頭・§3-3 で使った句） | 0.00（0.000） | 最小 0.00 / 最大 0.00 | 最小 0.00 / 最大 0.00 |
| **句B＝食い**（拍頭の16分手前に onset・12音） | 4.50（**0.450**） | 最小 **2.00**（0.200）／中央 3.50／最大 4.50（0.450） | 最小 **1.00**（0.100）／中央 3.50／最大 4.50（0.450） |

- **句B では Verse の帯 [0.15, 0.35]（`ROLE_BANDS`・`syncopation.ts:116`）の上端 0.35 を候補群がまたぐ**（0.10〜0.45）。＝**どの候補を選ぶかで句のノリの性格が変わる**＝C-7 はここでは弁別する。
- 句A で散らない理屈：**区間内の最強拍に onset を置く割り方（C-2 の第1階層）はシンコペを増やさず、むしろ減らす**。`lhlSyncScore` は「onset の後に、それより強い位置が覆われていたら事象」と数えるので、その強い位置に onset を置けば事象が消える。元からシンコペ事象が無い句（=0.00）では消すものが無いので全候補が 0.00 のまま動かない。
- 同じ理屈で、**食った句では割り方によってシンコペ事象が「いくつ消えるか」が変わる**＝散る。しかも**下に散る（性格が素直な方へ寄る）**＝元の 0.450 が最小 0.100 まで落ちる。

→ **C-7 の扱い（訂正後）**：シンコペの無い句では順位付けに寄与しない／**食った句では弁別するので、候補に添えて並べ替えに使う**。そして「元の性格を保ちたい」という要求は C-2 の第1階層だけでは満たせない＝**候補に「食い型」（§2-2 の 5.30%）を明示的に混ぜる必要がある**。これが §3-2 の家族Bを立てる理由。

## 3. 候補の出し方（手続きの素描＋プロトタイプの実測）

### 3-1. 入出力

```
入力：
  notes    音符列（範囲内・start 昇順）           ← notesInRange（lyric.ts:182）
  moras    モーラ列（kana と kind）                ← effectiveReading（lyric.ts:334）＋ analyzeMoras（prosody.ts:46）
  words    語の切れ目                              ← LyricReading.words（design §31-3）※ C-8 用・無ければ C-8 を落とす
  k        余りモーラ数                            ← phraseStatus（lyric.ts:283）の {kind:"字余り", count}
  meter    beatsPerBar / gridPerBeat / tempo       ← 呼び側（tempo は現行 flowLyric に渡っていない＝穴1）
出力：
  候補の配列。1候補＝「割り位置（音符index, 絶対slot）の集合」＋添える事実
    { splits, notesAfter, 割った音符数, 既出か, CV, 句末音/句平均, syncPerBar, 特殊拍/語境界の当たり }
```

**候補までを機械が出し、選ぶのは人**（1本化しない）。並べ方は事実基準と好ましさ基準の**両方を出す**（§3-4）。

### 3-2. 手続き（4段）

**段1：音符ごとに「割り方の選択肢」を列挙する。**
音符 `[s, s+L)`（slot単位）について、j 個の追加 onset を入れる方法を、次の規則で再帰的に列挙する：

- 現在の断片のうち1つを選び、**その断片の内部で `metricWeights` が最大の位置**に onset を置く。同点なら**中点に近いほう**を採る（実測：最強拍 75.8%・中点 68.7%・両方 64.4%＝最強拍を主・中点を同点破りに使うのが実測に最も合う）。
- 断片が下限音価（C-3）を割るなら選ばない。
- j は音符あたり上限（既定2）。

これが**家族A（素直に割る）**。ここに次を足す：

- **家族B（食い型）**：最強拍でなく**その16分（1 slot）1つ手前**に置く枝を、音符あたり最大1つだけ足す（実測 5.30%・§2-2）。**元の句が食っているとき（syncPerBar が高いとき）ほど要る**＝家族Aだけだとシンコペ事象が消えて句が素直になってしまう（§2-5 の句Bで norm 0.450 → 最小 0.100）。
- **家族C（2階層目）**：区間内2番目に強い位置に置く枝（実測 16.0%）。家族Aで候補が足りないときの補充。

**段2：句全体で「合計 j = k」になる組み合わせを取る。**
音符ごとの選択肢の直積を、合計が k になるものだけ深さ優先で取る（残りで到達可能な最大 j による枝刈りをする）。**句末音は既定で選択肢 j=0 のみ**（C-4）。

**段3：硬い条件でふるう。** C-1（格子）・C-2（重み階層）・C-3（下限）は段1で構造的に守られる。ここで落とすのは下限に引っかかる組み合わせだけ。

**段4：柔らかい条件を「添える事実」として計算する。** C-4〜C-9 を**弾かずに数値/フラグで添える**（`sectionNoriLens` の warnings と同じ流儀＝降格はするが消さない）。

- CV（C-5）＝音価列の std/mean。帯 0.50–0.70。
- 既出か（C-6）＝割った後の各小節の16枠パターンを `RHYTHM16_DATA` に引く。全小節が既出なら「実曲にある形」。
- 特殊拍・語境界（C-8）＝**割った後のモーラ→音符の対応をやり直して**（`placeMoras` と同じ頭から1対1）、`kind==="sokuon"` のモーラが強拍かつ新規 onset に当たっていないか／新規 onset が語の内部に立っていないかを見る。
- 音高（C-9）＝新しい音符は直前と同音（既定）。

### 3-3. プロトタイプの実測

段1〜2＋段4の一部を実装して、§2-4(a) と同じ句（2小節・11音・句末2拍の着地）に掛けた（下限=16分・音符あたり上限2・句末保護あり）：

| 1 | 10本 | 8本（80%） |
| 2 | 49本 | 32本（65%） |
| 3 | 156本 | 81本（52%） |

### 3-4. 候補の並べ方（点数で1本化しない）

- **事実基準**：割った音符数が少ない順／格子の細かさが粗い順／既出か否か。＝説明が要らない、誰が見ても同じ順。
- **好ましさ基準**：コーパス頻度（`RHYTHM16_DATA` の出現回数）順／CV が帯の中央に近い順。＝「よくある形」であって「良い形」ではない、と明記して出す。

### 4-2. 足りないもの（穴）

1. **テンポが割る側に届いていない**（C-3）。`flowLyric` の引数は `(notes, moras, floor)` だけで、下限は `MORA_FLOOR = 0.25`拍固定（`lyric.ts:127`）。BPM60 の16分は 250ms、BPM180 の16分は 83ms＝**同じ「16分」が別物**なので、本来は ms で決めて拍へ換算するのが筋。呼び側（`PianoRoll.tsx:499`）は tempo を持っているので配線の問題。
   - **ただし優先度は低い**（下の§4-3 で必須条件から外した理由）。(a) 「何 ms までなら歌えるか」の**実測も出典も本doc には無い**＝閾値を決める根拠がまだない。(b) §2-4(c) のモンテカルロでは**下限に当たって止まった句が 0%**＝貪欲法の破綻要因は格子・句末・CV であって下限ではない。＝**下限は「割る機能を実装するときに決めればよい実装上の注意」**であって、作る/作らないの判断を左右しない。
   - 一方で**下限が効く経路は実在する**：詞先メロ（`generate.ts:762`）では16分格子が埋まり切って全音符 dur=0.25 になり、下限に当たって分割ループが break する（§5 の再現実験）。＝「効かない」ではなく「効くところが違う」。
2. **4/4 以外の根拠が無い。** `RHYTHM16_DATA` は「300曲/4-4のみ」（`motifModelData.ts:2`）。3/4 は `metricWeights(3,4)` で位置は出せるが**実測の裏が無い**。6/8 は語彙が別体系（12枠）で、`rhythmicContrast` も 6/8 を対象外にした前例がある（`2026-07-21-...` §5.1「6/8は rc 対象外」）。→ **当面 4/4 に限る**のが筋。
3. **「っ」「ー」の扱いが2系統に割れている。** オーナー裁定＝音符を立てる。`flowLyric`/`placeMoras` は立てる。`prosody.ts:97` `roleOf` と `lyricsPlan.ts:30` `isOnsetMora` は立てない。**割る機能を作るなら C-8 の判定がこの2本と衝突するので、先に裁定側へ揃える**（割らないと決めても、詞先メロの音数が裁定と食い違ったままなので直すべき）。
4. **自作コーパス（P2）が無い。** §2-2 の 75.8% も §3-3 の「既出」も、**他人（POP909＝pop）の統計**。オーナーの作風がここからずれる分は測れない。＝**「よくある形」としか言えず「良い形」とは言えない**。これは候補提示の思想（人が選ぶ）と矛盾しないが、**順位を「評価」と呼ばない**根拠でもある。
5. **音高の割り当ては別問題として残る。** 同音反復を既定にする根拠はある（C-9）が、音符が1つ増えるとモーラ→音符の対応が全部ずれるので、**高低（`noteHighLow`・`lyric.ts:235`）の当たりも作り直しになる**。アクセント整合（A-01：核直後の下降を旋律が上昇で裏切る）が新しく発生しうる。＝**割った候補ごとに高低の印を出し直す**必要がある（材料は揃っている＝`effectiveWordInfo` から作れる）。
6. **句の範囲と小節線の対応**。候補生成は「絶対 slot」で回すので、句の `start` が小節線に乗らない（弱起）とき、パターン照合（C-6）の窓をどう切るかを決める必要がある。＝小節境界基準に固定する（`extractRhythmPart` と同じ流儀）。

### 4-3. 見込みの結論＝**条件つきで作る**

「音楽的に成立する割り方を候補として出す」は**実現できる見込みが立つ**。判断の根拠は、割り位置という一番の勘所が**既存の `metricWeights` だけで決まり、しかも実測 91.8% で裏が取れた**こと（前提の取り方を変えても 92.3% で動かない）、そして**出した候補の実在性を `RHYTHM16_DATA` で言い切れる**こと。プロトタイプは実際に動き、候補数も扱える範囲に収まった。

ただし次の3つを条件にする（満たせないなら作らない＝切り捨てのままでよい）：

1. **4/4 に限る**（3/4 は位置だけ出して「実測の裏なし」と明示・6/8 は対象外）。
2. **候補は必ず複数出し、既定は「何もしない」**。1本に決めて自動適用しない。並べ方は事実基準と好ましさ基準の併記（§3-4）。
3. **現行の貪欲法 `flowLyric` の中身をそのまま残さない**（§5）。名前や置き場を変えるだけでは、押した人が §2-4 の結果を受け取る。

（初稿はここに「下限音価を実時間で決める」を4つ目の必須条件として挙げていたが、**閾値の実測も出典も無く、下限は貪欲法の破綻要因でもない**ため、§4-2 穴1 の実装上の注意へ格下げした。）

**作らない場合の落とし所**（この結論を採らないなら）：`placeMoras` のまま＝**余りは載せない**、`phraseStatus` が「字余りN」と言うだけ。直すのは人（表記を変える／音符を足す）。これは design §31-5 の「機械は詰めない・削らない・止めない」と完全に一致し、**追加実装ゼロで筋が通る**。

### 4-4. 追記（2026-07-30c・オーナーの問い「6/8 できないのはなんで？」への回答）＝**6/8 はハードに作れないのではない。裏取りの層だけが 4/4 限定**

オーナーが条件1（4/4限定）に疑問を呈した。実コードで詰め直した結論＝**「割る位置を出す計算」は 6/8 でも正しく動く。欠けているのは「その位置が実曲でよくある自然な形だ」と言い切るための統計だけ**＝**能力の穴ではなく、実在性を証明する裏取りの穴**。

1. **位置決めの数学は 6/8 対応済み。** `metricWeights`（`syncopation.ts:23`）は `factorTree` で拍子を因数分解する＝6/8 は `beatsPerBar=2, gridPerBeat=3` を渡すと 3 を三分割因数として正しく複合拍の階層（強拍・付点1拍・8分）を出す（`syncopation.ts:11-18`・§4-1 表「4/4・3/4・任意の gridPerBeat に対応」）。＝**どこで割るのが拍として妥当か**は 6/8 でも根拠を持って出せる。
2. **足りないのは統計の裏だけ。** 案Aの売り＝「出した候補が実曲に実在する形だと `RHYTHM16_DATA` で言い切れる」（§2-2 の 75.8%／上位2階層 91.8%）。この裏取りコーパスは **300曲・4/4 のみ**（`motifModelData.ts:2`）。6/8 は (a) 割り位置の頻度統計が無い (b) 割り語彙が別体系＝`RHYTHM68_DATA` は**手キュレーションの設計値でコーパス実測ではない**（§4-1 表末）(c) 音価対比の目標値（CV・句末1.31倍）も 4/4 pop 実測（note-value §5.1 が 6/8 を rc 対象外にしたのと同じ理由＝複合12slot格子では 4/4 の付点long-short統計が転写できない）。
3. **∴ 6/8 で候補は出せるが、「よくある形」とは言えず「拍として妥当な形」までしか言えない。** これは 3/4 に対して既に §4-2 穴2・条件1が付けている扱い（「位置は出せるが実測の裏なし」）とまったく同じ。

**条件1の書き直し案（推し）＝「6/8 は対象外」をやめ、非4/4 を一律に「候補は出す・ラベルで裏の有無を正直に区別」に統一する。**

- 4/4：候補＋「実曲◯%に出る形」（統計の裏あり）。
- 3/4・6/8・その他：候補＋「拍の重みからの位置提案・実曲統計の裏はまだ」（正直ラベル）。既定は「何もしない」（条件2）は共通。

理由＝**ハード除外は 6/8 の曲で機能が一切手伝わないことを意味し、それは「裏なしと明示して手伝う」より悪い**。案Aの芯（候補まで機械・実在性を偽らない・選ぶのは人）はラベルの正直さで保たれる＝「裏なし」を隠さない限り、6/8 候補を出すことはコンセプトに反しない。**将来、自作コーパス（P2＝`docs/research/README.md` の要石）に 6/8 曲が入れば、6/8 も 4/4 と同じ「実在性の裏」を持てる**＝除外は永久でなく裏取り待ち。

**この追記が条件1に効く帰結**：6/8 は案A採否の**ブロッカーではなくなる**（4/4限定という制約が「非4/4はラベルで正直に」へ緩む）。条件2（複数候補・既定は何もしない）と条件3（貪欲法をそのまま残さない）は変わらず必須。

## 5. 設計含意（design #31 §31-5 が待っている結論を埋める・採否はオーナー裁定）

> **⚠ ここから先は「案」です。** §1〜§4 は事実と実測（＝research の性格）ですが、この章は提案と段取り（＝drafts の性格）で、1本の文書に同居させています。**裁定が出たら要点を design #31 へ昇格記載し、この章は archive 扱い**にしてください。

### 5-1. 何を埋めるのか

現行 §31-5（2026-07-30 改訂・コミット済み）は、**音符を割って合わせる操作を残すかどうかを「音楽的に成立する割り方を候補として出せるか」の研究の結論待ち**にしている。常設ボタンの退役は既に決まっていて、**実施は歌詞パネル実装と同時**（先に外すと音符を割る唯一の口が消えるため据え置き）。名前は仮称のまま（§31-11 裁定待ち16）。

＝**本doc が埋めるのは「残すか／作らないか」の1点**であって、退役の可否や実施時期ではない。本doc の答えは §4-3＝**条件つきで残す（＝候補提示版として作る）**。

### 5-2. 3案（残し方の選択肢）

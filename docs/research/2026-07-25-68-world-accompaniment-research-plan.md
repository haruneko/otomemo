# 6/8 無国籍民族調の伴奏パターン — 研究計画（2026-07-25）

- **この doc の役割＝計画のみ**。研究の実行・web検索・譜例の起草は一切しない。「何を・どう調べれば、研究役がそのまま
  実行できるか」を定義する。成果物（研究役が書く語彙doc）の受け入れ基準まで含む。
- 発端＝オーナーが新ジャンルとして「6/8 無国籍民族調」の伴奏（コード刻み・ベースの運び・打楽器）をライブラリに欲しい。
  L4量産計画（`2026-07-25-pattern-library-L4-quantity-plan.md`）は裁定D で「6/8 は現状ライブラリから除外」としたが、
  それは L3 ピッカーの 4/4 前提という**実装ゲートの話**であり、語彙研究を止める理由ではない。本計画は裁定D の

  ハーモニックマイナー等）× 6/8 のグルーヴで「汎用的な民族調の空気」を作る**。既存実証＝ボカロ民族調 study

  実データで確認済（あれは 4/4 高速だが、和声側の芯は流用できる）。

## 1. 目的

**何を知れば「6/8 無国籍民族調」のコード伴奏／ベース／打楽器の型を、度数×12枠グリッドのテキスト譜で起草できるか**。

具体的には、研究完了時に次が揃っていること：

1. 使う旋法パレットとその「空気」の対応（どの旋法がどんな色か・伴奏側で何が変わるか＝ドローン適性・開放5度・回避音）。
2. 6/8 グルーヴの類型（遅い叙情系〜速い舞曲系）と、それぞれのテンポ域（付点4分 BPM）。
3. パート別の一般定石：コード楽器の刻み方（ストラム/アルペジオ/白玉+ドローン/ヘミオラ）・ベースの運び
   （1拍4拍アンカー/R-5交互/ドローン/小節末アプローチ）・打楽器の型（低太鼓+枠太鼓 Dum-tek 系抽象・シェイカー/
   タンバリン細分・手拍子）。
4. 「無国籍化」の作り方＝特定文化の署名要素（特定の伝承曲・特定楽器の記名的装飾）を避けつつ民族調の空気を出す線引き。
5. 場面（Aメロ/サビ）ごとの密度差の付け方（verse 疎＝ドローン/アルペジオ、chorus 密＝ストラム/打楽器全部入り、等の定石）。

これらが、既存語彙4doc（piano/guitar/bass/drum vocabulary）と同じ体裁の**語彙doc 1本**
（仮名 `2026-07-XX-68-world-accompaniment-vocabulary.md`）に収まれば研究完了。その先の辞書化・seed・ピッカー6/8対応は
L4 の方式(a)（辞書に型追加→再seed・`2026-07-25-pattern-library-L4-quantity-plan.md` §3）に乗せる別スライス。

## 2. 前提の実測（スキーマ制約・実装ゲート）— 研究役が守るべき「枠」

研究の自由度を最初に確定する。実コードで確認済（2026-07-25 main）：

| 事実 | 出典（実コード） |
|---|---|
| 6/8 の生成グリッドは **1小節=12枠（16分基底）**。`stepsPerBar = beatsPerBar*4`＝6/8→12 | `apps/api/src/music/generate.ts:945` |
| web エディタも同じ：`meterSteps` が 6/8→ stepsPerBar **12**・beatStep **6**（拍＝付点4分＝6枠） | `apps/web/src/components/ChordPatternEditor.tsx:134-141`（BassStepEditor/RhythmEditor も同関数） |
| メロ側も 6/8 は「16分12枠を常時基底」へ統一済（8分6枠の二重グリッドは廃止決定） | `docs/research/2026-07-10-68-grid-unify-16th.md` |
| **ドラム辞書は 6/8 を表現できる**：`grid: 16 \| 12`・`six8.ballad`（meter:"6/8", grid:12）が既在 | `apps/api/src/music/drumLibrary.ts:24,92` |
| ただし seed が非4/4 を除外（L3 ピッカー 4/4 前提）＝裁定D の実体 | `apps/api/scripts/seed-pattern-library.ts:26,78` |
| **コード伴奏辞書は grid:16 固定**（全型 4/4）＝6/8 型はスキーマ拡張が要る | `apps/api/src/music/chordLibrary.ts:37` |
| **ベース辞書も grid:16 固定**・パーサが16セル厳格検証＝同上 | `apps/api/src/music/bassLibrary.ts:29,57` |

**帰結（研究役への指示）**：

- **テキスト譜は 6/8＝1小節12セル（16分基底）で書く**。既存ドラムdoc の 6/8 記法（6セル＝8分基底・
  `2026-07-14-drum-pattern-genre-library.md` §1）は**採用しない**＝メロ側統一（16分12枠）と `meterSteps` に揃える。
  拍構造：step 1〜12、**大拍（付点4分）＝step 1 と 7**、8分＝奇数 step（1,3,5,7,9,11）、16分裏＝偶数 step。
  ヘミオラ（3対2）＝4 step 間隔のアクセント（step 1,5,9）＝12枠で正確に表現できる。
- **12枠×整数 bars に収まる型だけが今の仕組みで（拡張後に）鳴る**。収まらない型（例：8分をさらに3分割する装飾＝24枠相当、
  自由リズムのルバート導入）は捨てずに採録してよいが、**「スキーマ拡張要」と明示マークする**（受け入れ基準 §5-4）。
- 実装側の待ち工事（研究のスコープ外・語彙doc に含めない）：chord/bass 辞書の grid:12 型対応・seed の 6/8 解禁・
  L3 ピッカー/プレビューの 4/4 前提解除。これらは L4 方式(a) の別スライスとして design.md に下ろす。

## 3. リサーチ質問リスト（研究役がそのまま実行できる粒度）

### RQ-A 旋法・和声軸（「無国籍の空気」の音組織）

- **A1**: 民族調の空気を出す旋法パレットの一般論を集める。候補＝エオリアン／ドリアン／フリジアン／ハーモニックマイナー
  （＋フリジアンドミナント）／ミクソリディアン。各旋法について「特性音（ドリアンなら長6度、フリジアンなら♭2）」
  「伴奏側で特性音をどこに置くと色が出るか（コードに含める/ドローン上の旋律に任せる）」を出典付きで表にする。
  既存の裏＝自前コーパスの短調実測（`2026-07-14-mode-usage-stats.md` §1-2：ドリアンの IV 長は**中間専用**4.2%・
  フリジアの ♭II 2.0%・和声的短音階の V 9.8%・エオリアン終止 ♭VI→♭VII→i が V→i を上回る）を必ず参照し、
  外部一般論と突き合わせる。
- **A2**: **ドローン（保続音）と開放5度**の定石。ルート+5度（3度抜き）が旋法の曖昧さを保つ理由、ドローン上でコードが
  動くときの衝突回避（ドローン音と♭2/長7の短2度衝突をどう扱うか）。伴奏型として「ドローン持続＋上声だけ動く」を
  何小節単位で使うのが定石か。
- **A3**: 6/8 民族調で使うコード進行の型（伴奏研究に必要な範囲だけ）。i–♭VII／i–♭VI–♭VII／i–iv／ドリアンの i–IV。
  和音の変わる速さ（1小節1和音か・大拍ごとか）とグルーヴ類型の対応。※進行そのものの深掘りは不要
  （`2026-07-06-vocaloid-folk-study.md`＋`2026-07-14-mode-usage-stats.md` で足りている）。**伴奏の型が「何和音/小節」を
  前提に書かれるべきか**の裁定材料だけ取る。

### RQ-B グルーヴ軸（6/8 の時間構造）

- **B1**: 6/8 グルーヴの類型を教則・理論源から収集して命名する。最低限当たる仮説リスト（研究役が検証・追加する）：
  (i) 遅い 6/8 ロール（叙情バラード系・大拍2つのうねり）、(ii) 中速リルト（フォークの「揺れ」＝R-5 交互バウンス）、
  (iii) 速い舞曲駆動（ジグ的 8分駆動）、(iv) スキップ/跳ね（タランテラ的・付点跳ね）、(v) シチリアーナ型リズム
  （付点8分+16分+8分＝12枠で 3+1+2 step＝表現可）、(vi) ヘミオラ/3対2（12枠の step 1,5,9 アクセント）、
  (vii) ドローン+オスティナート（リズム型というより密度最小層）。各類型に「12枠のどこにアクセントが来るか」を付ける。
- **B2**: テンポ域の相場。付点4分 BPM でクラス分け（遅 40–60 / 中 60–100 / 速 100–140 目安・要出典検証）。
  既存の錨＝`six8.ballad` は付点4分 50–80（`2026-07-14-drum-pattern-genre-library.md` 型16）。速い側（舞曲系）の
  相場を外部から取る。**型ごとに tempoMin/tempoMax を付けられる粒度**まで。
- **B3**: 6/8 と 3/4 の違い（2大拍 vs 3拍）を伴奏型がどう体現するか＝「6/8 らしさ」の必要条件（ベース/キックが
  step 1・7 を打つ、等）。ヘミオラはどの頻度・どの場面（サビ前・句末）で使うのが定石か。

### RQ-C パート別語彙（本丸・3系統）

- **C1 コード楽器の刻み**：6/8 のギターストラム定石（D-dd-dd 系のパターン族・アップ/ダウン配置）、鍵盤/ハープ的
  アルペジオ（6音循環＝R-5-8-10-8-5 等の上下波・12枠で 2 step 刻み）、白玉+ドローン、ヘミオラ・ストラム。
  各型を**度数×12枠**（piano vocab `§0-1` の記法を12枠化・LH/RH 2段）で書ける情報粒度まで取る。目標 8 型以上。
- **C2 ベースの運び**：大拍アンカー（step 1・7 にルート）、R–5 交互（1拍目R・4拍目5）、ドローン持続、
  小節末アプローチ（step 11–12 で次和音へ 2度/半音接近＝bass vocab の kickRel/アプローチ定石の 6/8 版）、
  オクターブ跳ね、ヘミオラベース（step 1,5,9）。**キック絡み符号（unison/interlock/counter・
  `2026-07-14-bass-genre-vocabulary.md` §0）を 6/8 でも付ける**。目標 8 型以上。
- **C3 打楽器**：フレームドラム系（ダフ/バウロン/レク等の**族としての**低音-高音 2 層＝Dum-tek 抽象）を
  **特定伝承のリズム名のリテラルではなく骨格抽象**として採る（先例＝`break.amen_abstract`「構造のみ」・
  `2026-07-14-drum-pattern-genre-library.md` §6）。層構成の定石：低（Dum＝大拍）/高（tek＝細分・裏）/
  シェイカー・タンバリン（8分 or 16分の持続層）/手拍子（大拍 or ヘミオラ）。**GM 音源で何番に割るか**が必須の調査項目
  （GM パーカッション：タンバリン54・カバサ69・マラカス70・コンガ62-64・ボンゴ60-61・クラベス75・ウッドブロック76-77、
  フレームドラムの代用＝ロータム45/フロアタム41+サイドスティック37 等の代用表を作る。ドラムdoc §1 の GM 表を拡張）。
  目標 8 型以上（うち「低+高+持続層」のフルキット型と、持続層だけの薄い型の両方）。

### RQ-D 無国籍化・密度設計（様式の運用）

- **D1**: 「無国籍民族調」を実務でどう作るかの先行知見。当たり先＝日本のゲーム/同人音楽文化圏の「民族調・ケルト風・
  幻想民族」作曲解説（オーナーの文化圏に最も近い）＋映画/ゲーム劇伴の world music 汎用化の議論。
  **何をやると「特定文化のコピー」に寄るか**（記名的な装飾法・特定の伝承リズム名の忠実再現・特定楽曲の引用）と、
  **何が汎用の建材か**（旋法・ドローン・6/8 リルト・Dum-tek 層構造）の線引きを出典付きで言語化する。
- **D2**: 場面別密度の定石。verse＝疎（ドローン/アルペジオ/打楽器薄）→ chorus＝密（ストラム/フル打楽器/ベース跳ね）
  の段差を、既存4doc の場面設計（piano vocab §3-3 verse疎/chorus密・drum doc §9 選択表）と同じ形式の
  **場面×型の選択表**にする。intro/bridge の「ドローンだけ」「打楽器だけ」も候補に。
- **D3**: 型間の互換・遷移（drum doc §10 と同型）：同曲内で verse型→chorus型 へ移るとき保存すべき層
  （大拍アンカー）と変えてよい層（細分密度）。

## 5. 受け入れ基準（語彙doc が満たすべき条件・機械判定できる形）

成果物＝語彙doc 1本。以下を**上から機械チェック**（grep/目視表チェックで判定可能な形に書く）：

1. **記法節がある**：冒頭に「6/8＝1小節12セル（16分基底）・大拍=step1,7・8分=奇数step」の格子定義
   （§2 の帰結どおり。既存 piano vocab §0-1 の12枠版）。
2. **型数の下限**：コード刻み **8型以上**・ベース **8型以上**・打楽器 **8型以上**（数え方＝型ID見出しの数）。
   各パートで **verse 適格 4型以上・chorus 適格 4型以上**（roles 表記から数える。1型が両場面適格でも可＝L4 の
   「セル内 distinct 4件」目標・`2026-07-25-pattern-library-L4-quantity-plan.md` §0 に整合）。
3. **各型の必須フィールド**：型ID（英数字・`w68-` 等の接頭で名寄せ可能に）／度数×12セルのテキスト譜
   （打楽器はレーン×12セル・GM ノート番号併記）／テンポ域（**付点4分 BPM** で min–max）／場面 roles／
   キック絡み符号（ベースのみ）／**出典URL 1本以上**。→ 機械判定＝「型見出しごとに譜面ブロック・テンポ・roles・URL の
   4要素が揃う」を grep で確認できる書式（表 or 定型見出し）にすること。
4. **12枠表現可能性の明示**：全型について「セルが 12×bars 格子に整数で載るか」を確認し、載らない型は見出しに
   **【スキーマ拡張要】** を付けて理由（24枠要/自由リズム等）を書く。機械判定＝譜面ブロックのセル数カウント
   （12 の倍数）＋マーク有無。**マーク無しの型はセル数 12×bars ちょうどであること**。
5. **リテラル転写ゼロの確認方法**（§6 のチェックリスト運用）：doc 末尾に「出典×採録内容」対応表を置き、各行に
   採録タイプ＝{一般定石/骨格抽象/統計} のいずれかを明記。**「採譜」「transcription of <曲名>」タイプの行が 0 であること**。
   型名・譜例キャプションに特定曲名・特定伝承曲名が現れないこと（grep で曲名の不在を確認。「ジグ的」「タランテラ的」の
   様式名は可＝リズム族の一般名）。
6. **既存4doc との体裁一致**：記法節→型辞書→場面選択表→設計含意→出典一覧、の章立て
   （`2026-07-14-drum-pattern-genre-library.md` の構成が最も近い雛形）。設計含意には「chord/bass 辞書の grid:12 拡張・
   seed 6/8 解禁・ピッカー 4/4 前提解除が実装前提」（§2 の待ち工事）を明記。
7. **README 索引 1行追加**（CLAUDE.md 規約）。

Fable 監査（§8 手順）はこの 1–7 を判定基準として使う＝監査項目が doc 側に自己申告表として埋まっていること。

## 6. 著作権チェックリスト（コンセプト既定の硬い線・研究役が毎出典で回す）

前提＝**他者コーパス・他者曲・伝承旋律からのリテラルな旋律/モチーフは保存しない。特定曲・特定民謡の写しは移調してもNG**
（CLAUDE.md 研究ルール＋`feedback-corpus-statistics-only-copyright`）。伴奏パターンは旋律より定石性が強い
（scènes à faire＝ありふれた建材・piano vocab §1 と `2026-07-14-melody-similarity-warning.md` の整理）が、線は同じ引き方で守る：

- ✅ **OK＝一般定石**：教則サイト・理論教材が「この様式はこう刻む」と型として教えるリズム/度数パターン
  （例：6/8 ストラムの D-dd-dd、R–5 交互ベース、Dum-tek の層構造）。
- ✅ **OK＝骨格抽象**：特定演奏の音色・装飾・ミクロタイミングを捨て、アクセント位置だけの構造に落としたもの
  （先例＝`break.amen_abstract`「2小節・構造抽象」）。抽象化の証明＝「どの一般構造を採ったか」を言葉で書けること。
- ✅ **OK＝統計**：コーパス・研究からの分布数値（旋法使用率・終止型頻度）。
- ❌ **NG＝特定曲の採譜**：既存曲（商用・同人・ボカロ問わず）のイントロ/伴奏の写し。**移調・楽器変更しても NG**。
- ❌ **NG＝特定伝承曲のリテラル**：民謡・伝承旋律は PD でも**本プロダクトの線では保存しない**（「無国籍」のコンセプト
  そのものに反する＝特定文化の記名物を持ち込まない）。伝承の**リズム族の一般名**（ジグ、タランテラ）と
  **骨格**（6/8 の 8分駆動）は可。
- ⚠️ **グレーの判定手順**：出典が「<曲名> の弾き方」型の教則だった場合、そこから採ってよいのは
  **その教則が一般化して説明している型**のみ（「6/8 バラードは大抵こう」の部分）。譜例がその曲固有の音列なら捨てる。
  迷ったら採らない＝別の一般教則を探す。
- **運用**：§5-5 の「出典×採録内容」対応表を書きながら回す（後追いで表を埋めない）。各行＝出典URL／採録タイプ／
  採った内容の一言。この表が監査の一次証跡。

## 8. 想定コストと段取り

**規模見積り**：
- fan-out＝**T1–T4 の4並列**（web 検索エージェント・Opus 級・各 10–20 出典規模）＋ **T5 統合 1 本**（Fable）。
  歌詞支援研究（8 分割）より小さく、単発語彙doc（piano/guitar 各 1 エージェント相当）より大きい＝中規模。
- 産出物＝語彙doc 1本（24型以上・12枠譜例つき）＋ README 1行。

**段取り（順序と受け入れ）**：
1. **オーナー確認（§9）を先に**＝①裁定D 上書きの承認・②ジャンル語・③空気の重心・④テンポ重心。①以外は
   「後から直せる」ので、回答待ちで研究を止めない（`feedback-dont-stop-without-blocker`）＝既定値を仮置きして進め、
   回答が来たら T5 で反映。
2. T1–T4 並列実行（各トラック＝ §3 の RQ をそのまま指示文に使う。§6 チェックリストを毎出典で回す）。
3. T5 統合＝語彙doc 起草（§5 の 1–7 セルフチェック表つき）。
4. **Fable 監査**＝§5 基準の機械チェック＋出典の実在・裏取り（`feedback-verify-audits-in-code` の流儀＝所見は原典で確認）
   ＋§6 対応表の抜き取り検査。
5. **オーナー耳確認は辞書化後**＝語彙doc の紙上では耳確認できない。L4 §3-3 手順（辞書化→seed→プローブ MIDI 束を
   1回で聴く）に乗せる。**ただし辞書化の前提工事（chord/bass grid:12・seed/ピッカー 6/8 対応）が別スライス**なので、
   耳確認はそのスライス後＝本研究の完了条件には含めない（研究の完了＝Fable 監査パス）。
6. 実装スライス（別）＝design.md へ「6/8 対応（裁定D 上書き）＋ w68 型追加」を下ろす → テスト先行 → 辞書 → seed →
   実機確認 → 耳プローブ。

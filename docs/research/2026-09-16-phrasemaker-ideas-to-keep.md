# phrase_maker から残す考え方（取り込みアークを閉じるにあたって）

作成日: 2026-09-16。**オーナー裁定（同日）＝「考え方だけ残して閉じる」**。phrase_maker（同じオーナーの Python 試作）から Otomemo へのコードの取り込みはここで終わりです。耳で合格して Otomemo に残っているのは **ドラムのフィル（毎回その場で解く身体シミュレーション）** と **ウォーキングベース** の2つだけです。これ以降の伴奏・リフ・ケルトなどの新機能は、白紙から設計します。

**この文書の読み手＝新機能を白紙から設計する人。** 最初に読むことを想定しています。そのため本文では、Otomemo や phrase_maker のコードの形・関数名・ファイル名を使わず、音楽と作り方の言葉だけで書きました。根拠の所在（ファイルと行）は末尾の出典欄にまとめてあります。設計の段階で出典欄を開いてコードを読みに行く必要はありません。

読み方：
- §1＝残す考え方（こう作るとよい）
- §2＝負の知識（こう作ると失敗した）
- §3＝考え方ごとの証拠の強さ（**耳で確かめた**／**コードと文書からの判断のみ**＝未検証の考え方）
- §4＝使わなかったものの一覧
- 物差しは今もオーナーです。この文書は「正しい答え」ではなく、過去の試行から取り出した材料です。

---

## 1. 残す考え方（肯定側）

### 1-1. 型を貼るのではなく、その場で生成する

**考え方**：前もって用意した数小節の型（表）を貼り付けて、コードに合わせて音を読み替えるのではなく、コード進行・拍子・前後の状況を見て、**その都度、規則に沿って1拍ずつ・1打ずつ音を選ぶ**。

**根拠**：
- ウォーキングベースは型を持たず、拍ごとに「コードの音・次のコードへの導き・禁じる跳躍・跳躍の後は戻る・線の向き」という規則で音を選びます。オーナーの耳＝「使える」「自分が使わない手癖で良い」。
- ドラムのフィルも、型の辞書から選ぶのではなく、長さと行き先が決まったら毎回その場で解いています。耳で合格（2026-08-30）。
- 反対に、2小節の固定の型を貼ってルートに合わせたベース・ギターのリフは「固い・動かない」「リフではない」と言われ、撤去されました（§2-2）。実測でも、型を貼った方はルートの割合が高く同音の連打が多く、規則で選んだウォーキングはルート率 0.19〜0.31・同音連打 0 でした。

**注意**：規則で選べば何でも良い、わけではありません。phrase_maker でもウォーキングの初版は「這いすぎ」、別版は「逐次で目先だけ選ぶので限界」と耳や批評で却下されています。**耳を決めるのは規則の中身**です。型か規則かは「必要条件の側」の話です。

### 1-2. 手の届く範囲から音を出す（身体性を「生成」に使う）

**考え方**：楽器を弾く体（指板上の手の位置・鍵盤上の手の広がり・ドラマーの両手両足）の制約を、**音を選ぶ前の候補の集合そのもの**として使う。いま手がある場所から届く音・届く打面の中から選び、届かなければ手を動かす（その移動も音楽に表れる）。

**根拠**：
- phrase_maker の芯＝「楽器の身体性シミュレータ＋発散・選別の相棒」。弦・フレット・運指・両手のリーチという物理と慣用の制約空間から、**手癖では選ばない"弾ける動き"**を出す。
- Otomemo に残ったドラムのフィルは、この作り（四肢で叩ける順序を毎回解く）で耳に合格しています。
- phrase_maker の鍵盤の試作（掴んだ和音の手の位置から、空いている指が届く音だけを候補にする）は、向こうの文脈（ジャズバラードの独奏・ロックの合奏）で耳の評価を積み上げています（「良くなった・やりたいことに近づいている」→「どれも良い」）。**ただし Otomemo の文脈では一度も鳴らしていません**（§3）。

**見分け方（重要）**：体の制約が「生成」しているか「検査」しているかで、結果が全く違います。
- 生成＝届く範囲が先にあり、その中から選ぶ。
- 検査＝先に音を決め、届かないものを捨てるだけ。これは phrase_maker 自身が「物理層が何でも通す検査係に堕ちると、型を押すだけの道具になる」と2度失敗した形です。
- 確かめ方＝**体の制約の重みを振ってみて出力が変わるか**。変わらなければ検査係になっています（向こうのギター試作でこの方法により実際に発見・修正された記録があります）。

### 1-3. 発散は1本のつまみでまとめず、軸ごとに持つ

**考え方**：「どれくらい変えるか」を 0〜1 の1本のつまみにまとめると、つまみを上げても「同じ候補の先頭から何個を変えるか」が増えるだけになり、**質的に別の候補**になりません。**何を固定し何を崩すか**を軸ごとに分け（例：音高の輪郭／打点／密度／音域）、軸を選んで崩す。候補は1つの最良解ではなく、質的に違う複数を出して、選ぶのは人の耳。

**根拠**：
- phrase_maker の芯（発散の層）＝「密度のつまみや最小コストの1解ではなく、質的に別のアイデアを複数」「平均（いちばんありそうな凡庸）を出さない」。
- 向こうのベースの発散つまみは1本のつまみで入れ子に変える作りで、向こう自身のコンセプトが否定した形でした。
- Otomemo で撤去した変奏の試作でも「軸を1本だけ崩す・なし／中／多めの段階で並べる・守る打点を決める・変えたつもりが打ち消されていないか実測する」という発想自体は筋が良いと判断されました（土台の型が固定表だったので、効く量が構造的に小さく、一緒に外れました）。
- Otomemo 側の計画（語彙帳＋配札）＝「数枚配る・ランキングしない・ピンを種に配り直す・軸を指定して配り直す」と同じ向きです。
- 選ぶときは「平均をとる」「最良1つ」ではなく、**上位からの確率的な抽選**で多様性を保つ作りが向こうの共通の作法でした。

### 1-4. 評価の物差し＝「雑に打ち込んだ場合と差が出るか」

**考え方**：出来の良さや破綻の無さではなく、**作曲者が超雑に自分で打ち込んだ場合と比べて差が出るか**＝手癖に無い本物の語彙・身体性を実際に足しているか、で判定する。差が薄いのは「いちばんありそうな凡庸に寄っている＝語彙が薄い」と読む。

**根拠と運用**：
- phrase_maker の正典の評価基準（2026-08-08 確定）。「完成度」「手で打てるか」は基準ではない（DAW で打ち直すことは織り込み済み）。
- 操作の形＝**採用率**。短いクリップごとに「そのまま貼る／ノリだけ直す／音符を書き換える／貼らない」＋「自分では思いつかない置き方があったか」を聞く。
- 機械の指標は診断であって、良さの報酬にしない（Otomemo の「評価に言語モデル判定を使わない・理論スコアはガードレール止まり」とも一致）。
- 反例として、オルガンの伸ばし方の試作は「伸ばしただけ、打ち込み適当と変わらん」「破綻していないから最低限合格」と言われました。**破綻しない＝合格ではない**、というこの物差しの実例です。

### 1-5. 他人の手癖を借りるのは目的。材料は他者の実データの統計と、楽器の身体性

**考え方**：「誰かの手癖を借りる」ことは問題ではなく**目的**（他人の本物の語彙＝新鮮さ＝価値）。本当の問題は「語彙が薄い／一人分／本物でない」こと。材料は2つ：
1. **楽器の身体性**（§1-2）＝弾ける動きの土台。
2. **他者の実データから取った統計**（リズムの分布・輪郭・遷移の傾向・ボイシングの傾向）＝様式の色。

**Otomemo のコンセプトと両立させるための線**：
- 他者コーパス（POP909 等）からは**統計だけ**を取る。旋律・パターンの逐語は、移調しても保存しない（Otomemo の硬い線）。phrase_maker でも「実演の音符をそのまま移植する」経路は、権利・格子に乗らない・発散ゼロの3点で却下されています。
- オーナー自身の MIDI から手癖を採る案は不採用（オーナー原文「手癖を超えたいのに私のライブラリを使うのは変」）。手癖の鏡も作らない。
- 向こうの整理＝「**物理が土台、語彙が色**」。身体性で弾ける動きまでは出るが、様式の色はそこまで決まらない。色は土台の上に足す別の層。

### 1-6. 構成（入力と設定）は丸ごと運ばないと耳の結果は再現しない

**考え方**：ある構成で耳に合格したものを別の場所で動かすときは、**つまみ・既定値・前提の入力まで同じか**を機械的に確かめる。聞こえ方の多くは、仕組みの芯ではなく手で合わせた係数から来ている可能性がある。

**根拠**：phrase_maker の鍵盤の試作を合奏へ載せた初回は「全然だめ・劣化・全曲同じ」で、原因は耳に合格した設定のつまみ4つが黙って落ちていたことでした。直すと「品質的には元に戻った」。

これは白紙設計にも効きます：**向こうで良かった音は、向こうの入力（ドラムの譜を全パートが共有する・1小節1コード・4/4）込みの結果**です。その入力が無い Otomemo で同じ耳になる保証はありません。

## 2. 負の知識（否定側）＝こう作ると失敗した

撤去検討の5項（design 追補 (k) に記録済み）に、2026-09-16 の選び直し・判定・反対三面で新たに出た事実を足して、計10項です。

1. **キックに揃える規則は合奏の糊であって、リフではない。** 「キックの位置には必ずルート」「キックに刻みを揃える」はバンドを噛み合わせる規則で、別パターンを生む仕組みではない。耳＝「必ずルートは固い」。研究上も「キック位置＝ルート」という規則は無く、「コードの変わり目＝ルート・強拍＝構成音」程度。**共有のリズム譜から時刻を決める規則（伸ばす音の掴み時刻を「キック以外の最初の打点」にする、など）も同じ系統**。
2. **固定の数小節の型を貼る方式は、リフを「作る」仕組みではない。** 既存の型辞書と同じ性質の表が1つ増えるだけ。源流も「型の表はわざとらしい・収束の元」と自認していた。表の上に変奏の層を足しても、動かせる音が元から1〜2割しか無いので差が出ない。**土台を疑わずに上へ層を積んだ直し（錨を弱める・つまみを足す・変奏を足す）は、何を作りたいのか分からないものになった。**
3. **評価の単位を確かめる：バンド全体の耳を、パート単体の価値と取り違えない。** 「ロックとても良い」はバンド全体の評価で、ベース単体は「まあまあ」だった。それを根拠に移植した。
4. **別の計画は、オーナーの課題の計画と接続してから走らせる。** 取り込み計画はオーナーの課題（手癖で似たニュアンスの別パターンが出せない・楽器固有のリフ・オルガン／ピアノの奏法バッキング）とその計画を一度も参照せず、「リフ」という名前だけが合流した。
5. **使えると言われた方と固いと言われた方の差＝型を敷かず規則で選ぶ／型を敷く。**（§1-1 の裏側）
6. **名前で判定せず、中身で判定する。** phrase_maker の「リフ」と名の付くものは、どれも伴奏の刻み（固定2小節の型・固定テンプレート）で、和声との関係の型（移調／固定／ペダル／微調整）を選ぶ口も無かった。「リフ」「身体性」「手の形」という名前がついていても、中身が型の表や検査係であることがある。
7. **忠実な移植・テストが通ることを、進捗と取り違えない。** Python と1ビット一致させる移植を積み上げても、耳で「リフではない」と言われれば全部外すことになった（撤去は数百ファイル規模）。**耳を先に、移植は後**。
8. **安全側の規則は平均へ寄せる。** 「連打を避ける」「次の音の少し前で離す」「共通音はつなぐ」「強拍はコードトーンに直す」「強さを平らにする」は、どれも破綻を防ぐ規則で、手癖に無い動きを足すものではない。耳の言い方＝「破綻していないから最低限合格」「あんま変わってない」。1つの入力に1つの答えしか返さない純粋な規則は、「数枚配る」「平均を出さない」の両方と噛み合わない。
9. **1小節1コード前提の生成器は、J-POP の「2拍でコードが替わる」に合わない。** phrase_maker の鍵盤の試作は、拍単位の進行を小節単位に丸めて（2拍のコードが1小節に膨らむ）、和音を掴み直すのは小節の頭だけ、拍子は 4/4 限定だった。Otomemo の伴奏の写像で「全案共通の要石」として潰した課題に逆行する。**和声のリズム（コードが替わる位置）と拍子を、生成の最初から入力として扱うこと。**
10. **耳の記録は「次の回の冒頭」に書かれていることが多い。** phrase_maker では機能を入れた回の記録は必ず「まだ耳で聴いていない」で終わり、耳の言葉は次の回の仕様・批評・研究の冒頭に転記されている。当該の回だけ見て「未判定」と書き誤った前例がある。過去の試作の耳を引くときは前後を読む。

## 3. 考え方ごとの証拠の強さ

| 考え方 | 証拠の強さ | 中身 |
|---|---|---|
| 1-1 型を貼らずその場で生成 | **耳で確かめた（Otomemo 上）** | ウォーキング「使える」／ドラムのフィル合格。反対側（固定の型）は「固い・リフではない」で撤去。ただし対照はジャンルも役割も違う＝「規則なら何でも良い」までは言えない |
| 1-2 手の届く範囲から音を出す | **ドラム＝耳で確かめた（Otomemo 上）／鍵盤・ギター＝未検証の考え方（Otomemo では）** | ドラムのフィルは Otomemo 上で合格。鍵盤の手の試作の耳は phrase_maker の文脈（ジャズバラード独奏・ロック合奏・主旋律なし）のみ。ギターの手の形は向こうでも耳未判定 |
| 1-3 発散は軸ごと・複数候補 | **未検証の考え方** | phrase_maker の正典と、コード・文書の判断のみ。Otomemo の変奏の試作は土台ごと撤去され、軸ごとの発散そのものの耳は取れていない。向こうのドラムの複数案も「名前付きの狙い同士が必ずしも別物でない」と記録があり、複数案の「別物度」は耳で確かめていない |
| 1-4 雑な打ち込みと差が出るか | **物差しとしては確定（phrase_maker 側・オーナーの言葉）** | 向こうの正典で確定。Otomemo 上でこの物差し（採用率）を回したことはまだ無い＝運用は未検証 |
| 1-5 他人の手癖を借りる・材料は統計と身体性 | **オーナーの言葉で確定（方針）／効果は未検証の考え方** | 「手癖を超えたい・900POPS とかの実データを使いたい」（オーナー原文）・向こうの手癖の原則。統計で候補分布を較正して耳が良くなるかは Otomemo ではまだ確かめていない |
| 1-6 構成を丸ごと運ぶ | **耳で確かめた（phrase_maker 上）** | 設定の落ちで「全然だめ」→戻して「元に戻った」 |
| 負の知識 1〜5 | **耳で確かめた（Otomemo 上）** | 2026-09-13〜16 の耳判定と撤去 |
| 負の知識 6・7・10 | **コードと文書からの判断** | 選び直しと撤去検討での実物確認 |
| 負の知識 8 | **一部耳（phrase_maker 上のオルガン「あんま変わってない」）＋判断** | 「安全側の規則が平均へ寄せる」という一般化は判断 |
| 負の知識 9 | **コードからの判断のみ** | 鍵盤の試作を 2拍替わりの J-POP 進行で鳴らしたことは無い |

**未検証の考え方として明記するもの**：1-2 の鍵盤・ギターへの適用（Otomemo 上）／1-3 軸ごとの発散・複数候補の別物度／1-4 の Otomemo での運用／1-5 の統計較正の効果。設計に使うときは、**最初の試作で耳に出す項目**として扱ってください。

## 4. 使わなかったもの（何を・なぜ）

コードは移していません。考え方として残すものは §1・§2 に入れました。

| 対象（phrase_maker 側） | 移さなかった理由（一行） |
|---|---|
| 鍵盤の手の形の生成器（掴んだ手から次の音を選ぶ）＋手のモデル＋フレーズの弧 | 1小節1コード・4/4 限定で J-POP の2拍替わりに逆行・約2,750行・Otomemo 文脈で未聴＝**考え方（§1-2）だけ残す** |
| オルガンの伸ばし方の規則（掴む時刻・離す時刻・共通音のタイ） | Otomemo で書ける量・時刻をキックから決める合奏の糊・向こうの耳「伸ばしただけ」「あんま変わってない」 |
| ドラムの複数案・名前付きの狙い・自動の息継ぎ | 既存のフィルのつまみを振って似た案を刈るだけ＝移すものが無い・狙い同士が別物でない記録・息継ぎは機械が構成を決める |
| ケルトのジグ（音型の語彙＋半小節ごとの目標音＋方向の慣性＋軸音） | 3課題に効かず耳「軸が無い」・軸音版は未判定。**ケルトは「行けるなら入れたい」＝移植でなく新機能として白紙から設計する対象** |
| ケルトのリール・装飾（カット・ロール） | 耳「リールはよくない」・スラー未実装・装飾は格子外で足すと逆効果寄り |
| ベースのリフ文法（固定2小節の型3種）とキックへのルートの錨 | 2026-09-16 に撤去（負の知識1・2） |
| ギターのリフ文法・刻みのキック揃え・コード追従 | 同上（固定の型・合奏の糊・パワーコードの連打） |
| ギターの手の形（フォームを状態として持つ） | 型が和音か単音かを決めてしまい手が選べる幅が狭い・耳未判定・楽器固有リフへの答えではない |
| ベースの発散つまみ（1本のつまみで入れ子に変える） | 質的に別の候補にならない（向こうのコンセプト自身が否定・§1-3） |
| 鍵盤の崩し度の表（容器と12セルのつまみ）・バラード／ボサの型 | 体の制約が検査係（届かない音を捨てるだけ）・後継の手の形の試作に置き換え済み・載せても静的な型になる |
| 器楽ソロの生成器 | 初期スコープ外・耳未確定・変換が移高／反転／切り詰めの3種のみで薄い |
| ベースの奏法（スライド・ハンマリング・ゴースト） | ニュアンスは DAW の領分・Otomemo はピッチベンド等を持たない |

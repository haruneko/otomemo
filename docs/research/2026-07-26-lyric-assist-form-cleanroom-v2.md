## 1. 設計の芯

このツールは「歌詞を書くエディタ」ではなく、**言葉と音を突き合わせる作業台**である。

- 作業の単位は**セクション**。曲先・詞先はセクション単位で反転するのだから、「どちらが先か」をツールの構造にしてはいけない。固定されている側と動かす側が入れ替わるだけの、同じ一つの台。
- 機械の仕事は**候補を差し出すこと**と**印をつけること**まで。採点しない、直さない、止めない。韻・アクセント・音数の理屈は欄外の鉛筆書きであって、赤ペンではない。
- スマホは**拾う場所**、机は**組む場所**。ただしデータも作業台も同一で、出先で拾った断片が机の上に既に載っている、という連続性が生命線。
- 推敲の最終審級は「歌ってみる」。だから**声に出す・音を鳴らす**動線を作業台から一動作で。

## 2. 要る面の一覧（導出と論証）

導出の起点として、作詞の作業を分解する：
- (a) 断片を拾う（出先・細切れ時間）
- (b) 音数・リズムに言葉を当てる（曲先）
- (c) 言葉の音数・抑揚から音を起こす（詞先）
- (d) 響き・アクセント・歌いやすさを確かめる
- (e) 2番を1番の譜割りに合わせて書く
- (f) 曲全体の物語・感情の流れを保つ
- (g) 歌って確かめる
- (h) 迷った案を捨てずに比べる

この8つを最少の面に畳むと、**画面は4枚、シート（画面内の引き出し）が3つ**になる。

### 画面A：断片帳（主・スマホの入口）
- **目的**：(a)。思いついた一行・言い回し・題・母音遊びを、5秒以内に放り込む。
- **見えるもの／できること**：時系列の断片リスト。テキスト入力と音声メモ（鼻歌・呟き）の2種だけ。曲やセクションへの紐付けは**後回しにできる**。断片を長押し→「この曲のこのセクションへ」で昇格。
- **なぜ要るか**：細切れ時間が原点である以上、「どの曲の？どのセクションの？」と問う入口は捕獲率を殺す。分類を先送りできる受け皿がなければ、使い手は標準メモアプリに逃げ、ツールは出先で死ぬ。ただしそれだけなら標準メモと同じなので、断片帳の真価は「候補シートに自分の断片が湧く」接続にある（拾った言葉が、後日、譜割りの穴に候補として再登場する）。

### 画面B：曲の地図（従・移動と文脈の担当）
- **目的**：(f)と、セクション間の移動。
- **見えるもの／できること**：セクションの縦一列（A / B / サビ / 2A…）。各行に：セクション名、状態（詞のみ・音のみ・両方・仕上げ済み）、そのセクションの役割・感情の一言メモ。冒頭に**曲の羅針盤**＝テーマ・語り手・視点/時制を数行で。タップで画面Cへ。並べ替え・追加・複製（「2番はこのメロを写す」）。
- **なぜ要るか（所与とせず検討した）**：捨てる案も真剣に考えた。作業単位がセクションなら俯瞰は不要では？——不要にならない理由が2つある。(1) 作詞の層に「構成」「感情の移動」が明示的にあり、これはセクションの中からは見えない。サビを書いている最中に「Aメロで既に言ってしまった言葉」「感情の高低の並び」を確かめる場所が要る。(2) 往復作業は「Aメロ→2番→サビ→…」とセクションを渡り歩く。渡るための廊下が要る。
- **ただし限定する**：これはタイムラインでもピアノロールでもない。**目次＋一言メモ**に留める。曲の時間構造の本丸はDAWにあり、ここで俯瞰編集を始めた瞬間にDAWの劣化コピーになる。

### 画面C：セクション作業台（主役。ツールの本体）
- **目的**：(b)(c)(d)(e)(g)(h)のすべて。言葉と音の突き合わせ。
- **見えるもの**：上下2段。上段＝**音の影**（音符そのものではなく、音数・リズム・伸ばす位置・ざっくりした音高の起伏を示すスロット列）。下段＝**言葉**（行単位の歌詞。各音節がスロットに対応づく）。
- **できること**：
  - **錨の切替**：「メロに合わせる（曲先）」＝上段固定・下段を書く／「言葉から起こす（詞先）」＝下段固定・上段に言葉のモーラ数・抑揚・母音の並びが影として立ち上がり、それを整えてリズム案として持ち出せる。切替は1タップ。同じ画面で錨だけ替える——これがこの設計の心臓で、往復が「モード変更」でなく「手首の返し」になる。
  - **印（ガードレール）**：伸ばす音の母音、行末の母音（韻）、アクセントと音程の逆行、子音の詰まり——を下線や淡色マークでインライン表示。**トグルで消せる。点数は出ない。**
  - **写し書き**：2番を書くとき、1番を**薄い下敷き（ゴースト）**として同じスロット上に重ねる。音数の一致・不一致が一目で見える。(e)の専用画面は要らない、下敷きで足りる。
  - **歌う**：再生ボタンでメロ（合成音で十分）を鳴らしながら音節を追い、録音ボタンで自分の声を録ってその行に貼る。
  - **行の別案**：各行は別案を積める。横スワイプで差し替え比較。捨てた案も残る。(h)。
- **なぜ要るか**：作詞の全層のうち、譜割り・響き・歌いやすさは「言葉と音が同じ視界にある」ことでしか作業できない。これをやる道具が世に薄く、メモアプリにもDAWにもない。ツールの存在理由そのもの。

### 画面D：曲一覧（従・玄関）
- 曲のリストと新規作成。論証するほどのものはないが、無いと入れない。最薄でよい。

### シート（画面ではなく、Cの中の引き出し）
- **候補シート**：スロットや行を選んで引き出すと、その穴に合う候補——音数の合う言い換え、母音の合う語、そして**自分の断片帳から関連する断片**——が並ぶ。機械の候補と自分の過去の拾い物が同じ棚に並ぶのが思想の体現。「選ぶのは人間」。
- **語さがしの引き出し**：文脈なしで「〜aiで終わる暗い色の言葉」を漁る遊び。候補シートの自由入力版。詞先の細切れ時間に効く。
- **録音・再生バー**：Cの下端に常駐する小さな帯。

### 導出の結果、捨てたもの
- **診断・採点レポート画面**：捨てた。理屈を別画面に集約した瞬間、それは「検定を受けに行く場所」＝審判になる。思想に反する。指摘はインラインの淡い印のみ。
- **楽譜・ピアノロールエディタ**：捨てた。楽譜入力はDAWの仕事で、二重化すれば両方中途半端になり、スマホでは操作不能。ツール内のメロは「影」（音数・リズム・起伏）で十分。精密さが要る作業は机のDAWで。
- **韻辞書の独立画面**：捨てて引き出しに降格。独立させると辞書アプリになり、文脈（この穴に、この音数で）から切れる。
- **AIとの対話（チャット）画面**：捨てた。会話UIは候補を「言葉の穴」から切り離し、正解を出す機械の顔をし始める。候補はスロットに対して湧くべき。
- **バージョンツリー・完全な履歴管理**：捨てた（行の別案スタック＋いつでも戻れる程度で足りる）。作詞の比較単位は「行の別案」であって「ファイルの版」ではない。

## 3. 面同士の関係と往復の回り方

```
断片帳(A) ──断片を昇格──▶ 作業台(C) ◀──セクション選択── 曲の地図(B)
   ▲                        │  ▲
   └──候補シートに断片が湧く──┘  └─ 錨の切替（曲先⇄詞先）は C の中で完結
                                └─ 隣のセクションへは B を経ず左右スワイプでも移動
```

典型の往復：「Aメロのメロに詞を当てる（C・メロ錨）→ 2番を書く（C・1番を下敷きに）→ サビの詞を書く（C・言葉錨）→ その詞のリズム案を持って机のDAWへ → 戻ってきてサビのメロを影として入れ、詞を微調整」。**この間、画面遷移は実質ゼロ〜スワイプのみ**。方向の反転が画面の引っ越しにならないことが、この設計の合否判定基準。

曲の地図(B)は「渡り廊下＋羅針盤」。書いている最中に上端の羅針盤（テーマ・語り手）一行が常時見えており、引き下ろすと地図全体が出る。

## 4. スマホ／机の出し分け

同じ4画面・同じデータ。**出し分けは配置と入力手段だけ**で、機能の有無で差をつけない（出先でも仕上げに踏み込みたくなる日はある）。

- **スマホ**：起動即、断片帳 or 最後に触った作業台。1カラム。候補シートは下からのボトムシート。録音ボタンを親指圏に大きく。行の別案は横スワイプ。音の影の入力は「画面をリズムでタップ」（歩きながら鼻歌の律動を叩ける）。
- **机**：作業台を中央に、左レールに曲の地図、右に候補パネルを常時展開。1番の下敷きは上下重ねでなく並置も可。キーボード主体（行移動・別案切替・再生をショートカットで）。メロの影はDAWからのファイル持ち込み（MIDI等）や録音の解析でも入れられる。仕上げ・写し書き・構成の見直しは自然と机が主戦場になる。
- **暗黙の必須**：端末間の同期は機能ではなく前提。出先で拾った断片が机に「もう載っている」ことが体験の核。

**断片帳**：入力欄が最上部に開いた状態で起動。下に断片が新しい順。各断片にマイク印（音声）か文字。右スワイプで「どこかの曲へ」。

## 6. 作る順と理由

1. **作業台の芯**（音の影スロット＋歌詞行＋モーラ対応＋再生）：ツールの存在理由はここにしかない。断片捕獲だけなら標準メモが既にあり、勝負にならない。まず「言葉と音が同じ視界にある」を成立させる。
2. **断片帳＋昇格動線**：原点シナリオ（出先）を塞ぐ。作業台がある今、断片には行き先がある。
3. **曲の地図＋1番の下敷き**：セクションが2つ以上・2番が発生した瞬間に必要になる構成層を支える。
4. **候補シート（機械の候補＋断片の再浮上）**：機械の出番は、人間の作業が台に載ってから。先に作ると「正解を出す機械」に育つ危険がある。
5. **印（ガードレール）の充実・録音貼り付け・語さがし**：磨き。

順序の原理：**人間だけで一周回る道を先に舗装し、機械は後から歩道の脇に立たせる。**

## 7. 迷った判断とトレードオフ

- **曲先・詞先を1画面か2画面か**：2画面に分ければ各画面は単純になるが、反転がセクション単位で頻発する以上、反転＝画面移動は往復を殺す。1画面＋錨切替を選んだ。代償はUIの過密で、「錨でない側は薄く沈める」表示規律で払う。
- **メロをどこまでツール内に持つか**：正確な音高がないとアクセント逆行の検出精度は落ちる。それでも「影」に留めた。楽譜を持ち込むとDAWと競合し、スマホで破綻し、作詞の道具でなくなる。精度は「ざっくり起伏の手入力＋机でのファイル持ち込み」で妥協。
- **断片帳の墓場化**：分類を先送りできる受け皿は、必然的に断片の墓場を生む。全断片の整理を強いる代わりに、候補シートでの再浮上に賭けた。掘り返されない断片は死んでよい、という割り切り。
- **印を能動的な警告にするか**：能動（ポップアップ等）は気づかせる力が強いが審判臭が出る。受動の淡い印に倒した。見落としは起きるが、最終審級は「歌ってみる」であり、印はそこへの補助線に過ぎない——思想側に倒す。
- **曲の地図の薄さ**：感情の移動を線やグラフで可視化する案は捨て、一言メモに留めた。可視化は「感情の正しい形」があるかのような顔をするため。ここも思想側に倒したが、曲が長大な場合に地図が力不足になる可能性は残る（そのときは机側のみ拡張を検討）。

一行に畳むなら：**セクションという作業台の上で、言葉と音のどちらを錨にするかを手首の返しで替えられること**——それがこのツールの全部で、残りはその周りの廊下と引き出しである。

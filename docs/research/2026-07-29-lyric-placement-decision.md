# 1. 結論

**歌詞の正データは「セクション」に置く。** セクションが句の列を持ち、句が自分の範囲と、漢字仮名交じりの表記を持つ。

向きは変わっていない。**変えたのは理由**です。前の版は「1番と2番で詞だけ違う形が分家でタダで手に入る」を一番の柱にしていましたが、これはコードを読むと成り立たないので捨てました。

# 2. 何を根拠にするか（実測3つ）

**(a) メロの中に置くと、書いた詞が数秒後に消える。**
メロの自動保存は毎回 content を決め打ちで作り直す（`useNetaEditor.ts:334`）＝歌詞の欄を足しても、音符を1つ動かした数秒後に消えます。セクションは同じ関数の別の枝で、content を触らない（`:347`）＝壊れません。

**(b) メロが無い場所に詞を置くために、空のメロを作らなくて済む。**
音符ゼロのメロは尺の計算で1小節として数えられる（`sectionContext.ts:81, 88`）＝置いた瞬間に曲の長さが狂う。セクションに句だけ置けば、この工事が要りません。

**(c) 詞のあるメロが、曲に入っていないセクションの中にある。**
「みなそこイントロ」の親セクション（題名「組み合わせテスト」）はどの曲にも入っていません。曲に置く形だと、この詞には置き場がない。

**(c)については正直に書きます。実例は1件です。** 前の版は「セクション22件中、曲に入っているのは3件」を根拠にしていましたが、22件の題名は「★E2E 6/8確認」「CP test」「テストテスト」「新しいセクション」など**大半が検証用**で、これを数えるのは、同じ文書が歌詞ネタ8件を「全部捨てデータ」として切り捨てたのと物差しが合っていません。数え上げは取り下げます。

(a)と(b)は実データの件数に関係なく効きます。(c)だけがn=1です。

# 3. 撤回した2つ

**撤回1：「分家すれば詞だけ別・メロは共有」は今のコードでは起きない。**

分家の確認から「この曲だけ変える」を選ぶと、こう動きます（`useCowGuard.ts:89-93`）。

```
その親の下にある、そのセクションの配置を全部拾う
　→ 全部を同じ1つの分家へ差し替える
```

実データの `68_SONG` は `68_Aメロ` を0拍目と12拍目の2回置いています。ここで分家を選ぶと**両方とも同じ新セクションを指す**＝1番も2番も同じ詞のまま。「詞を分けたい人が詞を分けられない」という一番悪い外れ方をします。

ただし、**1配置だけを正しく分家する実装は既にあります**（`FormStrip.tsx:224-236`。曲フォームの「分家にする」＝先頭の1配置だけ差し替え）。無いのは「詞の1文字目で出る確認」からその道を通ること。つまり必要なのは新発明ではなく、既にある2つの道の繋ぎ直しです。

**撤回2：「オーナーはすでに使い回しの恩恵を受けている」は事実と違う。**

# 4. 音符に写した読みは、保存しない

ここが今回の一番大きい直しです。

句の表記から機械が読み（かな・高低）を出し、その句の範囲に重なる音符へ写す——この向きは変わりません。**変えたのは「写した結果をDBに書かない」こと。** 画面を出すとき・歌わせるときに、その場で組み立てます。

理由は、**3つの出口が全部「渡された音符の列」を見ている**からです。

- **仮歌**：ブラウザは `/neta/:id/sing`（保存された読みを使う口）を**使っていません**。使っているのは汎用の `/sing` で、音符と読みをその場で渡す形（`api.ts:246`・そのコメントに「web からは未使用」と明記・`playback.ts:47`）。
- **音符の中の文字**：`PianoRoll.tsx:423` は渡された音符を描くだけ。
- **赤黄の印**：`PianoRoll.tsx:74` → `computeLyricHits(notes)` も渡された音符を見るだけ。

＝保存しなくても3つとも動きます。逆に**保存すると壊れます**。1番と2番が同じメロを共有していれば、あとに書いたほうの読みが勝って、もう片方の仮歌と表示が別の詞のものになる。

保存しないと決めると、副産物として次の2つも解けます。

- **1つのセクションの中に同じメロが2回置かれている場合。** 実データの「検収-Aメロ-20260714」は同じメロを0拍目と64拍目に置いています。ここに前半と後半で別の句を書いても、写しを保存しないので衝突しません。
- **一方向の写しで既存のかな入力が黙って消える問題**（後述）。

なお、チャットから呼ぶ `sing_neta` は保存された読みを使う口のままです。これは従来のかな入力で入ったものを歌わせる道として残ります（実データ4件がそれ）。

# 5. 1番と2番をどう分けるか（作り直した答え）

既定は別セクション（傾きどおり）。同じセクションを2回置いた状態で2番の詞を書きたくなったとき、こうします。

1. まず**曲フォームの「分家にする」を明示で踏む**（`FormStrip.tsx:224`。既にある操作で、1配置だけ差し替わる）。
2. これでセクションが分かれ、**その下のメロ・伴奏は同じ実体のまま**残ります（分家は子をコピーせず辺だけ複製する＝`core.ts:143`）。
3. 分かれたセクションに2番の詞を書く。メロを直せば1番にも2番にも効きます。

前の版との違いは、**「詞の1文字目で自動的に出る確認に任せる」のをやめた**こと。今の確認は配置を全部まとめて差し替えるので任せられませんし、明示の操作を先に踏ませるほうが「暗黙の操作を増やさないでほしい」とも合います。

工事としては、**詞の編集では分家の自動確認を通さない**（明示メニューへ誘導する）か、確認に「この配置だけ」を足すか、どちらかが要ります。**どちらにせよ追加実装はゼロではありません。**

# 6. 白紙の曲・まだ曲に入れていないもの

前の版が答えていなかったところです。

**思いついた1行（曲もセクションもまだ無い）** ＝ 今ある歌詞ネタ（`kind:"lyric"`・textarea1枚）に書く。ここは曲に紐づかない下書きの置き場として残します。曲に並べるときにセクションの句へ移す。

**セクションが1つも無い白紙の曲** ＝ セクションを1つ作る操作を明示で踏んでもらう。勝手には作りません（「実体を明確に作る合図なければ作られたくない」）。**これは曲に置く案なら要らなかった手数で、セクション案が払う代償です。** 隠さずそう書きます。

**曲に入れていないセクションの詞** ＝ ここは**先に聞かないと決められません**（下の問い）。通しの面は曲を辿るので、曲に入っていないセクションの詞は通しに出ません。「推敲は必ず通しでする」が確定事項なので、放置できない穴です。

# 7. 句の形

**範囲は任意。空でよい。** 「セクションの頭から何拍目・何拍ぶん」を持てますが、**まだメロが無い段階では空のまま置けます**。詞側で使う物差しは音数であって拍ではないので、道具の側が先に拍を決めさせるのは筋が悪い。

範囲が空のとき、出るのは「メロなし」だけ。「字余りN」「あとN音」は範囲が入ってから出ます。

**負の拍を許します。** 実データで詞の付いたメロ「みなそこイントロ」は先頭が **-0.5拍**（弱起）。104件中この1件だけですが、まさに詞が入っている1件です。

**範囲は音符から自動で決めません**（決めるとメロが無い場所に句が置けなくなる）。その代わり、あとで符割りが変わって範囲がずれたときは**ずれを見せます**（自動で直さない）。

**句の中身は、決まっている語と「まだ決まっていない枠」の並び。** 枠は音数とアクセントの条件だけを持ちます。`xxxxx yyyyy zzzzzz wwwww` の「zの中の単語1個だけ無い」を表すのがこれ。表記1本では、真ん中の1語だけ無い状態を文字列の中の目印で表すしかなく、その目印は読み取りに食わせた瞬間に読みを壊します。

# 8. 既存のかな入力との関係

「1つも殺さずに済む」は**撤回**します。

音符に直接かなを打つ口（詞モード）は、**句が重なっている範囲では閉じます**。理由＝そこは句の読みが出るので、打ってもすぐ隠れて、打った内容がどこにも残らない。「殺していない」のではなく「消えるまで気づかない」形になります。閉じると明言するほうが正直です。

句がどこにも重なっていない音符では、従来どおり打てます。仮歌だけ当てたい素のメロはこれまでどおり。

# 9. 落とした案

**曲に置く** ＝ 落とす。根拠は§2(c)の1件（n=1）と、白紙のセクションを育てている途中に詞が書けないこと。**ただし§6のとおり、白紙の曲では逆にセクション案のほうが手数が多い。** 一方的に勝っているわけではありません。

**メロに置く** ＝ 落とす。理由は§2(a)(b)。工事が2つ増えるだけで、できることは同じ。

**配置ごとに持つ** ＝ 落とす。理由は「並べ替えると消える」（配置の付け替えは消して置き直す＝`compose-repo.ts:23, 37`）と「曲に置く前は配置が無いので書き始められない」の2つ。**「DBの作り変えが要る」は落とす理由になりません**（主キーは既に位置を含む＝`db.ts:238`、列を足す移行は過去に2回やっている＝`db.ts:216-250`）。

# 11. 採らなかった指摘

**「配置を指す手段が無いので、1配置だけ分家できない」** ＝ 採りません。位置は既に返っています（`core.ts:283` の `{position, ord, node}`）し、配置の主キーは位置を含みます（`db.ts:238`）。1配置だけ差し替える実装も既に動いています（`FormStrip.tsx:224-231`）。足りないのは、確認の関数が位置を受け取っていないことだけ（A1）。

**「同じセクションを1曲に2回置く例は検証データなので、共有セクションの話は弱い」** ＝ 半分だけ採ります。実例が検証データなのはそのとおりなので「実データで誤り」という言い方は取り下げます。ただし同じ子を複数の位置に置く形は仕様として入っていて（`compose-repo.ts:26-33`）、畳んで「×N」と出す画面もある＝**起こる形として想定済み**なので、「共有セクションなら詞は最初から別」という前提には立てません。

**「保存しないなら仮歌の入口を作り直す工事が要る」** ＝ 採りません。ブラウザの仮歌は既に音符と読みをその場で渡す口を使っています（§4）。作り直しは不要です。

## 1. 状態の見せ方の体系表

### 1.1 見せ方の原則（先に立てる。以降の全セルはここからの導出）

UIに出す言葉はすべて素の日本語（ブリーフ§5）。「穴」「伏せ字」はUIに出さない（却下理由§2-2）。以下の「帯」「枠」「棒」「点線」は絵の描き方を指す文書側の言葉であり、UIに出す名前ではない。

- **原則1（行）**: 歌詞は「句」を1行として縦に並べる。1行は上下2段＝**上段にメロ、下段に詞**。同じ場所の詞側とメロ側が、同じ行の別の段として常に対で見える。
  - 根拠: C-14（まだ音が無い詞とまだ詞が無い音を別物として扱う）を、場所を分けずに段を分けることで満たす。C-8（歌詞全体が空きも含めて見える）の器。裁定「句を構造に持つ」（ブリーフ§1）。
- **原則2（実体）**: **有るものは実体で描く**。メロ＝概形（音高の上下を示す点列・折れ線）、詞＝文字。
  - メロ概形の精度は**句内の相対的な上下の形**（正確な音高の判読は求めない）を提案する。理由: §2-1の目的は「詞を当てる対象の形が分かる」ことであり、正確な音高の確認・編集は既存PianoRollの仕事（R-4の行き来で担う）。幅360pxの通しの眺めで正確な音高は読めない。既存部品MiniRoll（当て込みメモ§5）を土台にできる。
- **原則3（帯）**: **メロのデータが存在する範囲を薄い帯で敷き、概形はその上に描く**。帯の中で音の無い所＝**意図した休符**。帯が無い所＝**メロ未定**。
  - 根拠: R-16・軸D5（未定と休符の見分け）。データ上も「メロのブロックが置かれている範囲」と一致し、二重帳簿を作らない（R-13）。
- **原則4（枠）**: **メロがあって詞が無い音は、音符の位置に空きの枠**を描く。枠の数＝音数＝埋める作業の大きさがそのまま見える。
  - 根拠: D-1相当（空きの所在と粒度が分かる）。「伏せ字○○○」の代わりに、記入欄が空いているという誰でも読める形にする（却下理由§2-2）。
- **原則5（棒）**: **詞を付けないと決めた音は、枠ではなく横棒**を音符の位置に描く。長い範囲には「詞なし」と添える。
  - 根拠: R-16・軸D1（意図して詞なしと未定の見分け）。記入欄の慣習（空欄＝未記入、横棒＝該当なし）に乗る。
- **原則6（点線）**: **句も音も何も無い区間は点線の枠**で描き、**当ての注記**（小節数・音数・短いメモ）を任意で添えられる。手で置いた予定（裁定「予定マーク」）も、セクションの範囲から導かれる残り（範囲はあるが中身が無い区間）も、同じ点線で見える。
  - 根拠: 裁定「句＋予定マーク」（ブリーフ§1）・軸D3（当てあり/なしの区別＝注記の有無）。
- **原則7（仮）**: **構成の仮（セクションの存在・位置が未確定）は、見出しを点線にして「仮」と書く**。確定した構成の見出しは実線。
  - 根拠: 軸E2・裁定「大枠づくりは内」（ブリーフ§1）。中身の空き（原則6）と構成の仮（原則7)は別の事柄なので、点線を使う場所（区間の中身か、見出しか）で描き分ける。
- **原則8（色）**: **下書きの詞は薄い色、確定した詞は通常の色**。確定の操作は編集の場に置く。
  - 根拠: R-11・軸D2。
- **原則9（並びの外）**: **置き場所が決まっていないものは、並びの外の置き場**（並びの下の「まだ並びに入れていない」領域）に、普通の句と同じ形（概形＋文字）で並ぶ。
  - 根拠: 軸D4（仮置きモチーフ）・B-7（モチーフ一節しか無い初期）・軸E3（並びが無い）。場所が未定のものを並びの中に無理に置かない。
- **原則10（印）**: 音韻・イントネーションの印は**文字への付け足し**（既存PianoRollと同じ 赤=アクセント逆行/黄=注意 の配色。M-19）とし、表示の切替（素の表示／音韻／イントネーション）で選ぶ。点数・優劣は出さない。
  - 根拠: C-3・C-7・E-2・R-23・ブリーフ§5。

導出の要点: **「何が決まっているか」を層で塗り分ける**。メロの決定＝帯、詞の決定＝文字、決定済みの空き（音数が決まった空き）＝枠、意図した無し＝棒/休符、何も未決＝点線、構成の未決＝見出しの点線。この6層の重なりだけで、以降の全状態が原則の組合せとして一意に見える。

## 2. 場の構成の導出

### 2.1 仕事の整理と切り口

仕事は3つ＋行き来（ブリーフ§4-2）:
1. 通しで見る（推敲含む。B-9・B-10・C-7・C-8）
2. 空きを埋める（B-1〜B-8・C-5・C-6）
3. 大枠を決める（構成の仮の並び・名前・当て。ブリーフ§1裁定）
4. 既存画面との行き来（R-4ほか）

場の割り方を決める切り口として「仕事の種類で割る」「1枚に全部入れる」「見ている範囲の広さで割る」を検討した。

### 2.2 検討した案と捨てた理由

**案ア: 仕事ごとに3枚（通しの面／埋めの面／構成の面）**
- 捨てた。理由: 「通しで見る」と「大枠を決める」は**同じ対象（セクションの並びと句）を同じ縮尺で見る**仕事であり、分けると同じ絵が2枚できる。2枚の間で現在地（R-8）と反映（R-13）の同期問題だけが増える。さらにE3（断片だけの初期）では通しの面も構成の面もほぼ空になり、どちらに居るべきか分からない。B-9（曲全体のまだらを置いて、次にどの空きを埋めるか選ぶ）は、構成と中身が**一枚の眺め**にあってこそ成り立つ。

**案イ: 1枚に統合（通しの面の中で埋める作業もその場で行う）**
- 捨てた。理由: 埋める作業の場は、裁定により**二欄並置（意味欄・音の枠欄）**＋前後の確定部分（R-17）＋候補一覧（C-6）＋文字入力（キーボード）を同時に必要とする。幅360pxの縦持ち（ブリーフ§5）では、これを通しの眺めの上に同居させると、読み・並べ替えの場に編集具が常駐して推敲（B-10）の読みを濁し、スクロール中の誤編集も生む。下にシートで出す形も、前後表示・二欄・候補・キーボードの四つで実質全画面になる。既存アプリの作法（一覧が主役のmv-home／編集が主役のmv-paneの1画面切替。当て込みメモ§1）からも外れる。ただし「1枚に見える」体験の利点は、編集から戻ったとき同じ位置に戻る（R-6・P-8）ことでほぼ回収できる。
- 部分的に残した点: **構成の粒度の編集（見出しの追加・並べ替え・名前・当て・仮/確定・予定を置く）は通しの面でその場で行う**。これは眺めの粒度と操作の粒度が一致しており、別の場に出す理由が無い。

**案ウ: 大枠づくりを既存の曲画面（セクション並び画面）に寄せ、新しい場は通し＋埋めの2枚**
- 捨てた。理由: 既存の曲画面のセクションカードは役割・小節数・レーンの実体を前提にした**詳細配置の入り口**であり、「名前と当てだけの仮」を置く粗い粒度と合わない。裁定（ブリーフ§1）も「粗い粒度の構成づくりはこのツールの内／詳細配置は既存画面のまま」と線を引いている。またE3の初期（断片しか無い）では曲画面は実体を要求して重く、B-7の入りに向かない。詞と音の欠け具合を見ながら並びを考える（B-9）ためにも、構成づくりは欠けが見える眺めと同じ場にあるべき。

**案エ（採用）: 見ている範囲の広さで2枚＋既存画面との行き来**
- **歌詞全体画面（通しの面）**: 曲全体スケール。仕事1（通しで見る・推敲の表示切替）と仕事3（大枠を決める）を担う。読む・並べる・構成を置く場であり、**詞の文字・メロの中身はここでは編集しない**（提案。§5問い1）。
- **句の編集画面（編集の面）**: 一箇所スケール。仕事2（空きを埋める）を担う。二欄並置・前後表示・候補一覧（一覧はこの面の中のシート。既存FormSuggest型）・歌詞ネタ引用・チャット相談・PianoRoll/配置への橋。
- 既存画面（曲のセクション並び・レーン配置・PianoRoll・歌詞ネタ・チャット・トレイ）へは、同じ箇所を指したまま行き来（R-4）。
- 採った理由: 場の数が「範囲の広さ」という1つの物差しで決まり、恣意の余地が少ない。曲全体スケールの仕事2つは対象も縮尺も同じなので1枚に、箇所スケールの仕事は集中の場に。既存アプリのmv-home/mv-pane作法と同型になり、導線・戻る・状態保持（R-6・R-7）を既存の作法に乗せられる。
- 推敲専用の面（4枚目）は作らない。推敲は通しの面の**表示切替**（素の表示／音韻／イントネーション。原則10・R-23）で担う。眺めは同じで印だけが替わるため、場を分けると同期問題だけ増える。

## 4. 作画への指示書（次フェーズ＝HTMLモック）

### 4.1 共通

- 幅360px縦持ち基準。既存の暗色調・「← 戻る」ヘッダ・再生バーの見た目に合わせる（スクショ03〜06と同型）。
- UIに出す言葉は素の日本語のみ。禁止: 「穴」「伏せ字」「まだら」「スロット」等。使う言葉の例: 「歌詞」「セクションを足す」「予定を置く」「詞なし」「仮」「下書き」「確定にする」「候補を探す」「歌詞ネタから引く」「相談」「メロを開く」「配置を開く」。
- ダミーの詞は意味の薄い日常語の連なり（作品らしさ・詩情を出さない詰め物）。メロ概形もダミーの上下形でよい。
- 赤=アクセント逆行／黄=注意 の配色は既存PianoRollの凡例と一致させる（M-19）。

### 4.2 歌詞全体画面のワイヤー構成（上から）

1. ヘッダ: ← 戻る／曲名（プロジェクト名）／表示切替（素・音韻・イントネーション）
2. セクション見出し（貼り付き）: 名前＋小節の当て＋つまみ（並べ替え）。実線=確定・点線＋「仮」=仮
3. 句の行 × n: 上段=帯＋概形（またはその欠け）、下段=文字／空きの枠／横棒／点線＋注記。行の右端に小節範囲を薄く
4. 点線の区間（中身の無い範囲）・「セクションを足す」「予定を置く」
5. 並びの外の置き場: 見出し「まだ並びに入れていないもの」＋断片の行
6. 下端: 既存の再生バー

文字の並べ方: 素の表示では文字を普通に組み（推敲の読み流し優先）、音韻・イントネーション表示では文字を音符の時間位置に緩く揃える（対応の確認優先）。概形の帯は常に時間基準。

### 4.3 句の編集画面のワイヤー構成（上から）

1. ヘッダ: ← 戻る（歌詞全体へ）／曲名›セクション名›小節範囲
2. 前の句（薄め。文字＋概形。境界またぎでも出す）
3. 対象: 帯＋概形＋文字/枠/棒/点線を大きめに
4. 二欄並置: 「意味（言いたいこと）」自由記述欄／「音の枠」欄（音数・アクセント・小節。メロがあれば自動で入り、無ければ手で当てを書ける）。**左右や上下の順序で優劣を付けない**（C-4・E-1）
5. 次の句（薄め）
6. 操作列: 候補を探す／歌詞ネタから引く／相談／メロを開く／配置を開く／この範囲は詞を付けない／確定にする
7. 候補一覧（ボトムシート）: 2案を両方描く。(a)適合度順＝上から並べるが点数は出さない、(b)事実区分＝「音数ぴったり」「字余り1」「アクセント違い」の見出しで区分。各候補に宛先表示。選ぶのは人（C-11）
8. メロ側の空きを開いた場合: 4の代わりに「決まっている詞（音数・アクセント表示）」を主にし、操作が「メロ候補を頼む」「ピアノロールで置く」になる（S-8）

### 4.4 描く枚数（提案）

1. 歌詞全体画面・素の表示（主サンプル曲＝下記4.5。全長スクロールで描く）
2. 同・音韻／イントネーション表示（同じ曲・印と文字揃えだけ替える）
3. 同・初期状態3態（A6×B1／A6×B2／A6×B3+E3。短い曲3つ）
4. 句の編集画面・詞の空き・両端固定（C1）・候補=適合度順
5. 同・候補=事実区分（並べ方だけ差し替え）
6. 同・メロ側の空き（詞を見ながら）＋孤立（C4）の前後表示
7. 既存画面への足し込み: 曲画面カードの事実表示・「歌詞」ボタン・PianoRollの「歌詞で見る」＋入口〜遷移の図

## 5. オーナーに返す問い

設計者が決めるべきでないと判断した選択。いずれも上の設計はどちらでも成立する（提案の既定値だけ書く）。

1. **歌詞全体画面での直接編集**: 通しの面は「読む・並べる・構成を置く」に徹し、詞の文字はタップ1手で開く編集画面でだけ打つ、という切り分けでよいか。それとも語1つの空きくらいは通しの面でその場で打ちたいか。（提案の既定=編集画面に寄せる。理由=推敲の読み場の純度と誤編集の防止。ただし手数は1手増える）
2. **下書き/確定の印**: 句ごとに「下書き（薄い色）⇄確定」の区別を持つ運用でよいか。それとも書いたものはそのまま（印なし）が実感に合うか。（R-11は仮採。実際の書き方に合わせたい）
3. **歌の無いセクション（前奏・間奏）**: 歌詞全体画面では一行に畳んで出す／そもそも出さない、のどちらがよいか。（提案の既定=畳んで出す。曲の長さの感覚と再生位置の対応(R-22)が保てるため）
4. **曲がまだ無いモチーフから入るとき**: メロネタ単体から「歌詞で見る」と開いた場合、その場で曲を作って断片の置き場に入れる、でよいか。（R-3の実現形。勝手に曲が増えるのを嫌うなら、曲を選ぶ/作るの確認を挟む）
5. **仮のセクションと既存の曲画面の関係**: 歌詞全体画面で置いた仮のセクションは、(a)確定にした時点で既存の曲画面に実体として現れる、(b)仮のうちから曲画面にも仮の印付きで見える、のどちらがよいか。（大枠＝このツールの内／詳細＝既存画面、の境目の運用）
6. **予定の当ての形**: 点線に添える当ては自由記述だけでよいか、小節数・音数の欄も分けて持つか。（数値があると候補依頼(C-6)の条件にそのまま使える。提案の既定=自由記述＋任意の数値）
7. **候補一覧の並べ方**: 既定どおり、適合度順と事実区分の2案をモックで並べて判定いただく（ブリーフ§1のまま。ここでは決めない）。

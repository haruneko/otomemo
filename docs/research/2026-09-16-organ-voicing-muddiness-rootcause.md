# オルガンの型が濁って聞こえる原因（実測・2026-09-16）

## 結論（12行以内）
1. **主因＝ボイシング関数 `voiceToTop` の積み方**。トップ音を決めた後、残りの構成音を `QUALITY_INTERVALS` の並び順（R→3→5→7）で「今の最低音の直下」へ1つずつ下ろすため、**表の最後にある 7th（テンション）が必ず右手の最低音**になり、右手の幅が約22半音に広がる（三和音は約14）。`apps/web/src/music.ts:736-742`。
2. 実測（試聴と同じ進行・型の既定）：Fmaj7＝**F2 | E3 A3 F4 C5**（E3 は左手 F2 の長7度上＝低い長7度、さらに F4 と短9度）／Em7＝**E2 | D3 G3 E4 B4**（E2-D3 の短7度は低音域の限界より下）／Am7＝**A2 | G3 E4 A4 C5**（G3 が最低）。
3. **オーナーの見立て「7th の配置」は当たり**。7th/9th を持つコードを12ルート走査すると、7th が右手最低になる率＝maj7 8/12・m7 9/12・maj9/9/m9 10/12。三和音は0。
4. 副因①**低音域の音程の限界（lower interval limit）違反**：Em7 で E2-D3（短7度）、OG-SOUL/PB-BLOCK8 の左手5度 B2 と D3（短3度）。9th 系では12ルートで約20ペア。
5. 副因②**オルガン音色（持続・倍音が減衰しない）が①④を増幅**：F2 の第2倍音 174.6Hz と E3 164.8Hz の差 9.8Hz、E2×2 と D3 の差 18Hz＝最も粗く聞こえる帯のうなりが鳴りっぱなしになる。音色単体の不具合ではない（音符が正しければ出ない）。
6. 副因③（上の型のみ）左手の無い OG-STAB/OG-PUNCH では 7th が**最低音＝ベース役**になり Am7/G・Em7/D の転回に聞こえる。OG-PUNCH の Fmaj7 は E4 と F5 が**短9度**。
7. **否定**：(c) 前のコードの音の残り＝.mid でコード境界を跨ぐ音 0 件（followChords が正しく切っている・音源のリリース残響は未計測）。(f) ベース＝試聴の .mid にベースのトラック無し（ch0 のオルガンと ch9 のドラムのみ）。(d) の和音定義表そのもの・左手ルートの重ねは正しい。backlog の `"11"`（長3度＋♮11）はこの進行では**使われておらず無関係**（ただし同じ積み方で 11/13 は右手が左手より下に潜る＝別途悪化）。
8. **ピアノ系も同じ**：鍵盤の型は全部 `top`（既定72）経由で `voiceToTop` を通る（`apps/api/src/music/generate.ts:1035`）。PB-WHOLE-R10・PB-BLOCK8 の出音はオルガンと同一の和音。ピアノは減衰するので目立ちにくいだけ。
9. **直し方の推し＝案A「トップの下に密集で積む（音高順に並べてから下ろす）」**＋案Bの「左手がルートを持つとき右手のルートを省く」を選べるように。どちらも**既定の出音が変わる＝耳の裁定が要る**。

## 3. 候補ごとの判定
| 候補 | 判定 | 根拠 |

## 4. 外部の理論（出典）
- **低音域の音程の限界（Lower interval limit）**：音程ごとに「これより低いと濁る」最低音の目安。代表値（Wikipedia の表）＝短7度 F2-E♭3、長7度 F2-E3、短3度 C3-E♭3、長3度 B♭2-D3、完全4度 B♭2-E♭3。→ Em7 の E2-D3 は下回り、Fmaj7 の F2-E3 はちょうど境目。
  https://en.wikipedia.org/wiki/Lower_interval_limit
- **うなりと粗さ（Plomp & Levelt 1965）**：近い周波数の2音は臨界帯域の約1/4の差で最も粗く聞こえ、低域ほど帯域が相対的に広い＝同じ音程でも低いほど濁る。
  https://doi.org/10.1121/1.1909741
  計算：F2 第2倍音 174.6Hz vs E3 164.8Hz＝差 9.8Hz／E2×2＝164.8Hz vs D3 146.8Hz＝差 18Hz／A2×2＝220Hz vs G3 196Hz＝差 24Hz。いずれも粗さが大きい帯。
- **ドローバーオルガンの倍音**：足管の組み合わせで第2・第3倍音以上を持続的に加える音色。
  https://en.wikipedia.org/wiki/Drawbar_organ
- **鍵盤ボイシングの定石**（ルート省略・7th/3rd を中域に置く・短9度を避ける）：既存の研究 `2026-07-14-citypop-extended-voicings.md`（ルートレス A/B・「低域濁り」警告）、`2026-07-22-piano-comping-vocabulary.md`。
- ※上記 URL は本調査の場では再取得していません（表の値は一般に流通している目安）。

## 5. どの段で濁りが入るか
1. 型の定義（`apps/api/src/music/chordLibrary.ts:277-300`）：`top` 未指定なら生成時に 72（`apps/api/src/music/generate.ts:1035`）、STAB 76・PUNCH 84。**ここは原因ではない**（top は高さの目安だけ）。
2. 和音の定義表（`packages/music-core/src/index.ts:92-95` 等）：正しい。**並び順（7th/テンションが最後）が次の段で意味を持ってしまう**。
3. **実音化のボイシング（`apps/web/src/music.ts:723-747` `voiceToTop`）＝濁りが入る段**。736行でトップ音を除き、739-743行で表の順に「現在の最低音の直下」へ下ろす。
4. 左手（`music.ts:847-861` `lhPitchFor`）：ルートは C2〜B2 に置く＝正しいが、右手最低の 7th と低域で近接する。左手の色音には LIL ガードがあるが、**右手には同じガードが無い**。
5. 保持（`music.ts:1010` followChords）：正しく切れている。

## 6. 鍵盤全般に効く知見（手の形の設計にも共有）
- **トップを決めて下へ積む方式は、下ろす順を音高（トップから下へ近い順）で決めないと、表の最後の音（7th・9th・11th・13th）が一番下へ行く**。構成音の多いコードほど悪化し、11/13 は左手ルートより下に潜る。
- **右手の最低音にも低音域の限界チェックが要る**（左手には既にある＝`LH_HI=48`）。目安として右手の 3rd/7th/テンションは C3〜E3 より上。
- **左手がルートを持つ型では右手のルートは重複**。maj7 は右手に根音があると長7度/短9度が残るため、ルートを省く（ルートレス）か 7th を根音の上に置くのが定石。
- **左手の無い型（スタブ・高域パンチ）は最低音がベース役に聞こえる**＝最低音は R か 3rd、または 5th に限る規則が必要。
- 持続する音色（オルガン・パッド・ストリングス）は同じボイシングでも濁りが目立つ＝ピアノの耳判定で OK だった形がオルガンで NG になりうる。

## 7. 直し方の案（どれも既定の出音が変わる＝耳の裁定が要る）
| 案 | 中身 | 良い点 | 悪い点 | 既定の出音 |
|---|---|---|---|---|
| A 密集で下ろす | 残りの音を「トップから下で最も近い位置」に置き音高順に並べる（1オクターブ内の密集） | 変更が1関数・全鍵盤に効く・限界違反 0（§2.2 計算）・幅約9 | maj7 の根音-7th の半音は残る／開いた響きが欲しい型は open 指定が要る | 7th 系の全鍵盤型で変わる |
| B 右手ルート省略 | 左手がルートを持つ型で右手から R を外す（ルートレス） | maj7 の半音衝突が消える・音数が減りオルガンで特に澄む | 左手無しの型には使えない／三和音は2音になる＝三和音は対象外にする等の規則が要る | 左手ありの型で変わる |
| C 右手最低音ガード | `voiceToTop` の後で右手の 3rd/7th/テンションが限界より下なら1オクターブ上げる | 既存の積み方を保つ・左手ガードと同じ流儀 | 最低音だけ上げるとトップを越え声部が入れ替わる／根本（下ろす順）は残る | 低い音域のコードのみ変わる |
| D 最低音の度数規則（左手無しの型） | STAB/PUNCH 等で最低音を R/3/5 に制限 | 転回に聞こえる問題を消す | 左手ありの型には効かない | 左手無しの型で変わる |

**推し＝A を土台に、B をオルガン（持続音色）と左手ありの型で選べる形**。D は左手無しの型のため A と併用。C は A を入れれば発火がほぼ無くなる保険。着手順はスペック（`docs/design.md` のボイシング節）→ テスト（Fmaj7/Em7/Am7 の期待音高）→ 実装、の後に**オーナーの耳で A 単独／A+B を聞き比べ**。

## オーナーの耳判定（2026-09-16・試聴帳 https://claude.ai/artifact/KBDCHZwQMk4yxk3rXqRxtv ）
**7型すべて（OG-PAD/PAD2/STAB/SOUL/PUNCH・PB-WHOLE-R10・PB-BLOCK8）で「案A＋Bがいい」**。→ 案A＋B を実装へ（既定の出音を意図して変える）。左手の無い型（OG-STAB・OG-PUNCH）の分数コード化は案B が効かず残る＝案D は未裁定。
注記：試聴帳の保存キーの作り方に不具合があり、OG-STAB と OG-SOUL の判定ボタンが共有になっていた（どちらも A＋B が保存されていたので結論は変わらない）。

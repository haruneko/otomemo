# 作詞補助ツールの画面設計（白紙／クリーンルーム・Fable）

- 日付: 2026-07-26
- 問い: 理想の作詞補助ツールに**どんな画面が要るか**を、既存アプリに一切引きずられず白紙から設計する。
- 経緯: 器の裁定（[[2026-07-26-lyric-assist-vessel-verdict]]）が「新規画面ゼロ・配線修理だけ」に収束＝既存アプリに引きずられたとしてオーナーが受け入れNG。**「歌詞全体を眺める画面はマスト」を確定要件**として、アプリコードを読ませないFableに白紙設計させた（[[project-lyric-assist-whole-song-overview]] / [[feedback-cleanroom-design-no-app-code]]）。本docはその生成果（Fableはファイル読み取り0回＝クリーンルーム遵守）。
- 位置づけ: これは1つの設計提案＝材料。採否・修正の物差しはオーナー。実装への落とし込み（既存資産との突き合わせ・詞先メロ断線バグの扱い）は別段で行う。

---

## 設計の芯（Fableが前提から導いたもの）

- 芯1：中心は「曲の見開き」＝歌詞全体ビュー。ここがホームであり、常にここへ帰る。
- 芯2：詞先/曲先を「モード」や「別画面」にしない。方向はセクションごとの状態であって場所ではない。同じ作業画面が、そのセクションに今あるもの（詞だけ/メロだけ/両方）に応じて姿を変える。
- 芯3：理論の表示はすべて「任意オン・静かな印」。点数や合否は出さない。赤いエラーを出さない。

---

## 1. 画面の一覧

### 主となる画面（それ自体が行き先になる場所）

**S1. 歌詞全体ビュー（曲の見開き）……主・中心 ※マスト要件**
- 目的：曲全体の詞をひとつづきの「読み物」として俯瞰する。フォームの流れ、言葉の運び、繰り返しと変化を眺める。次にどこを書くか決める場所。
- 見えるもの：全セクションの歌詞全文（曲順）、フォームラベル（Aメロ/Bメロ/サビ…）、各セクションの状態（詞なし/下書き/決まった、メロあり/なし）、任意で母音・音数の重ね表示。
- できること：通し読み、セクションへの移動（作業画面へ）、1行だけの軽い直し、フォーム構成の並べ替え・追加、番同士の見比べ。

**S2. セクション作業画面（詞とメロの作業台）……主**
- 目的：1セクションに集中して、言葉を書く・メロに言葉を当てる・言葉から音数を起こす。往復作業の現場。
- 見えるもの：そのセクションの歌詞、（メロがあれば）音符のマス目（音数・長さ・伸ばす音・音の上がり下がり）、行ごとの音数、前後セクションの端の行（文脈）、候補の引き出し。
- できること：本文の編集、音符への言葉の割り当て（譜割り）、音数を数えながらの下書き、候補行の差し替え、再生して耳で確かめる、隣のセクションへ横移動。

**S3. ネタ帳（言葉の断片置き場）……主（スマホでは事実上の入口）**
- 目的：出先で浮かんだ言葉・フレーズ・題材を、失う前に最短で書き留める。あとで曲やセクションに拾い上げる。
- 見えるもの：断片の一覧（新しい順）、タグ、どの曲に使ったかの印。
- できること：2タップ以内の書き付け（テキスト・音声メモ）、断片を曲/セクションへ送る、検索。

**S4. 曲一覧（入口）……主**
- 目的：曲を選ぶ・作る。作業の玄関。
- 見えるもの：曲の一覧（タイトル・最終更新・詞の埋まり具合の小さな印）。
- できること：曲を開く（→S1へ直行）、新規作成、複製。

### 従となる画面・パネル（主画面に付属して呼び出すもの）

**S5. 曲の覚え書き（テーマの紙）……従（S1から開く1枚）**
- 目的：意味・物語の層を1枚に固定する。テーマ、語り手、視点/時制、感情の移り変わり（セクションごとに一行）、サビで言い切る一言、タイトル案。
- 位置づけ：作業中いつでも横目で見られる「北極星」。書式は自由記述＋セクション対応の一行メモ。

**S6. 言葉の道具箱（韻・母音・類語）……従（画面でなくパネル/シート）**
- 目的：選択した語や行を起点に、母音の並びが同じ語（韻）、類語、言い換え候補を出す。選択肢を広げる道具であって、正解を出す装置ではない。
- 呼び出し方：S1/S2/S3 のどこでも、語句を選択→道具箱。独立画面にはしない（流れを切らないため）。

**S7. 候補と履歴の引き出し……従（S2に付属するドロワー。タブ2枚）**
- 目的：タブ1「候補」＝同じセクションの別案（自分の別稿・機械の提案）を並べて見比べ、行単位で取り込む。タブ2「履歴」＝時間軸の保存版、いつでも戻れる。
- 思想の置き場所：機械の提案は必ずここに「候補」として入る。本文に勝手に書き込まれることは絶対にない。

**S8. 通しで確かめるモード……従（S1の表示モード）**
- 目的：推敲の要「歌ってみる」。飾りを全部消した全文表示（黙読・音読用）と、メロがある区間の通し再生に合わせて歌詞が送られる表示。録音メモ（自分の歌）をここで残せる。

画面はこの8つで足りる、と判断。数を増やすより「S1⇄S2の往復が滑らかであること」に全予算を使う。

## 2. S1 歌詞全体ビューの詳細設計（最重要）

設計原則：ここは「書く場所」ではなく「読む場所」。ただし読んでいて気づいた1行の直しはその場でできる（直しに気づくのは読んでいる時だから）。構造的な作業（譜割り・大改稿）はS2へ降りる。

### (a) 基本レイアウト（スマホ・縦1列）

```
+----------------------------------+
| 曲名「◯◯」        [覚え書き][…] |
| A B サ A' B サ C 落サ サ   ←フォーム地図（横スクロール可・現在地が光る。押すと跳ぶ） |
+----------------------------------+
| ■ 1番 Aメロ      [詞:決 メロ:有] |
|  ひと駅ぶんの さよならを         |
|  ポケットの中 あたためて         |
|                                  |
| ■ 1番 Bメロ      [詞:下書き]     |
|  …                               |
|                                  |
| ■ 1番 サビ       [詞:決 メロ:有] |
|  会いたいだけじゃ 足りなくて     |
|  …                               |
|                                  |
| ■ 2番 Aメロ      [詞:なし メロ:有]|
|  （まだ言葉がありません）         |
|   ♪ ６音・７音・６音・８音 ←メロだけある区画は「音数の器」を薄く見せる |
| …                                |
+----------------------------------+
| [通しで読む] [表示▼] [書き出し]  |
+----------------------------------+
```

要点：
- 全文が曲順に、スクロールひとつで最後まで読める。折りたたみを既定にしない（俯瞰が目的なので隠さない）。
- 各セクションの頭にフォームラベルと状態バッジ（詞：なし/下書き/決まった、メロ：あり/なし）。「どこが空いているか」が一目で分かる＝細切れ時間で「次の一手」を選べる。
- 詞がなくてメロだけあるセクションは、空白でなく「音数の器」（♪6・7・6・8 のような行ごとの音数）を薄く表示する。俯瞰していて「ここに7音の言葉が要るのか」と出先で考えられる。これが曲先→詞の入口になる。
- セクションを押す→S2へ。長押し（または端のつまみ）で並べ替え・複製・追加＝フォーム構成の編集もここでやる（構成は「全体を見ながら」しか判断できないから）。
- 行を二度押しでその1行だけその場で直せる（インライン編集）。それ以上はS2へ。

### (b) 表示の重ね着（トグル群・既定は全部オフ）
- 母音表示：各行の下に母音列を小さく敷く（「会いたくて」→ a i a u e）。韻＝母音の連なりを目で確かめる用。同じ母音並びで終わる行同士を淡い同色の下線で結ぶ（自動の指摘はここまで。良し悪しは言わない）。
- 音数表示：行ごとのモーラ数。メロがある行は「詞の音数/音符数」（例 7/8）を併記し、合わない行にだけ小さな点を打つ（赤にしない）。
- 繰り返し表示：1番サビと2番サビ等で同一の行を淡く畳み「（1番と同じ）」と示す／逆に「番の間で変えた行」だけ色を付ける。繰り返しの設計（どこを揃え、どこを変えるか）を眺めるための表示。
- どのトグルも「素の歌詞の読み心地」を汚さないことを最優先。飾りは足すのでなく重ねる。

### (c) 番の見比べ（表示切り替え）
曲順表示と切り替えで、同じ役割のセクションを揃えて並べる表示を持つ。
- 机（横幅あり）：`1番Aメロ | 2番Aメロ` ……列で並置。行が対応する位置に揃う。
- スマホ（幅なし）：1番Aメロの行と2番Aメロの行を交互に重ねる（1行ずつ対にして縦積み）。
- 用途：2番の作詞は「1番との対」で書く作業なので、この表示が実質の下書き台になる。ここから該当セクションのS2へも跳べる。

### (d) 通しで確かめる（S8はこの画面のモード）
- 「通しで読む」：ヘッダーもバッジも消えた素の全文。音読・黙読用。
- メロがある区間は通し再生（ラ音や合成音でよい）に合わせて現在行が送られる。歌いながら詰まる場所を探す用。ワンタップで録音メモ（後で聞き直す自分の歌）。

### (e) 書き出し
- 全文テキスト（歌詞カード形式）、セクション別の譜割り一覧（行・音数・伸ばす音の母音）を書き出せる。机のDAW作業への橋。画面ではなく機能としてS1に置く。

## 3. S2 セクション作業画面の設計

原則：詞先/曲先を選ばせない。開いた瞬間、そのセクションの「今あるもの」に合わせて姿が決まる。

### 姿A：メロあり・詞なし（曲先の現場）＝「当てはめ」の形
```
+----------------------------------+
| ← 1番サビ   [2番Aメロ]   1番B →  ←前後へ横スワイプ |
|  …前のセクション最後の行（薄く）… ←文脈。言葉の運びを切らない |
+----------------------------------+
| ♪ [た][ち][ど][ま][る~~ ][ま][ち]| ←音符のマス目：幅=長さ、~~=伸ばす音、
|    ／  ＼ ＿ ／  ＿    ＼  ＿    |   線=音の上がり下がり（輪郭だけ）
|   （2行目のマス目…）             |
+----------------------------------+
| 下書き：たちどまる まちかどで__  | ←打った言葉が上のマス目に流し込まれる
| 音数 7/7 ✓   伸ばす音: 「る」(u) | ←静かな印：伸ばす音に置いた母音を表示
+----------------------------------+
| [候補と履歴] [道具箱] [▶ 再生]   |
+----------------------------------+
```
- メロは楽譜でなく「音符のマス目＋輪郭線」。正確な記譜はDAWの仕事。ここに要るのは音数・長さ・伸ばす音・上がり下がりだけ（スマホで読めることが優先）。
- 言葉を打つとマス目に音節が流れ、余り/不足が一目で分かる。伸ばす音のマスに来た母音を脇に表示（aやoは伸びやすい等の判断は使い手がする。ツールは事実だけ示す）。
- 言葉の抑揚とメロの上下が逆行する箇所は、任意オンで小さな印。警告ではなく「見どころ」の印。

### 姿B：詞なし・メロなし、または詞先で書き始める＝「書く」形
- 素直なテキストエディタ。行ごとに音数が右端に静かに付く（5・7・6…）。
- ここで書いた行の音数の並びが、そのまま「メロを起こすときの器」としてセクションに残る（詞先→曲の橋。後日メロを付けたら姿Cに育つ）。
- 覚え書き（S5）のそのセクションの一行メモを上部に薄く常掲できる（「ここは感情が反転する場所」等）。

### 姿C：詞もメロもある＝「推敲」の形
- 姿Aと同じ構図で、本文が確定稿として乗っている。行を選ぶと道具箱・候補が使える。再生と録音メモがここでも使える。

### 共通の付属品
- 前後スワイプで隣のセクションへ（往復作業はセクション間を渡り歩く作業なので、S1に戻らず横に動ける）。
- 「候補と履歴」（S7）：別案を並べ、行単位で本文に取り込む。機械の提案もここに入る。本文は常に人間の手でしか変わらない。
- 「道具箱」（S6）：選択した語から母音一致（韻）・類語を引く。結果は候補行としてS7に置ける。

## 4. 画面同士の関係と行き来（往復作業の回し方）

基本の軌道：S4（曲を開く）→ S1（全体を眺め、次の一手を決める）→ S2（1セクションに潜る）→ 横スワイプで隣へ、または S1 に浮上して眺め直す → また潜る。

詞先⇄曲先の反転はこう吸収する：
- 「Aメロにメロを書いた→詞を当てる」＝S1でそのセクションに「メロ:有 詞:なし」のバッジと音数の器が見える→押すと姿A（当てはめ）で開く。
- 「その詞に合わせて2番を作詞」＝S1を番の見比べ表示に切り替え、1番を横目に2番を書く（軽い直しならその場、腰を据えるならS2の姿B）。
- 「サビも作詞→その詞からメロを起こす」＝姿Bで書く。行ごとの音数の並びが器として残り、DAWでメロを付けて戻ってくると姿Cで突き合わせられる。
- つまり使い手は一度も「モードの切り替え」をしない。方向の反転は、セクションの状態が勝手に表してくれる。

全体と局所のつなぎ：
- スマホ＝時間差の並置。S1とS2はスタックで行き来し、S1は離脱時のスクロール位置を必ず保つ（俯瞰に戻るたび頭から、を絶対にやらない）。フォーム地図（A B サ…の帯）はS2にも極小で出し、現在地と全体の対応を常に見せる。
- 机＝空間の並置。左にS1（全体）、右にS2（局所）を常時2枚並べる。左で押した区画が右に出る。左は読みながら、右で書く。これが机の基本姿勢。
- ネタ帳（S3）はどの画面からも1操作で開く（+ボタン）。断片は後からS1のセクションへ「送る」（送るとS7の候補に入る）。
- 覚え書き（S5）と道具箱（S6）は画面遷移でなく、上/横から被さるシート。閉じれば元の場所にそのままいる。

## 5. スマホ／机の出し分け

方針：別アプリ・別画面にしない。同じ8画面の「並べ方と厚み」を変える。理由：往復作業の途中の頭の中は連続している。出先で眺めた続きを机で書くのだから、場所ごとに画面の概念が変わると往復が切れる。

スマホ（細切れ時間）で厚くするもの：
- ネタ帳への最短の書き付け（起動→2タップ以内。音声メモ含む）。
- S1の「読む」体験。通し読み・母音/音数の重ね表示・状態バッジ。信号待ちの30秒で「次の一手」を見つけられること。
- S2の小さな一手：1行の当てはめ、1行の言い換え、候補への○×。マス目編集は「読む＋言葉を流し込む」まで（メロ自体の編集はしない）。
- 通し再生を聞きながら口ずさむ・録音メモ。

机（DAW併用・がっつり）で厚くするもの：
- S1＋S2の2枚並べ（全体を見ながら局所を書く）。
- 番の見比べの列表示。
- 音符のマス目の編集・取り込み（DAWからメロのリズム/音数を持ち込む、譜割り一覧を書き出してDAWへ戻す＝往復の橋）。
- 候補の大量見比べ（S7を広げて3案並置）、長時間の推敲。

同じ画面か別か、の答え：全部「同じ画面の別の並び」。唯一の非対称は「メロのマス目の編集は机のみ・スマホは閲覧と流し込みのみ」。

## 6. 優先順位（作る順）

**第1段：S1 歌詞全体ビュー（＋最小のS4曲一覧）**
理由：マスト要件であり、全画面のハブであり、そして単体でも価値が立つ（テキストだけでも「曲全体の詞を眺める場所」は今日から役に立つ）。ここの読み心地が悪ければ他の何を作っても使われない。フォームラベル・状態バッジ・インライン1行編集・通し読みまでを第1段に含める。母音/音数トグルは第1段の後半。

**第2段：S2 セクション作業画面（姿B→姿Aの順）**
理由：往復のもう片輪。先に姿B（書く形＝行ごと音数）を出すのは、メロデータの取り込みという重い橋を待たずに価値が出るから。音符のマス目（姿A）はその次。

**第3段：S3 ネタ帳＋どこからでも書き付け**
理由：スマホ原点の場面（出先の断片）を拾う。独立性が高く、いつ足しても壊れない。

**第4段：S7 候補と履歴 → S6 道具箱 → S5 覚え書き → S8 通し再生/録音**
理由：いずれも主画面に寄生する「従」。土台の2画面が回り始めてから足すほうが、置き場所を誤らない。機械の候補生成を繋ぐのはS7ができてから（本文を勝手に触らない原則の受け皿が先）。

## 7. 設計判断とトレードオフ（迷った点と決め）

1. **詞先/曲先を別画面（またはモード切替）にするか → しない。** 反転はセクション単位で頻発する。切替操作を課すと往復のたびに小さな税を払わせる。「状態が姿を決める」一画面方式は実装は重いが、使い手の頭からモードという概念を消せる。ここが勝ち筋なので重さを呑む。
2. **全体ビューを編集可能にするか → 「1行の直しだけ」可能にする折衷。** 読む姿勢を既定にし、二度押しで1行だけ直せる。構造の作業は必ずS2。境界線は「1行」。
3. **メロディの表現をどこまで持つか → 楽譜は持たない。音数・長さ・伸ばす音・上がり下がりの輪郭だけ。** 記譜はDAWがやっている。作詞に効くのは「何音か・どこが伸びるか・上がるか下がるか」。この抽象ならスマホ幅でも読める。忠実度を捨てて携帯性と読みやすさを取った。
4. **韻・音数・アクセントの指摘をどう出すか → 既定オフ・任意オン・印だけ・点数なし。** 字余りも逆行アクセントも狙う表現があり得る。ツールが正誤を宣告した瞬間、道具が審判になる。事実（母音列・音数・伸ばす音の母音）だけ静かに見せ、判断は人間に残す。赤色は使わない。
5. **韻・類語検索を独立画面にするか → しない（選択起点のパネル）。** 辞書画面へ「行って帰る」形は文脈を捨てさせる。検索を画面でなく動作にした。
6. **機械の候補の置き場 → 本文と物理的に別の引き出し（S7）に隔離。** 「候補まで機械・仕上げは人間」を画面構造で強制する。取り込みは必ず人間の一手（行単位で拾う）を経る。
7. **番の見比べを独立画面にするか → S1の表示切り替えにする。** 曲順の俯瞰と番の見比べは「同じ全文を別の軸で並べただけ」。画面を分けると「帰る場所」が2つに割れる。ハブは一つに保つ。
8. **履歴と候補を分けるか → 一つの引き出しの2タブに統合。** どちらも「本文の外にある別テキストを見比べて拾う」同じ動作。時間軸（履歴）と並列軸（候補）の違いはタブで足りる。

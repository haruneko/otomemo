### R-2. `run_frontend` が語単位の対応とかな読みを返す

```
>>> pyopenjtalk.run_frontend('今日の予定を紙に書く')
今日   read=キョウ  pron=キョー  mora_size=2  acc=1
の     read=ノ      pron=ノ      mora_size=1
予定   read=ヨテイ  pron=ヨテー  mora_size=3  acc=0
を     read=ヲ      pron=ヲ      mora_size=1
紙     read=カミ    pron=カミ    mora_size=2  acc=2
に     read=ニ      pron=ニ      mora_size=1
書く   read=カク    pron=カク    mora_size=2  acc=1
```

- **表層文字列（string）と mora_size で「語区間↔モーラ区間」が機械生成できる**。
- **read はかな表記寄り**（ヨテイ・キョウ）、pron は発音（ヨテー・キョー）。モーラ行に出すかな文字は **read をモーラ分割**して得る（「よてい」が正しく出る）。助詞「へ」も read=ヘ（pron=エ）で表記寄り。
- 他の例: 「水を飲み干してから」→ 水(ミズ2)/を(1)/飲み干し(ノミホシ4)/て(1)/から(2)＝計10。「にわへ」→ に(1)/わ(1)/へ(1) と誤分割（誤読の正体が語割りにも見える）。「庭へ」→ 庭(ニワ2)/へ(1)。全角空白は読み「、」mora_size=0 の形態素になる（対応からは飛ばす）。

### R-3. read のモーラ分割数 = mora_size の検査

小書き文字（ゃゅょ等）を前のかなに付ける単純分割で、11文（飲み干し・言う・学校へ行って・ハート・10時・コーヒー・っていうか・雨の日は・朝早く…・朝起きて…・シャッター）の全形態素で **分割数＝mora_size に不一致なし**。無声化（起きて→o kI te）も read 側はキのまま。→ モーラかなの出所として成立。

### R-4. 正規化の罠（表層連結 ≠ 入力になる場合がある）

```
'きょうのよていを かみにかく'（半角空白）→ 連結 'きょうのよていを　かみにかく'（全角化）＝入力と不一致
'10時に着く' → 連結 '十時に着く'＝入力と不一致
'朝早く起きて　窓を開ける'（全角空白）→ 連結一致
```

→ span の文字位置は**入力文字列でなく形態素表層の連結に対して**張る。bake は「連結==feed」を検査し、違反句は焼けない（モックのデータは全角空白のみ・数字なしに限定して回避）。

## 1. 歌詞の2層

### 1-1. 原本は「表記」、読みは導かれる

- **原本＝表記**（漢字仮名交じり。かなで書きたい句ならかな、それも表記）。
- **導かれるもの＝読み**（モーラ列・アクセントの高低・アクセント句切れ）。accent.py が表記から読み取る。
- 読み取りは機械の推定であって確定ではない（「にわへ」→高高低の誤り・実測）。句に**「読み取り用の表記」**（任意・既定は表記そのもの）を持たせる。v7が内部に隠し持っていた `accent.src` を画面に出し、人が書ける欄に格上げする。
- 句のデータ: **表記（人が書く・原本）→ 読み取り用の表記（任意）→ 読み（機械: モーラ・高低・句切れ）→ 音符への割付（モーラi↔音符i）**。人が書くのは最初の2つだけ。モーラ列を直接書く場は作らない。
- v8では曲Aの句の表記を漢字仮名交じりに置き直す（「朝起きて　窓を開ける」「水を飲んでから」等・全句 accent.py 再実走で焼く）。2層の見本になる（表記=漢字交じり・モーラ行=かな）と同時に、素の面が「読める」ようになる（§2の1へ効く）。かな表記の句も1句残す（枚9の伏線）。

### 1-2. 表記とモーラの対応（spans）＝語単位・生成方法つき

- **対応の単位は語（pyopenjtalk の形態素）**。「表記の区間（形態素の表層文字列）↔ モーラ区間（mora_size の累積）」。文字単位は不採用: 「今日」→キョ・ウのどちらが「今」か機械に根拠が無く、熟字訓で定義が閉じない（批判1・実測§R-2）。語単位なら多文字↔多モーラの区間対応として常に閉じる。
- **生成方法＝`run_frontend`**（§R-2）。bake が feed（= 読み取り用の表記 || 表記）に対して走らせ、`{表層文字列, かな読み(read), モーラ範囲}` の列として焼く。
- **モーラ行のかな＝read のモーラ分割**（カタカナ→ひらがな変換）。「よてい」「きょう」が正しく出る（§R-2・R-3）。accent.py のローマ字からの逆変換はしない。
- **bake の検査（違反したらその句は焼けない）**: (a) Σmora_size == accent.py の mora_total (b) 各形態素で read の分割数 == mora_size (c) 表層連結 == feed（§R-4）。モックのデータは全角空白のみ・数字なしでこれを満たす。道具の実装時の退行規則（違反句は対応なしで光りが出ないだけ・モーラかなは pron から機械変換）は設計への注記であり絵にはしない。
- **読み取り用の表記がある句**: spans は feed（=読み取り用の表記）に張る。対応の光りは読み取り用の表記の欄で出す。**表記の欄は光らせない**——別文字列（「にわへ」と「庭へ」）の間の対応を取る経路は無い（実測に基づく制限。画面にもその旨の一言を出す）。
- 見せ方: 範囲の編集画面で、**タップした語の該当モーラ区画が薄く光る**（1状態を枚5に描く。§6）。

### 1-3. 縦揃え（裁定11）との関係

- 裁定11はモーラ層の裁定。モーラ区画の横位置・幅は**音符の時間位置から計算**して揃え続ける（1px以内・検証8）。この定義は帯が描かれているかに依存しない（§3-1）。
- **表記の行は揃えの対象外**。漢字1文字が複数モーラになる以上、文字と音符の1対1の揃えは成立しない。表記は普通のテキスト行として句単位で置く。裁定11の適用範囲の整理として§9で仰ぐ。

### 1-4. 食い違い（読みのモーラ数 ≠ 音符数）の見せ方

- **モーラ数 < 音符数**: 余った音符は空き（v7の空き枠表現）。行に事実チップ「あとN音」。
- **モーラ数 > 音符数**: 余ったモーラは「音符なしのモーラ」としてモーラ行の末尾に灰色で出す。行に事実チップ「字余りN」。
- **音数の食い違いはチップ止まりとし、行末ドットには通さない**（改訂: 批判4）。v7の行末ドットの黄はアクセント系で、裁定前に意味を黙って広げない。音数を行末ドットにも出す案は枚2「印の決まり」に載せて裁定対象にする（§5裁定待ち2に追記）。
- 機械は詰めない・削らない・止めない。直すのは人（表記を変える／メロを変える／割付をずらす——最後の1つは§10で聞く）。
- 割付は恒等対応（モーラi↔音符i・v7踏襲）。句の途中を直すと後ろの割付がずれる限界は枚8にそのまま出し、割付を手でずらす操作を入れるかは絵を添えて聞く（§10）。

## 3. 密度への解

### 3-1. パーツ選択と3切替の関係＝別の軸・衝突規則（改訂: 批判5）

- **3切替（素／音韻／イントネーション）＝モーラ層に何を注記するか**の排他選択（何を調べるか）。
- **パーツ選択＝行を構成する要素を出すか**の独立オン／オフ（何を出すか）。項目は6つ: メロ帯／空きマスの列／小節番号／意味メモ／予定チップ／印ドット。ヘッダの「表示」ボタン1個→小さなシート→6項目と「既定に戻す」。選択は切替をまたいで記憶。
- **衝突規則**: 切替が定義上必要とする層（モーラ行・高低線・母音の段・韻の下線）はその切替が出す。**メロ帯はパーツ選択に従い、切替は強制しない**。
- **切替オン×帯オフの姿は定義済み**: モーラ区画の横位置・幅は帯の描画とは独立に**音符の時間位置から計算**する（裁定11の「音符矩形の時間位置に一致」を「描画中の矩形」でなく「音符の時間データ」への揃えと読む。v7枚2のモーラ行はすでに時間揃えで置かれており、帯なし版としてそのまま成立する）。批判5の示した2案（帯を強制オン／検証を帯表示の枚に限定）はどちらも採らない——前者は切替のたびに密度が戻り、後者は検証から枚を黙って外す形になるため。揃えの期待値を時間から計算すれば全枚を検証対象にできる（§8-8）。
- **枚2・3の描画状態を指定**: 態A（既定・帯なし）＋切替の層。B担当は枚ごとに判断しない。
- パーツ選択が効くのは通しの面だけ。範囲の編集画面は開いた範囲の作業場なので常に全部出す。

- 枚間で一致すべきもの（割当文面・パーツ宣言・印の使用案・数の数え方）は**計画本文で確定し、検証は本文との文字列・宣言照合**にする（批判3・6・11・12の再発防止）。
- 新しい表示データはすべて工程0の焼き込み経由。バッジ・チップ・音の枠の数字も機械算出（批判13）。
- 実例は accent.py／run_frontend を走らせて確定してから枚に割る（批判8）。
- 主従・優劣の格付けは文書でせず、絵にして仰ぐ（批判9）。決められないもの（読みの受け止め・割付ずらし・既定の姿）は裁定待ちに分類。

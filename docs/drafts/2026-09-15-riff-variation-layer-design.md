# 繰り返しに変奏の層を足す — 設計案（ベースの体・ギターのリフ）

起草日: 2026-09-15。対象＝真因調査 `../research/2026-09-15-anchor-rigidity-guitar-motion-rootcause.md` の案1（オーナー裁定 2026-09-15＝採用・出し方は「候補を段で」）。**コードは変えていません**。並行して実装中の案2（錨＝変わり目だけ必須）・案6（刻みの音価をつまみに）と両立する形に限定し、案4（体を規則生成へ作り替え）は範囲外＝ただし将来そのまま使い回せる形にしています。

## 0. 要約（15行）

1. **何を**：2小節の表（ベースの文法3型・ギターの文法3型）を貼る**2回目以降の反復単位**に、古典的なモチーフ変換（`2026-08-02-riff-structure-and-variation.md` B-1）を**決定的に**当てる「変奏の層」を足します。
2. **どこで**：表を敷いたあと・錨（キックのロック）を掛ける**前**の1段。music-core に楽器非依存の純関数として置き、ベースの錨経路とギターのリフ経路の両方が同じ関数を呼びます。
3. **何を動かすか**：動かすのは**答句（answer／pickup／blue／climb の単音）だけ**。頭（anchor）・ペダル・刻み・リズムの格子は変えません＝「軸を1本だけ壊す」（B-6）。
4. **3候補**：変奏量 **なし／中／多め** を3件並べます。**なし＝従来と 1bit 同じ**。中＝2回目以降の答句を**リフ語彙の階段で1段ずらして応える（ゼクエンツ）**だけ。多め＝それに加えて、途中の反復で**答句を断片化して間を作り**、最後の反復で**答句を1拍ぶん前へ広げ**、装飾（ギター＝ゴーストの付け外し／ベース＝直前ペダルのオクターブ）を足します。多めは中を含みます（入れ子）。
5. **順序**：変奏 → 錨 → 実音化 → 既存の後処理 → 和音追従 → **最終出力で契約を実測**。変奏は**錨の候補地（キックの打点）に手を出さない**（保護する打点を入力に取る）ので、案2 の契約も和音追従のガードも黙って破れません。逆に**ガードが変奏を打ち消して従来と同じ音になった時は数えて告げます**（診断・ゲートにしない）。
6. **つまみ**：`riffVariation`（0／0.5／1）＋`riffVariationSteps:true`（3段を items で返す）。4口すべて（HTTP・MCP・`/gen/section`・web）。保存＝content の印（`guitarRiff.variation`／ベース `bassRiff.variation`）だけ・音符は毎回生成。
7. **検証**：データ一致は主張しません。既定 bit 一致・決定論・不変条件（非対象セル無傷・語彙内・錨の契約）・摂動テスト（段を振ると最終出力が変わる）・変異検査（層を恒等にすると摂動テストが落ちる 等）。
8. **案4 との関係**：層の入力は「役割つきオンセット列を反復単位で束ねたもの」であって表ではないので、規則生成が同じ形を出せばそのまま使えます。
9. **オーナーに聞くこと＝1件**（§12）：多めで**リズムも動かすか**（16分のずらし）。それ以外の「中の中身」「装飾の要否」は文字で決めず、実装後の**試聴帳で耳で決める**項目として仮の値を置きます。
10. **実装＝スライス6本**（§11）。最初の一手＝music-core に層の純関数を**赤テストから**（恒等・決定論・入れ子・非対象無傷・語彙内）。

## 2. 変奏の層＝独立した変換段

### 2-1. 置き場と入出力

**置き場＝`packages/music-core/src/riffVariation.ts`**（純関数・RNG/hash/Date 不使用）。api のベース錨経路（`generate.ts` の `anchorPath`）とギター経路（`genChordPattern` の `gtrWins`）が同じ関数を呼びます。web は呼びません（ギターは変奏済みの hits が content に載る・音高だけ web が出す＝現行分業のまま）。

入力は**表ではなく「役割つきオンセット列を反復単位（2小節＝32 step）で束ねたもの」**です。ベースの `BassGrammarOnset`（step/kind/deg トークン/anchor/role）もギターの `GtrCell`（step/kind/deg 半音/anchor/role/voicing）も、この形へ機械的に写せます。

```ts
// 役割つきオンセット（楽器非依存。deg は半音・ベースはトークン→半音へ写して渡す）
interface RiffCell { step: number /* 反復単位内 0..31 */; kind: "accent"|"note"|"ghost"|"dead"; deg: number; anchor: boolean; role: string; voicing?: "mono"|"power"|"power8" }
interface RiffTile { index: number /* 0 = 提示 */; cells: RiffCell[]; last: boolean }
interface RiffVariationOpts {
  level: 0 | 0.5 | 1;                 // なし／中／多め
  seed: number;                       // 方向の偶奇と回転にだけ使う（§8）
  protectedSteps: ReadonlySet<number>;// 手を出さない global step（錨の候補地＝キック）
  instrument: "bass" | "guitar";      // 装飾レバーの中身が違う（§3）
  ladder?: readonly number[];         // 既定＝リフ語彙 [0,3,5,6,7,10,12]
}
interface RiffVariationReport { tiles: { index: number; levers: string[]; changed: number }[] }
function varyRiffTiles(tiles: readonly RiffTile[], opts): { tiles: RiffTile[]; report: RiffVariationReport }
```

出力は同じ形（セルの追加・削除・deg／kind／role／voicing の書き換えのみ）。**入力は破壊しません**。

### 2-2. 何が「反復単位」か

文法は2小節（32 step）なので、反復単位＝**2小節の貼り付け1枚**（`buildGuitarSkeleton` の tile・ベースは `bar % 2` の交替）。セクション長が2小節の倍数でない時は最後の単位が欠けたまま（存在するセルだけが対象）。**index 0（提示）は決して触りません**＝「元がどう聴こえるか」を必ず先に出す（B-2 の developing variation＝反復が一貫性・変奏が単調の回避）。

## 3. 変換の語彙（B-1 から取る・発明しない）

| B-1 の変換 | 使うか | 当てる先 | 中身（仮） |
|---|---|---|---|
| **移調／ゼクエンツ（調内）** | ◎ 中の主役 | 答句の各セル | リフ語彙の階段 `[R, b3, 4, b5, 5, b7, 8]`＝半音 `[0,3,5,6,7,10,12]` 上で**1段**上か下へ（端で止まる）。方向＝`(seed + tile.index)` の偶奇。全セルが端で動けなかった時だけ源流 `diverge` の reselect（`[7,10,12,5]` を回す）で**必ず1音は変える** |
| **断片化** | ◎ 多め | 答句 | 答句の**頭1セルだけ残し、残りを休符に**（間を作る）。ギターは同じ小節後半の ghost/dead も落とす（本当の空白にする） |
| **拡大（答句を前へ広げる）** | ◎ 多め・最後の単位 | 答句の直前1拍のペダル／刻みセル（anchor でない・保護されていないもの） | 役割を answer に変え、deg を階段で答句の頭へ向かって1段ずつ近づける。ギターは voicing を mono に（単音の動く音が増える） |
| **装飾／簡約** | ◎ 多め | 答句の小節 | **楽器で中身が違う**：ギター＝答句の小節内の ghost/dead を外し、答句の頭の1 step 前が空いていれば ghost を1つ足す（vel 46 の「息」）。ベース＝ghost は無音なので使えず、代わりに**答句直前のペダル1セルをオクターブ上へ**（源流 `diverge` low band＝リズム保持×ピッチ差し替え） |
| リズム保持×ピッチ差し替え（源流 `diverge`） | ○ 部品 | 上の2行の中 | `octave`／`reselect` のレバーを**そのまま部品として取り込む**（RNG 無し・単体は py-parity で一致が取れる）。層そのものは源流に無いので層としての一致は主張しない |
| 反行 | △ 用意するが既定の段には入れない | 答句 | 答句の頭を軸に上下を反転し階段の最寄りへ。**less is more**（源流の学び）＝盛らない。試聴帳で「多めに足すか」を耳で決める候補 |
| 逆行／逆行反行 | × | — | 3音の答句では反行と区別がつかない |
| 拡大／縮小（音価） | × | — | リズムの格子を変える＝リフの同一性の半分（A-5）を壊す |
| ピッチ保持×リズム差し替え（16分のずらし） | ？ §12 | 答句 | 源流 HANDOFF の残課題「変位（ずらし）」。キックの契約・パームミュートの印象と絡むので**オーナーに範囲を聞く** |

**答句の定義**＝反復単位の中で `anchor:false` かつ `role ∈ {pickup, answer, blue, climb}` のセル（ギターは `voicing:"mono"` も条件）。`octave`／`root`（octave_call_response）は**知識の芯（レジスタ往復）**なので対象外。`head`／`pedal`／`chug`／`chord`／`dead` は同一性の錨（リズム＋ルートペダル）なので**触らない**（拡大の対象になる直前1拍のペダルだけ例外）。gallop の step 31（b2 の導音・anchor:true）は源流どおり不可侵。

## 4. 3段で何が起きるか

反復単位 t（0＝提示）ごとの当て方（**仮**・試聴帳で耳が決める＝§11 S5）。多めは中を**含む**（同じ場所には同じ変換＋追加だけ）＝段が階段として聴こえるようにするため（B-6 3「距離の階段」・源流 `diverge` の入れ子部分集合と同じ発想）。

| 反復単位 | なし（0） | 中（0.5） | 多め（1） |
|---|---|---|---|
| t=0（提示） | 素 | 素 | 素 |
| 奇数・最後でない | 素 | ゼクエンツ | ゼクエンツ＋装飾 |
| 偶数≥2・最後でない | 素 | 素 | 断片化 |
| 最後（t≥1） | 素 | ゼクエンツ | ゼクエンツ＋拡大＋装飾（句末で一番大きく） |

セクション長ごとの実際：

| 小節数 | 単位 | 中 | 多め |
|---|---|---|---|
| 4（試聴帳の条件） | 2 | t1＝ゼクエンツ | t1＝ゼクエンツ＋拡大＋装飾 |
| 8 | 4 | t1 ゼクエンツ（上）・t2 素・t3 ゼクエンツ（下） | t1 ゼクエンツ＋装飾・t2 断片化・t3 ゼクエンツ＋拡大＋装飾 |
| 2 | 1 | 変奏の余地なし（`meta.warnings` で告げる） | 同左 |
| 6 | 3 | t1 ゼクエンツ・t2 ゼクエンツ | t1 ゼクエンツ＋装飾・t2 ゼクエンツ＋拡大＋装飾 |

### 4-1. ベース（体＝`pedal_answer`・4小節・王道進行）の例

- **なし**：bar1 ルートペダル＋pickup 5 ／ bar2 ペダル＋答句 b7→5→4 ／ bar3-4＝bar1-2 と同じ相対形（従来）。
- **中**：bar3-4 の答句が階段で1段ずれる＝ b7→5→4 が **8→b7→5**（上）または **5→b5→b3**（下・seed の偶奇）。pickup 5 も同じ向きに1段（b7 または b5）。ペダル・頭・リズムは同じ。
- **多め**：中に加え、bar4 の答句の直前1拍（step 20・22 のペダル）が answer になり階段で答句の頭へ近づく（例 R→b3→4 と登って 8→b7→5 へ）、bar4 の答句直前のペダル1つがオクターブ上（レジスタの息）。**キックの打点に当たるセルは対象外**（§6）。

（ベースの ghost は無音扱い＝装飾レバーはオクターブ側だけ。gallop_pedal は答句が `answer/blue`（step 14-15）と `climb`（30-31・31 は anchor）なので、動くのは 14・15・30 の3セル＋拡大分。octave_call_response は `answer/blue`（12・22・28）のみ＝オクターブ往復は無傷。）

### 4-2. ギター（`power_chug`・4小節・ロック進行）の例

- **なし**：各小節が同じパワーコードの刻み（コード追従が deg を捨てる＝真因 §3-3 2）、動く音は pickup 1＋answer 3 の4音／2小節（従来）。
- **中**：bar3-4 の答句（step 15 pickup 5・26 b7・28 5・30 b3）が階段で1段ずれる。強拍（28）はコード追従で最寄りのコードトーンに着地、弱拍は隣の確定音の ±2 のスケール音＝**音高の変化は和音追従に丸められる範囲で出る**（真因 §3-1 の数字どおり小さい）。
- **多め**：中に加え、bar4 の答句直前1拍の刻み（step 20・22 の power）が **mono の answer** になる＝**動く音が2小節4音→6音**、bar4 の ghost/dead（27）が外れ step 25 に ghost が1つ入る＝刻みの一様さが1か所崩れる。**ロック中はキックの打点に当たる刻みは対象外**（ロックが (b) で power8 に戻すのを避ける）。

ギターは和音追従が音高差を丸めるので、**中の可聴差は「休符・ゴースト・単音化」を持つ多めより小さい**見込みです。これは欠陥ではなく「段の間隔」の話なので、試聴帳で中の中身（ゼクエンツかレジスタ上げか）を耳で選びます（§11 S5）。

## 5. どこで変奏するか（位置の規則）

- **反復単位＝2小節の貼り付け**。1枚目は必ず素（§2-2）。
- **小節内の位置＝答句の側（句の終わり）**。提示（bar1 の頭〜ペダル）は同一性の錨として保持。拡大だけが「答句の直前1拍」へ食い込む。
- **セクションの形＝最後の反復単位が一番大きい**（句末・次のセクションへ流れ込む）。途中の偶数単位で断片化＝**間**（源流ブレストの「同期100%・補完0%」への補完）。AABA のような曲レベルの形は**セクション単位の生成では扱わない**（セクション役割 `frame.section.role` を読んで変える案は、曲レベルの `cues` と同じ棚＝将来）。
- **フィルとの関係**：`fill`／`cues.fill` が差し替える小節は後段でそのまま差し替わる（変奏より上位の道具＝既存どおり）。錨の契約と同じく「破れた事実を数えて告げる」流儀（design (k-3)）。

## 6. 錨・和音追従との順序＝最終出力で不変条件を守る

このアークで実際に起きた事故＝「後段が契約を黙って破る」（design (k-3)・2026-09-10 監査）。変奏の層は**前段**に置き、契約の実測は**最終出力**で行います。

### 6-1. 段の並び

**ベース（`anchorPath`）**
```
体（文法の2小節）を反復単位に束ねる
→ ① 変奏の層 varyRiffTiles（保護する打点＝キック step）   ← 本設計
→ ② deg → 実音（既存 generate.ts:1485・窓 [33,48]）
→ ③ 錨 lockBassRootsToSheet（案2 の新契約＝変わり目のキックはルート・滞在中は構成音も可）
→ ④ 実音化（音価・レガート）
→ ⑤ approach（錨を避ける・既存）／snareGap／骨格 E／fill F／land G
→ ⑥ chordFollow H（強拍＝コードトーン・弱拍＝スケール・錨と骨格音は触らない・既存）
→ ⑦ 契約の実測（キック step の錨＝既存の台帳）＋ 打ち消しの実測（§6-3・新規）
```
**ギター（`gtrWins`）**
```
buildGuitarSkeleton（文法をタイル張り）
→ ① 変奏の層 varyRiffTiles（保護する打点＝ロック中のキック step）  ← 本設計
→ ② lockGuitarChugToSheet（anchorLock 時のみ・既存）
→ ③ gtrOnsetsToHits → content（相対形・hits に deg/role が載る）
→ ④ web／api 検算 realizeGuitarRiff → assignGuitarPitches（強拍＝コードトーン・弱拍＝隣の確定音の ±2・既存）
→ ⑤ 契約の実測（キック step の POWER 形・既存）＋ 打ち消しの実測（§6-3）＋ fretboardGate（既存）
```

### 6-2. なぜこの順序で契約が守れるか

- **錨の契約（案2）**：変奏は錨の**前**に走るので、錨は変奏後の体に対して従来どおり (a)/(b)/(c) を判定します＝契約は**構造上**保たれます（byConstruction）。加えて**保護する打点**（`protectedSteps`＝キックの step）を入力に取り、変奏は**その step のセルを対象にしない・そこへセルを増やさない・そこのセルを消さない**。理由は契約のためではなく、**「変奏したのに錨が (b) で元へ戻して黙って無駄になる」を避ける**ため（源流実測＝ロックが発散の余地を半分以下に削る・真因 §2-5）。
  - v1 の保護集合＝**全キック step**（ベース・ギターとも）。案2 が着地したら、ベースは**変わり目のキックだけ**に狭められます（滞在中のキックは構成音が生き残る）＝案2 の「変わり目の読み手」を変奏の入力に渡すだけ・層の中身は変えない（§10）。**案2 のコードに依存しないので、着地の前後どちらでも動きます**。
- **和音追従のガード**：ベース chordFollow（⑥）とギター `assignGuitarPitches`（④）は変奏の**後**で、リズムは動かさず音高だけを写すので、①②が黙って破れることはありません＝**ガードが勝つ**。変奏は語彙内（階段）の deg しか出さないので、ガードが写す先が空になることもありません。
- **既存の後処理**：approach は錨を避ける（既存）。fill は小節を丸ごと差し替える（上位の道具）。**どれも変奏の層を知らない**＝結線の変更なし。

### 6-3. 打ち消しの実測（新規・診断）

ガードが変奏を丸ごと戻すことは起こり得ます（例：ゼクエンツ先が強拍で、コード追従が元と同じコードトーンへ写す）。これを黙って通さないため、**`level>0` の生成では同じ入力で `level=0` も生成し、最終出力（ベース＝notes／ギター＝hits＋検算の実音）が完全一致なら `meta.warnings` に「変奏（中）は錨・和音追従に打ち消され、従来と同じ音になりました」を載せます**。段で出す時は3件を生成するので追加コストはありません。**ゲートにはしません**（形の要求を合格条件にしない）。

## 7. 3候補の出し方・つまみ・保存形・到達口

### 7-1. つまみ

| 名前 | 型 | 意味 |
|---|---|---|
| `riffVariation` | `0 \| 0.5 \| 1`（それ以外は最寄りへ丸めて告げる） | 変奏量。未指定＝0＝**従来と 1bit 同じ**。`anchorLock`（ベース）／`guitarRiff`（ギター）が**立った時だけ**効く。立っていない時は「錨／リフ文法を選んだ時だけ効きます（従来どおり生成しました）」と告げる（既存の `anchorLock` 通知と同じ流儀） |
| `riffVariationSteps` | `true` | **段で出す**＝なし／中／多めの3件を `items` に並べる（label＝「変奏なし（従来）」「変奏 中」「変奏 多め」）。`riffVariation` と同時なら steps が勝ち告げる |

既存の `variety`（型辞書の候補数）は**流用しません**＝リフ／隙間刺しが立った時に `variety` を捨てて告げる現行仕様（design (k-5)）はそのまま。段の候補は「別々の型」ではなく「同じ型の変奏量違い」なので、別の名前の方が MCP の利用者に誤解がありません。

### 7-2. 保存形（生きたレシピ）

- **ギター**：content は相対形のまま。`guitarRiff` の印に `variation: 0.5 | 1` を足す（**level 0／未指定はキーを生やさない＝既存 content と bit 一致**）。hits は変奏済みで載る（音高は毎回 web が出す＝現行）。
- **ベース**：錨経路の content は絶対 notes（現行）。印として `bassRiff: { grammar: string; variation: 0.5 | 1 }` を additive に足す（level>0 のみ）。「掴み＋つまみ＋seed→同じ音符」は錨経路の現行モデル（io-map）そのままで、印は「いま：変奏 中」の表示と再生成の復元に使います。**相対パターンへの昇格は範囲外**（`relative:true`＋`anchorLock` は現行どおり絶対で返す）。
- **音符レーンは足さない**。選んだ候補を「置く」だけ（既存の候補トレイ動線）。

### 7-3. 到達口（4口）

| 口 | ベース | ギター |
|---|---|---|
| HTTP `/music/gen_bass`／`gen_chord_pattern` | `riffVariation`・`riffVariationSteps` を素通し | 同左 |
| MCP `gen_bass`／`gen_chord_pattern` | inputSchema に2項追加（説明＝「錨を立てた時だけ。0=従来／0.5=2回目以降の答句をずらす／1=さらに間と拡大」） | 同左 |
| `/gen/section` | `body.bass.riffVariation` を素通し。**段は出せない**（1曲分の合成は各パート1件）＝`riffVariationSteps` が来たら「セクション一括では段を並べられません。段は各パートの生成で」と `warnings` に載せ level 0 で作る | `body.chord.riffVariation` 同様 |
| web TinkerSheet | ベース引き出し（錨 ON の下）に**「変奏を3段で並べる（なし／中／多め）」**チェック1つ（既定 OFF）。ON で `riffVariationSteps:true`。**トレイへ3件すべて積む**（現行の `gen_bass` は `items[0]` だけ＝`useMelodyGen.tsx:449` を「複数なら全件」に） | コード楽器引き出し（リフ文法の下）に同じチェック。トレイは既に全件積む |

web に単独の level つまみは置きません（段で聴いて選ぶ、が裁定）。置く時は候補カードの label が「変奏 中」なので、選んだ結果に印が残ります。

## 8. 決定論と seed

- 層は RNG を消費しません。seed は **(i) ゼクエンツの向き＝`(seed + tile.index)` の偶奇**、**(ii) reselect の回転＝`seed mod 4`** にだけ使います。同じ seed・同じつまみなら同じ出力。
- ベース錨経路は現在「RNG 不消費＝seed に依らず骨が安定」（`generate.ts:1454`）ですが、**level>0 では向きが seed で変わる**＝意図した変更（level 0 は従来どおり seed 非依存）。design 追補にこの一文を足します。
- 既存の Rng（approach の `seed+101`・snareGap の `seed+29`）の列は変わりません（層は別段・Rng を作らない）。

## 10. 案4（規則生成）との関係

- 層の入力は `RiffTile[]`（役割つきオンセット列）であって、文法辞書にも `BassCell` にも `GtrCell` にも依存しません。**表の後処理ではなく独立した変換段**です。
- 案4 が「リズムは譜から・音は許容集合と続きやすさで選ぶ」生成器になった場合、その出力に役割（head／pedal／answer…）を付けて `RiffTile` にすれば、変奏の層はそのまま使えます（規則生成が提示を作り、層が2回目以降を応答に変える）。逆に案4 が「反復単位ごとに毎回別の音を選ぶ」設計なら、層は要らなくなる＝**その時は層を呼ばないだけ**で、層の存在が案4 の設計を縛りません。
- 保護集合を「変わり目のキックだけ」に狭める（案2 着地後）のも、層の入力を変えるだけ（§6-2）。
- 将来の案5（power_chug の bVII/bVI をコード追従で生かす）は**レバーの1つとして同じ段に足せます**（`chord` 役割の deg を滞在中だけ尊重）。ただし和音追従の読み替えが要るので本設計には含めません。

## 12. オーナーに聞くこと／聞かないこと

### 12-1. 聞くこと（1件）

**多めで、リズムも動かしてよいか**（答句を16分ひとつ前へずらす「変位」を語彙に入れるか）。理由＝音高だけの変奏はギターでは和音追従に丸められて差が小さく（§4-2）、リズムを動かすと差は大きいが「パームミュートみたい」の印象やキックとの噛み合わせが変わる＝物差しは耳なので範囲を先に伺います。

| 選択肢（20字） | 説明（40字） | 利点 | 難点 | 整合 |
|---|---|---|---|---|
| **音高と間だけで始める** | ゼクエンツ・断片化・拡大・装飾のみ。リズムの格子は不変 | less is more（源流の学び）。錨・和音追従と衝突しない。実装が小さい | ギターの中の差が小さい可能性 | ◎ A-5「リフの同一性の半分はリズム」を守る |
| 多めだけ16分のずらしも | 最後の反復単位の答句を1 step 前へ（保護 step は避ける） | 「動かしたい」に最も直接。段の間隔が広がる | キックの契約・案6 の音価つまみと絡む。わざとらしさの再燃リスク | ○ 源流の残課題「変位」と一致 |
| 全部の段でずらす | 中からリズムも動かす | 差が最大 | 提示と応答の同一性が薄れる（別のリフに聴こえる） | △ |

**推し＝「音高と間だけで始める」**（S5 の試聴帳で足りなければ S6 で「多めだけ」を足す＝取り消せる順）。

### 12-2. 聞かないこと（機械が決めた仮の値・耳で決める項目）

- 中の中身＝ゼクエンツ（仮）。レジスタ上げ（源流 low band）との比較は**試聴帳（S5）で耳が決める**＝文字で聞かない。
- 装飾レバー（ギターのゴースト付け外し・ベースのオクターブ）を多めに入れるか＝仮で入れる・耳で外せる。
- 反行＝既定の段に入れない（仮・less is more）。耳で「多めがまだ足りない」なら S6。
- スケジュール（奇数＝ゼクエンツ・偶数＝断片化・最後＝拡大）＝仮。
- 階段（リフ語彙 `[R,b3,4,b5,5,b7,8]`）・向きの偶奇・reselect の回転＝仮。
- つまみ名・保存形・到達口・web のチェック1つ＝機械が決めた（§7）。
- 変換の組み合わせや強さの初期値はすべて**「仮」**であり、どの変換が耳に良いかは決めていません。

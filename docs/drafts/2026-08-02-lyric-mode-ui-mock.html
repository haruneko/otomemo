詞モードUI候補モック（メロディ編集・360px実機風）

前提の補正：モード行4つ目の現ラベルは「歌詞」（title="歌詞を直す（音符をタップ）"）＝直上に常設の歌詞1行（句の面）があり、「歌詞」の口が2つ並ぶのが現状。 例のメロ＝「とけいのはり」6音・2小節。配色・寸法は実CSS（transport-cards.css / base.css）から模写。黄色の注記＝モックでは動かない仕様の説明。

【候補1】現状維持＋説明増補（ベースライン）費用感＝極小（文言2か所＋属性1つ）
候補1-A：詞モードに入った直後（未選択）
配置は一切不変。ヒント文言だけ増補＝作法（タップ→かな→確定で次）を1行で読める化。
メロディ「サビ」
時計の針 過不足なし ▾
詞 音符をタップ→かなを打つ→確定で次の音符へ
title「1音ずつ直す（音符をタップ→かな→確定で次へ）」に更新（スマホ非表示は割り切り）。モード行の「歌詞」の名はそのまま＝歌詞行との二口も残る。
候補1-B：音符をタップした後（選択中）
バーは現行構成のまま。input に enterKeyHint="next"＝スマホIMEの確定キーが「次へ」になる。
メロディ「サビ」
時計の針 過不足なし ▾
詞 E4・2拍
enterKeyHint="next" のみが挙動追加。「押す前に読めない」穴と歌詞二口は現状維持のside。
【候補2】改名＋表計算式送りバー費用感＝小（バー1か所＋onKeyDown＋改名）
候補2-A：詞モードに入った直後（未選択）
名を「1音ずつ」に戻す＝直上の歌詞行（句の面）と役割が名前で割れる。幅CSSは据置。
メロディ「サビ」
時計の針 過不足なし ▾
詞 音符をタップ→かなを打つ→Enterか▶で次へ
design に一文「バーのボタンが正・キーは近道」＝物理キーとの両立の作法を閉じる。
候補2-B：選択中＝◀▶送りバー
「確定→次」は「▶」に吸収（押す＝確定して次）。「◀」＝確定して前へ（誤送り復帰）。対象音符はハイライト＋自動スクロール追従。
メロディ「サビ」
時計の針 過不足なし ▾
E4・2拍
キー定義：Enter/Tab=▶・Shift+Enter/Shift+Tab=◀・Esc=✕（preventDefault・isComposingガード維持）。enterKeyHint="next"。
【候補3】入口を歌詞行の隣へ移設費用感＝中（ボタン移設＋モード抜け結線＋テスト入口変更）
候補3-A：押す前（通常時）
モード行は「描く／選ぶ／消す」の3つに戻る。常設歌詞行の右端に「1音直す」＝歌詞の用が集まる場所＝文脈が説明を兼ねる。
メロディ「サビ」
時計の針 過不足なし ▾
タップ1回で詞モード＋固定バー出現＝入口はボタン・1タップ維持。弱点＝先例15種で0種の配置（drafts doc §件1(a)）。
候補3-B：押した後（詞モード中）
バーは現行のまま（候補2の◀▶と併用可）。✕の右に「終わる」＝描くモードへ戻る抜け口（入口が遠くなるぶんの補い）。
メロディ「サビ」
時計の針 過不足なし ▾
詞 E4・2拍
モード行に「歌詞」が無い＝押す前から歌詞の用は歌詞行に集約・title不要。
【候補4】かなチップ帯＋まとめ打ち費用感＝中〜大（チップ描画＋index対応＋自動スクロール＋分配upsert）
候補4：詞モード中（編集対象＝「は」）
バー2段化（+約40px）。上段＝句のかなチップ帯：タップで任意音符へ（Tab連打の上位互換）。下段＝現行バー＋まとめ打ち。
メロディ「サビ」
時計の針 過不足なし ▾
と け い の は り
E4・4拍
編集中チップ＝塗り反転／手直し済み＝下線。複数モーラ入力は splitMora で時間順に分配（例「はりを」→は・り・を）。1モーラ＝現行と同一・空=消す・「ー」=のばす据置。デスクトップは←/→でチップ移動。名は「1音ずつ」だと嘘になるため「かな直し」等＝改名（候補2）同梱が前提。

併用の目安：2+3・2+4は併用可。1→2→4は積み上げ導入できる（3のみ配置変更＝可逆だが別枠）。 「押す前に読めるか」の埋まり＝1:埋まらず／2:名で識別／3:文脈で用まで／4:入った後の理解が最強。

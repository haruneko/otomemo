# 演奏レシピの入出力対応表 — 楽器ごとの「掴み → 生成物 → 効くつまみ」（一案）

前提（確定済み・覆さない）：レシピは**ジェネレーター**＝掴み（最小入力）を与えると演奏そのものを生成する。保存は掴み＋パラメタ＋seed のみ（A＝生きたレシピ・完成音は保存しない・再生/解決のたび毎回生成）。ノリは生成物の一面。候補まで機械・採否は人間。

根拠の在り処（転記でなくポインタ）：otomemo＝`apps/api/src/music/generate.ts`（genDrums 1566・genBass 1100・genChordPattern 940）・`apps/api/src/mcp.ts`（gen_bass 771・gen_chord_pattern 820・gen_drums 825）・[M0契約](2026-08-20-phrasemaker-M0-contract.md)・[実装計画](2026-08-19-phrasemaker-port-implementation-plan.md)。phrase_maker＝`docs/CONCEPT.md`（芯＝身体性シミュレータ・コア入力契約）・`docs/HANDOFF-NEXT.md`（共有リズム譜 RhythmSpec・bodyfill・GMD手触り）・`experiments/drums/gen2/src/timing.py`（声部別ms）・`experiments/drums/fills/src/bodyfill.py`・`experiments/ensemble/ensemble.py`（fill_marks・kick ロック・隙間刺し）・`experiments/piano/fingersim/`。

## 共通の芯と、楽器で本質的に違う所

**共通の芯**：全楽器が同じ型＝「掴み＋つまみ＋seed → `resolve(recipe, ctx)` → ストレート実音＋skeleton＋groove → 試聴 → 別案（seed 振り直し）→ 採用＝レシピ保存」。groove は常に演奏レイヤー行き（B1裁定）・resolve の音は常にストレート・「置いた/指した意図は生成が消さない」も共通。**本質的に違うのは掴みの性質**：ドラムだけ「骨を**描く**」（格子への手入力＝生成物にそのまま残る）、ベース・コードは「**指す**」（コード＋役割の記号入力＝音符は全部生成）。この非対称は欠陥でなく構造＝ドラムの骨が skeleton として下流全員の掴みになる（phrase_maker の共有リズム譜と同じ・「1回描けばバンド全員が噛む」）。ドラムの掴みは実質バンドの掴み。

## オーナー裁定（2026-08-20・全7点決着）

1. **ドラムの骨は必須でない＝空でも「おまかせ骨」生成を許す**（生成器ゆえ空入力でも候補・描くのは任意の掴み強化）。
2. **ベース/コードにも「描く口」を開ける＝将来やる／ただし時期をずらす**（初期は「指す」だけ・描かせ口は後）。＝**捨てない・ロードマップに残す**。
3. ドラムレシピ不在時のベース＝**こだわらない**（実装都合で可・推し＝既存経路＋仮骨フォールバック）。
4. 既存 gen 系（型辞書）との終着＝**併存**（吸収判断は B6＝M2後）。
5. コードのタイミング掴みを描かせるか＝**#2と同じ**（将来開けるが後・初期は型任せ）。**捨てない**。
6. フィルマーカーは**掴み＝保存対象**（「この範囲にフィル」の構成意図を残す）。→ **2026-08-21 改訂**＝位置と強さは[セクションの合図へ引っ越し](2026-08-21-arrange-data-locus.md)（案C）。レシピに残るのは「フィルの弾き方」だけ。
7. 別案の単位＝**M1は全体振り直しで始め、小節単位の再生成はM2で足す**（additive）。phrase_maker の芯は小節単位＝**捨てない・目標として残す**。

含意：初期スコープ＝ドラムは描く・ベース/コードは指す（描く口は後）／別案は全体（小節単位は後）。「後」の3点（#2/#5/#7）は additive で乗る＝初期契約を壊さない前提で先送り。

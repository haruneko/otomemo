# 鍵盤の「つかみ」を芯にした生成器の進化先（設計案・2026-09-16）

phrase_maker（同じオーナーの Python 試作・読むだけ）の「鍵盤の手の形（handframe）」を、Otomemo に**移植ではなく進化させて**取り込むための設計案です。オーナーの耳判定（2026-09-16）「**全部取り込んでいい。ただつかみ以外は雑なので進化先をもっと考えていいと思う**」を起点にしています。当事者外の判定と反対三面（「移植しない」）は耳で覆されたので、それらが挙げた制約は**取り込まない理由ではなく、進化先で解く課題**として扱います。コードは変えていません。行番号は phrase_maker `e186970`・Otomemo `8f47a1c` 時点です。

## 要約

1. **「つかみ」の定義**＝コードを弾く**時刻**（どの16分マスで和音を打つか）と、そこで手が押さえられる**音の組**（いまの手の位置と押さえている指から届く2〜4音）と、その**長さ**（次の掴みまで／区間の終わりまで／短く）を、手の状態から決める仕組み。コード上は「区間頭の確立（RESEED）」「合図の位置の部分掴み（GRABp）」「掴みの量の段（ラダー）」の3つです。
2. **「雑」な部分**＝掴みの間を単音で埋める「波」、フレーズの弧、ペダル、ばらし、音量の輪郭、左手の殻、手で合わせた係数の束、バンドの床。**第1版では全部外し**、掴みだけで生成器を白紙から書きます（波は後段の「崩し」軸として耳で判断）。
3. **進化先の要点**＝時間軸を「小節」でなく**「コード区間 × 拍子の格子」**にし、2拍替わり・3/4・6/8 を最初から入力にする。掴む時刻は**入力**（拍子の裏拍／セクションのドラムと合図／人の指定の3本）で、ドラムが無くても立つ。音高は手の窓からだけ出す。選択は上位数候補からの抽選＝1つの答えを返さない。
4. **置き場の推し＝④「相対の譜に写して持つ」**＝生成器は api 側（配札の出どころ）、出力は既存の相対パターン（hits に音数・度数の部分集合・長さ）＋境界規則、実音化は今の web 経路のまま。手の到達は半音の距離で決まるので調に依らず、相対で持っても失うものが小さい。往復一致（同じ進行・同じ調で生成器の音＝実音化の音）をテストで担保します。
5. **耳で先に確かめること**＝向こうの Python を**エンジン無改変・ハーネスの30〜50行**で改造し、(a) 2拍替わり区間でも掴みが生きるか (b) 掴みだけ（波なし）が良いか (c) 3/4・6/8 で立つか、を Otomemo の基準線と同じ進行（Fmaj7｜G｜Em7｜Am7→G）で聴く。4〜6本・短尺・任意。
6. **オーナーに決めてほしいこと**＝(1)「つかみ」の意味の確認（掴みの仕組みで合っているか）(2) 置き場（推し④）(3) 波（崩し）を後段の軸として残すか (4) 掴む時刻の既定（拍子の裏拍か・ドラムがあればドラムか）。

## 2. 「つかみ」の定義（コードで特定）と「雑」の一覧

### 2-1. つかみ＝3つの仕組み

phrase_maker の handframe で「和音を掴む」出来事は次の3つです（`experiments/piano/fingersim/`）。

| 仕組み | いつ | 何を掴むか（音高の出どころ） | 長さ | コード |
|---|---|---|---|---|
| **確立（RESEED）** | コード区間の頭（`is_boundary(b)`＝トークンが前と違う小節の slot 0） | ボイシング（RH＝R・3・5・R+8 の4音 `band_rh_voicing`）を `best_assignment` で手に載せ、**最高音とガイド音（3度・7度）の指だけ保持** | 保持指＝区間末まで、他＝短く | `handframe.py:813-875`（`reseed_move`）・`:1048-1049`（境界判定）・`:1176-1215`（slot 0 の分岐） |
| **部分掴み（GRABp）** | 「構造スロット」＝掴む時刻の集合 `structure_slots[b]` に載っているマス（`role=="structure"`） | 届く単音候補の上位6個から2〜3音の組を作り、保持指込みで `constrained_assignment`（手全体が単調・≤4音）に載せる。事前分布＝`-0.5 × grab_w`（`grab_w = a_slot × grab_w_scale`） | `grab_dur`＝短く／次の打点まで／**次の掴みまで（TILL_GRAB・区間末で切る）** | `:460-482`（`_grab_candidates`）・`:357-442`（`_make_grab`）・`:1258-1268`（重み）・`:293-318`（`dur_end`）・`handmodel.py:266-307` |
| **2音掴み（DYAD）** | 掴みの間（colour スロット）で、連なりの始点・着地・拍頭 | 単音候補の上位8個から2音の組 | 短く | `:445-457`・`DYAD_PRIOR_AMT=-0.4`（`:927`） |

補助：非境界の小節頭は**音を出さず手を置き直すだけ**（サイレント RESEED `:1187-1205`）。

**掴む時刻の集合の出どころ**（音高は運ばない＝スロット番号だけ・防壁1）：
- 共有リズム譜のスネア（±キック）から（`handframe_band.py:255-263` `build_structure_slots`）。
- **掴みの量の段（ラダー）**＝スネア→キック→アクセント→裏拍の順位で上位 N 個（`:327-348`）。段は「掴む数」と「間引き率」と「掴みの重み」を**連動**させた4段（`_GRAB_DENSITY :315-323`＝count 2/3/4/5・lambda_skip 0.55→0.14・grab_w_scale 0.7→5.2）。初版は数だけ増やして出力が潰れた＝**出力の掴み密度で段の分離を測る**教訓（`:300-313`）。
- 人が書いた掴みの格子（`g:` 行・`:276-312`）＝書いたとおりに使う（ガード無し）。
- アクセント表＝掴むマスは最強 1.0（`:391-420`）。これが間引き確率・2音掴みの事前分布・音量に流れる。

**耳の記録**：バンド版「品質的には元に戻った・良さそう」（2026-08-15）／ラダー「**掴みは選べるべき・この幅で良い**」（同日・memory `handframe-status.md`）／密の段で「和声が雑」→和声粗3点の修正は耳未判定（`bb173cf`）。

### 2-2. 言葉での定義

> **つかみ**＝「**どの時刻に**（拍子と合図から決まるマスで）、**手がいま届く範囲の何音を**（押さえている指と到達窓から決まる2〜4音を）、**どれだけの長さで**（次の掴みまで／区間の終わりまで／短く）和音として打つか」を、**手の状態を持ち越しながら**決める仕組み。コードが替わる時刻の「確立」と、合図の位置の「部分掴み」の2種類があり、**量を段で選べる**。

## 3. 進化先

### 3-1. 時間軸＝「コード区間 × 拍子の格子」（1小節1コード・4/4 限定を解く）

向こうは小節単位でした（`ensemble.py:2065` で拍単位の進行を小節へ丸める・`handframe.py:1048-1049` の境界判定・`handframe_band.py:48` の 4/4 固定）。進化先では**最初から**次を入力にします。

- **拍子**＝1小節の格子数 `grid`（4/4＝16・3/4＝12・6/8＝12）と拍の位置。Otomemo は 4/4 と 6/8（world68・grid 12）が現用（design:825-834）。3/4 は着手時に確認。
- **和声のリズム**＝セクションの `chords[]`（各コードの拍長）を**区間**の列に写す：`区間 = {開始マス, 長さ（マス）, コード}`。区間の長さは 2拍（8マス）でも 1小節でも 2小節でも同じ扱い。
- **掴みの規則を区間に結ぶ**：確立は**区間の頭**（小節頭ではない）。「次の掴みまで」の長さは**区間末で切る**（向こうの `dur_end` の clamp と同じ `handframe.py:300-303`）。**掴みの量の段は「4拍あたりの掴み数」で定義**し、2拍区間では半分（最低1＝確立）に、6/8 では2大拍あたりに読み替える＝**区間の長さに依存しない形**。
- **合図の位置（掴み候補）は小節の格子上**で与え（裏拍は小節の性質）、区間はそれを切り取るだけ。区間頭と合図が重なれば確立が勝つ（向こうの E2 規則 `handframe.py:1170-1175` と同じ）。

**テストで先に固定すること**：2拍区間に確立が1回入る／確立は区間頭以外に出ない／区間をまたぐ長さが出ない／4/4 grid16 と 6/8 grid12 で同じ規則が通る／2拍替わりの進行と、それを1小節に丸めた進行で出力が違う（丸めていないことの反証）。

### 3-2. 掴む時刻の供給＝3本（ドラム譜への依存を解く）

向こうは共有リズム譜のスネアが必須で、無いと掴みが空になりました（`ensemble.py:2066-2077` の警告）。進化先では**掴む時刻の候補集合は生成器の入力**にし、供給元を3本持ちます。生成器は供給元を選びません（指揮者を作らない・design:2119）。

| 供給元 | 中身 | いつ効くか |
|---|---|---|
| **① 拍子の裏拍（既定・常に立つ）** | 4/4＝2・4拍（マス 4・12）、3/4＝2拍（マス 4）、6/8＝2つ目の大拍（マス 6）。段が上がるとキック相当の表拍・8分の裏へ順位で広げる | ドラムが無いとき・コード楽器を単体で配るとき（PlacePicker の候補4枚はドラムを知らない） |
| **② セクションのドラムと合図** | セクションにドラムのネタが置かれていれば、その sd/bd の打点を①の代わりに順位付けの種にする。合図（`Cue.kind` build/break/fill・design:2121）は**小節ごとの段の増減**として受ける（build＝段を1つ上げる・break＝確立だけ・fill の小節＝掴みを前半に寄せる） | `/gen/section` のカスケード（ドラムが先に在る）・セクション文脈での配り直し |
| **③ 人の指定** | 既存のコード楽器エディタのステップ格子で掴みの打点を直す＝パターン単位の編集（req:222） | 配られた候補を採用したあと |

- **防壁**＝供給元から生成器へ渡るのは**マス番号の集合だけ**。音高・度数は渡さない（`handframe_band.py:255-263` の作法）。
- **負の知識1（合奏の糊）との線引き**：向こうで「スネアに揃える」が本体だったのに対し、ここでは (i) 時刻の出どころは3本のうちの1つで既定はドラム無しでも立つ (ii) 音高は手からしか出ない (iii) 量は段で選べる。「キック位置には必ずルート」のような**音高を時刻に縛る規則は入れません**。
- **②は薄く**：cues の型（`Cue = {bar, kind, intensity?, aim?}`）に新しい kind を足さない。ドラムの打点を読む口は「セクションの子の content を1回読む」だけで、聴き合いのループにしない。

### 3-3. 掴む音の組（手の物理）と長さ

- **手の状態**＝手首の位置・各指の最後の鍵・押さえている指（`HandFrame` `handframe.py:219-231`）。区間の確立で載せ直し、部分掴みでは保持指を残して空いた指で組む。
- **音の組の出どころ**＝(a) 確立＝ボイシング（Otomemo の voicing.tones を度数→半音に展開したもの）を `best_assignment` 相当（到達表＝Parncutt 1997・pianoplayer の定数 `handmodel.py:10-22,52-66`・MIT・NOTICE に再掲が要る）で手に載せる。届かなければ4音→3音に落とす。(b) 部分掴み＝保持指を固定した到達窓（`free_finger_reach :224-263`）∩コード音（＋許すならテンション）から2〜3音の組を `constrained_assignment` で手全体が単調になるものだけに絞り、身体コスト÷音数＋時刻の事前分布で採点。**選択は上位3候補からの温度付き抽選**（`sample_topk :769-795`・argmin 禁止）。
- **長さ**＝3種（短く／次の打点まで／**次の掴みまで**・区間末で切る）。第1版の既定＝「次の掴みまで」（ペダル無しで持続が出る乾いた側＝wave1 §7）。
- **音域**＝下限は楽器の既定（ピアノ中域）＋注文チップ「低く/高く」。ベースを見に行かない。
- **検査係に堕ちていないことの反証**（(B) の必須）＝到達表の重み（弱指・黒鍵・伸ばしの罰）を振ると**出力の音の組が変わる**こと、および到達窓が合法候補を刈った割合をテストで測る（`SPEC-piano-handframe.md:198-200` の束縛度3点を Otomemo 側で書き直す）。**数値は診断で、良さの報酬にしない**。

### 3-4. 掴みの量と置き方＝離散2軸＋seed

- **量（4段）**＝「4拍あたりの掴み数」で定義（疎＝確立＋裏拍1／中／密／最密＝それでも全マスは打たない）。段の分離は**出力の掴み密度が単調に増え、隣の段と離れていること**で受け入れる（数だけ増やして潰れた向こうの教訓 `handframe_band.py:300-313`）。
- **置き方（3種）**＝裏拍寄り（既定）／表拍寄り（キック相当）／合図に従う（②があるとき）。
- **seed**＝抽選の道筋。同じ段・同じ置き方でも手の道筋が変わる＝「似たニュアンスの別パターン」の最小単位。
- 連続つまみは露出しない。プリセット名（grip/mid/loose）は持ち込まず、段と置き方の2軸だけを注文チップに出す。

### 3-5. 「雑」な部分の扱い（良くする／外す／DAW に任せる）

| 部分 | 扱い | 理由 |
|---|---|---|
| 波（単音の崩し） | **第1版では外す**。後段で「崩し」軸（なし／少し／多め）として**耳で**要否を決める | オーナー「雑」。音符の詰めは DAW（req:222）。ただし「手癖に無い崩し」を欲しがる可能性は残る（fingersim で一度「自分の手癖と違うものが出てる」＝memory `comping-eval-protocol.md`）ので、撤去でなく保留 |
| フレーズの弧 | 外す。合図（build/break）→段の増減だけで受ける | 層違い（曲/セクションの構造・design:2119）。M3 の因果仮説（弧で連打が減る）は向こうでも不成立 |
| ペダル | 外す。「次の掴みまで」の長さで持続 | CC を持たない（design:258） |
| ばらし・音量の輪郭 | 外す。既存 feel 層 | ニュアンスは DAW／既存が担う |
| 左手の殻 | 既存 `lh` 契約（root/root5/oct）を使う。3/7 殻は後段の custom hits | 二重に作らない |
| 型の反復 | 既存の `bars:2` テンプレで代替 | 同じ機能 |
| ベース床 | 外す。音域は voicing の指定＋チップ | 問い合わせ口を作らない |
| 係数の束 | 持ち込まない | 聞こえ方の多くが係数から来ている可能性（反対レビュー・memory「既知の制限②」）。白紙で段を出力密度から決め直す |
| テンションの解禁 | 第1版はコード音のみ。テンションは voicing.tones に既にある分だけ | オルガンの 7th の濁りの真因調査と絡む＝待つ |

**良くする方向（統計と身体性で）**＝(i) 掴む時刻の既定の順位（裏拍→表拍→8分裏）を、後段で他者実データの**打点の分布**で較正する（統計のみ）(ii) 音の組の厚み（2音か3音か）の出やすさも同様。身体性側は到達表そのもの（変えない）。

### 3-6. 配札（S2＝「生成器を配る」）への接続

- **出どころ**＝コード楽器の候補取得（design:457 の `gen_chord_pattern` の流儀）に「その場で作る」出どころを1つ足す。型辞書の候補と**同じカード**に並ぶ（見た目で区別しない・ランキングしない）。
- **数枚の作り方**＝seed × 段 × 置き方の組から、**出力の掴み集合の署名**（打点列＋音数列）で近重複を刈って4枚（向こうの fill_variation の刈り方 `ensemble.py:1584-1597` と同じ考え）。
- **注文チップ（軸を指定して配り直す）**＝「もっと少なく/多く（段）」「表/裏（置き方）」「薄く/厚く（音数）」「低く/高く（音域）」「短く/伸ばす（長さ）」。ピンを種に＝seed と段を固定して置き方だけ振る、など。
- **進行を変えたら**＝置き場④なら境界規則で自動で付いてくる（枝5）。手の道筋を最適化し直したいときは「配り直す」1タップ。
- **別物度の確認は耳**（next-work-list §4-2）。機械の距離で決めない。

### 3-7. 統計の使いどころ（後段・統計のみ）

他者実データ（POP909 のピアノ伴奏トラック等）からは**打点の分布・音数の分布・掴みの長さの分布**だけを取り、掴む時刻の既定の順位と段の中身の較正に使う。リテラルな打点列・音列は保存しない（CLAUDE.md:35）。効果は未検証（ideas-to-keep §3）なので、最初の試作では入れず、耳の後に「差が出るか」で判断。

### 3-8. オルガン（仮説に留める）

- **仮説**＝オルガンでは「掴む時刻を区間頭から少し遅らせる・次の音の直前で離す・共通音は繋ぐ」（向こうの保持レイヤーの規則 `ensemble.py:2496-2580`）が、そのまま**掴みの計画の「置き方」の1種**として表せる。手の物理（≤4音・保持指）は 7th の配置を狭い範囲に閉じるので、濁りが**配置の広さや重なり**から来ているなら効くかもしれない。
- **ただし**濁りの真因は別担当が調査中（backlog「オルガンの型は…真因調査が先」）で、原因が実音化の経路（voiceToTop の積み方）にあるなら生成器側では直らない。**本書では設計しない**。真因が出てから、オルガン用の「置き方」を足すかを判断。

## 4. 置き場（旧 §8-2 の3択を今の文書で判断し直す＋4つ目）

旧 master plan §8-2（`docs/archive/2026-09-09-phrasemaker-port-master-plan.md`）は「①その場で毎回作る／②作った音を持つ／③別の道具で作る」で推し①でした。**進化先では生成物が「掴みの計画」に絞られる**ので、4つ目が立ちます。

| 選択肢（20字） | 説明（40字） | 進行を変えたら付いてくるか | 別の調で鳴るか | 後から手で直せるか | 実音化の経路 | 作る側の重さ | 生成時に聴いた音との一致 |
|---|---|---|---|---|---|---|---|
| ①その場で毎回作る | 生成器を共有部品に置き、再生のたびに手の状態から弾き直す | 付いてくる（自動） | その調で鳴る | パターン単位では直せない（毎回作り直される） | **2本**（既存＋手の生成器） | 中〜大（web でも走らせる） | 一致 |
| ②作った音を持つ | 生成した実音を控えとして保存しそのまま鳴らす | 付いてこない（作り直し） | 原調のまま鳴る（移調規則の手当て7箇所） | 読み取り専用 | 1本＋例外 | 中 | 一致 |
| ③別の道具で作る | Python を同梱して呼ぶ | 付いてこない | ②と同じ | ②と同じ | 1本＋例外 | 小〜中・**アーキ変更** | 一致 |
| **④相対の譜に写して持つ** | 生成器は api・出力は hits＋音数/度数の部分集合＋長さ＋境界規則・実音化は今の web 経路 | **付いてくる**（境界規則で。手の道筋の最適化は配り直し） | **その調で鳴る**（相対） | **既存エディタでパターン単位に直せる** | **1本** | **小〜中** | 同じ進行・同じ調なら**一致**（往復テストで担保）・進行が変わると近似 |

**推し＝④**。理由：(i) 「api はテンプレ・実音化は web」（design:548）と「content は人が仕上げる単位」（design:506）にそのまま乗る (ii) 枝5（進行変更→自動で当て直し）が構造で満たされる (iii) 手の到達は半音の距離で決まる（`handmodel.py:52-66`）ので、相対で持っても失うのは「別の進行に対する手の道筋の最適化」だけで、それは配り直しで補える (iv) 実音化の経路を2本にしない・絶対 notes の違反（design:570）を新しく作らない。

**④に必要な additive 契約（着手時に実コードで確定）**：`ChordHit` に「音数または度数の部分集合」と「長さの種別（次の掴みまで）」を書ける口（前例＝`ChordHit.dir?`・`lh.hits[].deg` design:460-461）。未指定＝既存全ネタ bit 一致。LH の度数トークンが R/3/5/7/8 限定で未知が黙って根音になる件（backlog）は先に直すか、部分集合をその5種に限る。

**④→①の切替条件（撤退基準の1つ）**＝往復一致のテスト（同じ進行・同じ調で、生成器が手で決めた絶対音＝相対 content を web の規則で実音化した音）が**設計上取れない**と分かったとき。そのときは①を再提案し、実音化2本の是非を改めて裁定に出します。

## 5. 耳で先に確かめること（実装の前に・向こうの Python を小さく改造して）

**鳴らせます。エンジン（`handframe.py`）は無改変、ハーネス側 30〜50 行**で足ります。理由＝`generate_handframe` は「トークン列＋区間長 `bar_dur`＋格子 `grid`＋打点の器 `container`」を受けるだけで（`handframe.py:930-935`）、同じトークンが続く「小節」は境界にならない（`is_boundary :1048-1049`）。よって**「2拍を1小節と見なす」だけで2拍替わりが再現**できます。

## 6. 段取り（スライス・テストの順序・受け入れ・撤退基準）

**S0 耳と定義の確認（機械の作業は Python ハーネスのみ）**
- §5 の #1〜#3 を鳴らして聴く。あわせて §8 (1) の「つかみ」の意味を1問で確認。
- 撤退基準①＝#1 で「丸めた版・PB-BLOCK8 と差が出ない」なら**取り込まない**（S1 に進まない）。

**S1 掴みの計画＝純関数（api 側・生成器本体）**
- 入力＝区間列（`chords[]`＋拍子から）・格子・掴む時刻の候補集合（マス番号）・段・置き方・seed・voicing の度数。出力＝相対 content（hits＝打点・長さ種別・音数/度数部分集合・vel）＋境界規則。
- **テストを先に（この順で赤→緑）**：(a) 2拍区間に確立が1回・区間頭以外に確立が出ない (b) 掴みの打点は供給された集合の部分集合（音高は入力に無い） (c) 段の単調性＝**出力の掴み密度**が増え隣と離れる (d) 到達表の重みを振ると音の組が変わる（検査係でない反証）＋窓が候補を刈った割合 (e) **往復一致**＝同じ進行・同じ調で生成器の絶対音＝web 規則の実音化 (f) seed 決定論 (g) 4/4 grid16 と 6/8 grid12 (h) 既存 content は bit 一致（additive）。
- 撤退基準②＝(e) が設計上取れない→§4 の①切替を裁定に出す。それも重いと判断されれば止める。
- **規模の上限（兆候の見張り）**＝生成器本体 約400行。超え始めたら「波を持ち込んでいる」兆候として止まり、何を持ち込んだか書く。

**S2 掴む時刻の供給元3本**
- ①拍子の裏拍（既定）→②セクションのドラム＋合図（cues の build/break で小節ごとの段）→③人の指定（既存のステップ格子で直せることの確認）。
- テスト＝ドラム無しで①が立つ／ドラムがあれば②が①を置き換える／build の小節で段が1つ上がり break で確立だけになる／③は書いたとおり（ガードで消えない）。

**S3 配札への結線（実機フロー）**
- 候補取得の出どころに足す→PlacePicker で候補4枚→文脈試聴（主旋律と一緒）→採用→進行を変えて追従→配り直しのチップ。**テスト緑≠結線保証**＝実機でこの流れを1回通す（memory「結線は実機フローで確認」）。

**S4 耳（Otomemo 上・主旋律あり・J-POP 2拍替わり・6/8）**
- 物差し＝**採用率**（そのまま貼る／ノリだけ直す／音符を書き換える／貼らない＋「自分では思いつかない置き方があったか」）。棚の型と並べる。
- 撤退基準③＝棚の型と同等以下→撤去（additive の経路なので既定出音は不変・小）。
- ここで後段（波＝崩し軸・LH 3/7 殻・統計較正・オルガンの置き方）の着手可否を決める。

**受け入れの作法**＝機械のゲートは**診断**（束縛度・密度の単調性・往復一致・決定論・bit 一致）。「間が良い」「静的でない」のような耳の観察は**機械の合否に硬化させない**（形の要求は診断で持ち、良さは耳）。

## 9. 自信の無い点

- **「つかみ」の意味**は試聴帳の「掴みの量」の言葉から読んだ解釈です。オーナーが「掴み＝曲の頭の導入」の意味で言った可能性は否定できません（§8 (1)）。
- **④の往復一致**は設計上の見込みで、Otomemo の実音化の規則（voiceToTop・followChords の再ボイシング）を実コードで読んでいません。部分集合の指定だけでは同じ音に落ちない可能性があり、その場合は「音域の目安」や「転回の指定」を additive に足すか、①へ切り替えます。
- **波を外しても「良さ」が残るか**は耳の前提です。§5 #2 で先に確かめます。
- **6/8 の掴みの既定**（2つ目の大拍）は拍子の性質から置いた仮定で、world68 の型と並べた耳はまだありません。
- **合図（cues）から段を動かす**設計は design:2121 の型に基づく文書上の判断で、cues が実際にコード楽器へ配られているか（S0 凍結のみか）は着手時に実コードで確かめる必要があります。
- 行数の上限「約400行」は兆候の見張りであって根拠のある数字ではありません。

# 鍵盤の「手の形（handframe）」を取り込む設計（第1版＝試作 #1 の構成をそのまま運ぶ・2026-09-16 起草／2026-09-17 改訂）

phrase_maker（同じオーナーの Python 試作・読むだけ）の「鍵盤の手の形（handframe）」を Otomemo に取り込むための設計書です。2026-09-16 の耳判定と裁定（末尾・正）に合わせて 09-17 に全面改訂しました。**改訂の芯＝「雑」な部分（波・弧・ペダル・ばらし）を外す前提が耳で否定された（#2 掴みだけ＝良さが残らない）ので、第1版は試作 #1 の構成をそのまま運び、2拍替わりへの対応だけを入れる。** 雑な部分の磨き込み（進化先）は第1版の後（§6）。コードは変えていません。行番号は phrase_maker `e186970`・Otomemo `a3f0a86` 時点です。

## 要約

1. **第1版の範囲＝試作 #1（`scratchpad/listen7/hf_listen7.py`）の構成を1音も変えずに運ぶ**：エンジン `handframe.py`＋バンド包み `handframe_band.py`＋手の物理 `handmodel.py`（＋弧 `phrase_arc.py` はコードとして残し既定 OFF＝試作どおり）。preset `mid`・掴みの量 L2・ペダルあり・ばらしあり・左手＝ルート抜き 3/7 の殻・ベース床固定 48・係数の束もそのまま。**唯一の変更＝時間軸を「区間（セル）」にして 2拍替わりを受ける**（試作の疑似拍子と同じやり方・§3）。
2. **「全部残す」と「Otomemo のコンセプトで外す」の衝突は3箇所**（§2-3）：**ペダル**（content に CC が無い `design.md:258`→ 音の長さの延長で近似が推し・**オーナー裁定**）／**ばらし**（ms の揺れ＝既存 feel 層・vel の揺れ＝content の vel＝近似・裁定不要）／**弧**（層違いの懸念は「生成器内部の既定・曲の構造とは結線しない」で解ける・第1版は試作どおり OFF）。事実＝**耳が「残らない」と言った #2 は 波・ペダル・ばらし を一緒に外した版**（弧は #1 でも OFF）＝どれが効いたかは未特定。
3. **2拍替わりの写し方（§3）**＝セクションの最短コード長を**セル**（2拍 or 1小節）にし、全小節を同じセルで切って**セルを「小節」としてエンジンに渡す**（試作 #1 と同一）。コードが替わるセル頭＝確立・同じコードのセル頭＝無音の置き直し（エンジン既存の規則）。1小節1コードだけの進行ではセル＝小節＝元のエンジンと同じ出力。3/4・6/8 は生成器の入力としては通す（拍子表 `chart.py:78-89`）が、**耳判定なし＝第1版では 4/4 だけ配る**（推し）。
4. **置き場（裁定④＝相対の譜）と新ボイシング（案A＋B）の関係（§4）**＝手の形の出力は「打点ごとに手が届く2〜4音（部分集合・単音・オクターブ位置つき）」で、和音全体を弾く `voicing`＋`hits` の形には写らない。**`voiceToTop`（案A＋B）を通すと必ず積み直され往復一致は取れない**。→ **打点に「明示音（度数＋オクターブ）」を書ける additive の口**を足し、明示音のある打点は `voiceToTop` を通さない（前例＝左手 custom の `deg`・`design.md:466-468`）。経路は web `resolveChordPattern` 1本のまま（中の分岐が1つ増える）。度数語彙＝ベース相対の語彙（質依存 R/3/5/7＋固定半音 `2/b3/4/…`・`design.md:580-581`）を流用。**この形なら往復一致は構造で取れる見込みが高い**（度数解決の関数を api/web 共有の `packages/music-core` に置き、生成器の逆写像を同じ関数で検算）。
5. **段取り（§5）**＝S0 契約と基準音の固定（赤）→ S1 手の物理 → S2 エンジン本体（Python と bit 一致＝**耳合格の音を運べた証明**・進捗ではない）→ S3 バンド包み＋セル分割 → **耳A（Otomemo の音＝試作 #1 と同じに聞こえるか）** → S4 相対の譜への写しと web の明示音経路（往復一致）→ S5 配札への結線（実機フロー）→ **耳B（主旋律つき・J-POP 2拍替わり・採用率）**。最初の一手＝S0 の基準音（試作 #1 の設定で `humanize=False` の音列を JSON に落とす）と契約テスト（赤）。
6. **規模（§7）**＝移す Python 約 2,750 行（handframe 1,700・band 581・handmodel 361・phrase_arc 109）＋置換する部品（和音表・拍子・ばらし）約 300 行分。乱数＝本体は `random()` のみ（`handframe.py:783,1235`）＝spike 緑の `PyRandom` で bit 一致・`gauss` は揺れ専用（`chord_attack.py:85,91`）＝Otomemo 側の乱数へ。TS 見積り 3,000〜3,500 行＋テスト。8〜10 セッション。
7. **オーナーに決めてほしいこと（§9）**＝(1) ペダルの持ち方（長さ延長で近似／CC64 を content に足す／外す）(2) 効いていた部分の切り分け試聴（Python 3本・任意）をやるか (3) 6/8 を第1版で配るか（`73_meter_68.mp3` は未判定）(4) 手で足した打点は和音全体（voiceToTop）でよいか (5) 単体で配るとき左手は殻（ルート無し）のままでよいか。

## 3. 2拍替わりへの対応＝時間軸を「セル」にする（第1版の唯一の変更）

### 3-1. 試作で良さが残った形をそのまま写す

試作 #1 は「半小節を小節とみなす疑似拍子」でした（`hf_listen7.py:12`）。エンジンは「トークン列＋`bar_dur`＋`grid`＋器」しか見ず（`generate_handframe :930-946`）、境界＝トークンが前と違う（`:1048-1049`）なので、**セルを「小節」として渡せば 2拍替わりはエンジン無改変で成立**します。第1版はこの形を採ります（理由＝耳が合格したのはこの構成・1-6）。

**実装の写し方**
- **セル長**＝セクションの `chords[]` の最短コード長（拍）を {2拍, 1小節} に丸める。全部1小節なら**セル＝小節＝元のエンジンと同一**。1拍のコードがあれば第1版はセル 2拍にし、セル頭で鳴っているコードを採る（警告・1拍替わりは第1版外）。
- **疑似拍子**＝`Meter(beats_per_bar=cellBeats, subdivisions=cellBeats*4, beat_steps=0,4,…, pulse_steps=0,2,…)`（`chart.py:42-75` の型・試作の HALF と同じ）。バンド包みの `METER` はモジュール変数（`handframe_band.py:48`・試作は差し替えで通した）＝**TS では引数にする**。
- **トークン列**＝セルごとのコード名。同じコードの連続セル頭＝サイレント RESEED（手の置き直しだけ・`:1170-1188`）＝1小節1コードのときの「非境界の小節頭」と同じ。
- **器（掴む時刻の既定＝拍子の裏拍・裁定5）**＝セル 8 マス：`b: x.....x.` `s: ....X...` `a: ..x...x.`（試作 #1）／セル 16 マス：`b: x.......x.......` `s: ....X.......X...` `a: ..x...x...x...x.`（試作の丸めた版）。`s:`＝掴む時刻の種・`a:`＝波の打点・`b:`＝L の順位付け。段＝`grab_density_cfg(container, 2)`。
- **ペダル窓＝セル**（`:516-517`）＝2拍セルでは半小節ペダル（試作どおり）。弧・動機の周期もセル単位になるが、第1版は弧 OFF・動機は `motif_bias=0`（`_RH_CFG_BAND` に無い）＝影響なし。
- **時刻の写し**＝`step = cellIndex × cellSteps + slot`（セクションの格子へ）。`bar`（6タプルの最後）はセル番号＝content には持たない。

**テストで先に固定すること（赤→緑の順）**
(a) 2拍替わりの進行でコードが替わるセル頭に音つきの確立が入り、同じコードのセル頭は無音／(b) 1小節1コードだけの進行はセル＝小節で **Python 4/4 版と bit 一致**／(c) 2拍替わり版は **試作 #1 の基準音（§5 S0）と bit 一致**／(d) 2拍替わりの進行と、それを1小節に丸めた進行で出力が違う（丸めていないことの反証）／(e) 区間をまたぐ音が無い（`dur_end` の clamp `:300-303`）。

### 3-2. 3拍子・6拍子＝生成器は通す・第1版では配らない（推し）

- 拍子表は向こうに既にある（`chart.py:78-89`＝4/4 grid16・3/4 grid12・6/8 grid12）。試作 #3 は鳴った（`73_meter_34.mp3`・`73_meter_68.mp3`）が**耳判定なし**。

## 4. 置き場（裁定④＝相対の譜）と新ボイシング（案A＋B）の関係＝往復一致の設計

### 4-1. 問題＝手の形の音は「和音全体のボイシング」ではない

- 今の和音パターン content＝`{ mode, voicing:{tones, openClose, octave, top?, …}, steps, hits:{step,dur,dir?}[], lh?, followChords? }`（`design.md:402,466-467,555`）。**打点は和音全体を弾き、音は実音化時に `voiceToTop` が決める**（トップ最寄り→残りをトップ直下へ密に・左手が R なら右手から R を抜く＝案A＋B・`:432-435`）。
- 手の形の出力＝打点ごとに**手が届く 2〜4 音の部分集合**（確立＝R・3・5・R+8 の配置／部分掴み＝2〜3音／波＝単音／2音掴み）＋オクターブ位置＋声部ごとの vel。Fmaj7 の確立は F A C F（7th 無し）、`voiceToTop`（案A＋B・左手 R）は E A C（＋top 最寄り）。**同じ和音になりません。** 打点の音数・度数・オクターブを content に持たない限り、`voiceToTop` を通した時点で積み直され、**往復一致は構造的に取れない**。
- 09-16 版が書いた「hits に音数・度数の部分集合」だけでも足りない（オクターブ位置が無いと `voiceToTop` 相当の再配置が要る）。

### 4-2. 解＝打点に「明示音」を書ける口（additive）＝手の形の音はボイシングし直さない

**契約（名前は仮・着手時に実コードで確定）**
- **`ChordHit.notes?: { deg: DegToken; oct: number; vel?: number }[]`**＝明示音。**ある打点は `voiceToTop` を通さず**、`pitch = rootRef(chordRoot) + degreeInterval(deg, quality) + 12 × oct` で実音化。無い打点＝従来（bit 一致）。前例＝左手 custom の `deg`（`design.md:466-468`）。
- **`lh.hits[].oct?: number`**（additive）＝殻の中域を書くため。指定時は LH 帯（C2–C3）と低音域ガードを適用しない（明示＝人が/生成器が決めた高さ）。deg 語彙に **`7`** を足す（現行 R/3/5/8＝未知が黙って根音になる件は先に「未知＝例外」に直す）。
- **度数語彙**＝ベース相対の語彙を流用（`design.md:580-581`）：和音の R/3/5/7 は**質依存**、それ以外の音は**固定半音**（`2/b3/4/#4/b5/#5/6/b7/#7/b2/#1/b6/#6`）。写し方＝音の pc が今のコードの R/3/5/7 なら質依存トークン、それ以外はルートからの固定半音トークン。
- **`rootRef(pc) = 48 + pc`**（C3 帯・左手 `lhBand` の1オクターブ上）。第1版の規則として固定（api/web で同一の定数）。
- **`followChords: true`**＝生成時は区間をまたぐ音が無いが、進行を変えたあとの跨ぎは境界で切り新コードで度数を再解決（左手 custom と同じ規則・`design.md:555`）。
- **来歴**＝`gen?: { engine:"handframe", version, seed, level, preset, cellBeats }`（additive・「配り直す」の種）。
- **`voicing`**＝従来どおり持つ（keyboard・top）。**明示音の無い打点（人がエディタで足した打点）だけが `voiceToTop` で鳴る**＝§9 (4)。
- **`steps = grid × bars`**（8小節 4/4＝128）。**現行の `steps` の上限とエディタの描画を S0 で実コード確認**（テンプレは 1〜2 小節のタイル張りが前提・`design.md:556`）。

**置き場の判断**＝`degreeInterval`・`rootRef`・明示音の解決は **`packages/music-core`**（api/web 共有・`design.md:2129` の前例）に置く。api の生成器は「絶対音→明示音」の写しに**同じ関数の逆**を使い、web はその関数で実音化する。→ **往復一致は「同じ関数を両側で使う」ことで構造的に成立**し、テストは (i) 写し→解決が恒等（生成器の絶対音列＝解決結果）(ii) web の `resolveChordPattern` が明示音を素通しで同じ音を出す、の2段。

**新ボイシング（案A＋B）との関係**
- 明示音は `voiceToTop` を通らないので、**案A＋B の影響を受けない**（積み直されない）。逆に、案A＋B の改訂で得た知見（右手最低音の低音域ガード・7th の位置・`docs/research/2026-09-16-organ-voicing-muddiness-rootcause.md` §6）は、手の形の出力の**診断**として持つ（床 52 で右手は E3 以上・殻は 52〜72＝概ね守られる見込み・違反数を数えるだけ・合否にしない）。
- 案B の「左手が R を弾くとき右手から R を抜く」は、殻（3/7）には発火しない。人が左手を root に変えても右手の明示音（R を含む確立）はそのまま＝ルートが重なる（許容・文書に残す）。
- **経路は1本のまま**＝`resolveChordPattern` の中に「明示音あり→素通し」の分岐が増えるだけ。実音化を2本にはしない（09-16 版 §4 ①への切替は不要の見込み）。

### 4-3. 往復一致が取れない場合（再裁定の材料・見込みは低い）

取れないと分かるのは (i) `steps` の上限やエディタが N 小節の content を受けない (ii) 明示音の additive が既存 content の bit 一致を崩す、のどちらかです。そのときの選択肢：

| 選択肢（20字） | 説明（40字） | 推し |
|---|---|---|
| ①明示音の口を足す | 本節の形。経路1本・既存は bit 一致・進行に付いてくる | **①**（第一に試す） |
| ②その場で毎回作る | 生成器を music-core に置き web でも走らせる。経路2本・進行に完全追従 | ①が (i) で落ちたとき |
| ③絶対 notes で持つ | 焼き込み。移調・進行変更に付いてこない＝是正中の違反を増やす | 採らない |

## 10. 自信の無い点

- **契約の細部は実コード未読**＝`ChordHit` に `notes` を足せるか・`steps` が 128 を受けるか・エディタが N 小節を描けるか（S0 の確認項目）。落ちれば §4-3 ②。
- **bit 一致の到達**＝`math.exp` の ULP と `sorted(..., key=(score, diag))` の同順位規則（`diag` の型が Python の比較規則に依る）。取れなければ撤退基準①で耳A だけに切り替える。
- **ペダルの近似**＝#2 で外した3つのうちペダルが効いていた場合、長さ延長では試作の良さが出ない可能性。§9 (2) で先に分かる。
- **ばらしの近似**＝feel 層の humanize プロファイルが `jitter_sd_ms=3.0`・`max_lead_ms=25` に近い揺れを出せるかは未確認（プロファイルを1つ足す可能性）。
- **和音表の差**＝向こうの `chordlib` と Otomemo の質の表（9/11/13・sus・dim）で構成音・和音音階が違えば、基準音との bit 一致は Fmaj7/G/Em7/Am7 の範囲でしか主張できない。基準音の進行はこの4つに限る。
- **N 小節の content**＝Otomemo のテンプレは 1〜2 小節のタイル張りが前提。8〜16 小節の通し content を「パターン単位で直す」体験が成り立つかは実機で見るまで分からない。
- **`beat_every = grid // 4`** は grid12 で拍と一致しない（第1版は 4/4 だけなので影響なし・6/8 を配る前に直すか判断）。

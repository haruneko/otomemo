## 件1．詞モード（1音符ずつの直し）の扱い

### (a) 事実（実コードで確認）

- **一等地にある**：モード行は「描く／選ぶ／消す／**詞**」の4つ。`apps/web/src/components/KindEditorBody.tsx:172-191`（詞ボタン＝`:188-190`・メロのときだけ出る `:187`）。
- **説明が出るのは押したあとだけ**：ボタンの説明は `title="詞（音符タップで歌詞を編集）"`（`KindEditorBody.tsx:188`）＝**マウスを載せたときに出る仕組み**なので、**スマホでは一度も表示されない**。押して入ると固定バーに「音符をタップして歌詞を編集」が出る（`apps/web/src/components/PianoRoll.tsx:446`）＝使い方は入ったあとにしか読めない。
- **他の3つはアイコン・詞だけ文字**：描く＝鉛筆SVG（`KindEditorBody.tsx:173-175`）、選ぶ＝破線の四角（`:178-180`）、消す＝消しゴム（`:184`）、詞＝漢字1文字「詞」（`:189`）。ボタン幅は `min-width:40px`（`apps/web/src/styles/transport-cards.css:1829-1835`）。
- **中身は動く**：音符タップ→かな入力→「確定→次」で時間順に次の音符へ（`PianoRoll.tsx:119-141`＝`lyrCommit`・バーは `:441-478`）。打ったかなは句の直し（edits）として取り込まれる（`:126`）。詞モード中は音符の作成・移動・削除が無効（`:344-352`・`:367`）。
- **入ったのは 2026-07-15**（commit `1c47b59`）＝約2週間前。
- **「使われていない」という証拠は無い**：このアプリに利用ログ・計測の仕組みは無い（`apps/web/src`・`apps/api/src` に該当なし）。分かっているのは「オーナーが存在を認識していなかった」という1つの事実だけで、**触ってみて要らなかった**のか**気づかなかっただけ**なのかは、いまの材料では区別できない。
- **先例の側の事実**：調査15種すべてが、音符上の1つずつの編集を最短の口に置いている（まとめ入力が最短で個別が奥、というツールは0種）。逆に VOICEVOX は口を1つに兼ねた結果「機能があることに気付けない」が課題化した（[issue #2116](https://github.com/VOICEVOX/voicevox/issues/2116)・`docs/research/2026-07-29-lyric-input-ui-survey.md` §8）。

### (b) 案

| 案 | 何が変わるか（1行） |
|---|---|
| **A そのまま** | 何も変えない。まず実機で触ってから決める |
| **B ボタンに言葉を出す** | 「詞」を短い言葉に替えて、押す前に用が読めるようにする |
| **C パネルの中へ移す** | モード行から外し、歌詞パネル内のボタンから入る形にする |
| **D 入口を2つにする** | モード行に残しつつ、歌詞パネルからも入れる |
| **E 廃止する** | 詞モードを消し、1音ずつの直しは別の形に寄せる |

（別枝）**文脈行を足すか**＝バーを1行→2行にして「語・機械の読み・高低・手直し済み」を出す案（画面設計 §3-3）。**足す／今は足さない**の2択。足すと詞モード中だけ約40px増える。

### (c) 表

| 案 | メリット | デメリット | 上位との整合 |
|---|---|---|---|
| A | 何も壊れない。判断材料を先に取れる | 気づかれない状態が続く。裁定が1回先送りになる | 「観察を確定要件に硬化させない」＝触る前に決めないのは筋が通る |
| B | 発見性の唯一の穴（説明が `title` だけ＝スマホで出ない）に直接効く。位置は動かさない | モード行の幅を食う（360px で収まるかは要実測）。文字が増えてアイコン3つと不揃い | 先例の標準形（個別編集を最短に）を保つ |
| C | モード行が3つに戻って軽い。歌詞の用が1か所に集まる | 「1音ずつ直す」が2タップ奥へ＝先例15種で0種の配置になる | 「個別の音符の修正がメイン」というオーナー自身の見立てと逆向き |
| D | 気づく機会が2つ。どちらの入り方でも届く | 実装が2か所。パネル側の裁定（件2）に依存して着手が遅れる | 発見性は最大。ただし口を増やす＝画面が太る |
| E | 画面が最も軽い | 個別修正の口が消える。先例と逆・オーナーの見立てとも逆 | 「機械は詰めない・選ぶのは人」＝人が直す口を減らすのは不利 |

### (d) 推し＝**B（ボタンに言葉を出す）**

理由は3つ。①**穴が特定できている**＝この道具の説明は `title` 属性1つで、それはスマホでは出ない（`KindEditorBody.tsx:188`）。アイコン3つの並びに漢字1文字が混じっているだけなので、押す前に何ができるか分からないのは自然なこと。②**位置は動かさない**＝「1音符ずつの修正が主動線」という見立て（先例15種の構造と一致）を壊さない。③**安い・戻せる**＝文字を替えるだけで、判断が変わってもすぐ戻せる。

**ただし、B を入れる前に一度だけ実機で触ってほしい**（3分）。これで A/B/C の分岐が確定します。

1. スマホ幅で、歌詞の入ったメロを開く。
2. こちらから何も説明せずに、モード行の「詞」を押す → 音符をタップ → かなを打つ → 「確定→次」を2〜3音ぶん続ける。
3. 答えてほしいのは2つだけ。**「押す前に、これが何のボタンか分かったか」**／**「1音だけ直したくなったとき、ここを探しに来ると思うか」**。

「探しに来る」なら B（言葉を足すだけ）。「そもそも使わない・パネルから入れれば十分」なら C。「押す前に分かった」なら A（据え置き）。

**文脈行（別枝）の推し＝今は足さない。** 理由＝機械の読み・高低・手直し跡を出すのは価値があるが、詞モード自体の形が決まる前にバーを太らせると、C になった場合に作り直しになる。件1が決まった次のスライスで足すのが安い。

## 件3．韻律チェックのトグルを歌詞パネルの奥へ移すか

### (a) 事実

- トグル行＝`PianoRoll.tsx:512-530`。**どれかの音符にかながあるときだけ出る**（`:512` の `hasLyric`＝`:100`）。ONのときだけ凡例「赤=アクセント逆行／黄=注意」が並ぶ（`:523-528`）。
- **既定ON**（`:95` `useState(true)`）。
- **OFF は覚えない**：`showFit` はこの部品の中の状態なので、**ダイアログを閉じて開き直すと必ず ON に戻る**。保存先（localStorage 等）に書いていない。
- **印そのものは行とは別**＝音符矩形の下辺ボーダーと ⓘ アイコンで描いている（`:615` 付近・`:650` 付近）＝トグル行を奥へ移しても印は消えない。

### (b) 案

| 案 | 何が変わるか（1行） |
|---|---|
| **A 奥へ移す** | 常設から1段消える。ON/OFFはパネルの奥 |
| **B 奥へ移す＋覚える** | 同上に加え、OFFにしたら次に開いても OFF のまま |
| **C 常設に残す** | 行は残し、凡例だけ畳んで1行を細くする |
| **D 行ごと廃止** | 常時ON。OFFにする道を無くす |

### (c) 表

| 案 | メリット | デメリット | 上位との整合 |
|---|---|---|---|
| A | 常設が1段減る（縦の回収に直接効く） | OFF が毎回リセットされるので、奥にあるぶん「毎回2タップで消す」になる | 画面設計案どおり。印は既定ONのまま＝機械の助言は消えない |
| B | 奥へ移しても手間が増えない。設定として筋が通る | 保存を1つ足す（既存の流儀＝localStorage） | 「表示したいパーツを選べるように」（過去裁定）の実装になる |
| C | 何も壊さない | 1段そのまま残る＝回収が減る | 縦を空ける目的に対して弱い |
| D | 最も単純 | 印を消す道が無くなる＝赤黄がうるさいときに逃げ場がない | 「機械は候補まで・選ぶのは人」に反する（消せないのは押し付け） |

### (d) 推し＝**B（奥へ移す＋覚える）**

理由。①奥へ移すこと自体は縦の回収に効く（常設が1段減る）。②ただし今の実装は OFF を覚えないので、A のまま奥へ入れると「うるさいから消す→開き直すと復活→また奥へ潜って消す」が毎回になる。③覚える置き場は既にある流儀（設定は localStorage・design §31-9）で、追加は小さい。

## 件4．文言

**変え方の費用（事実）**：画面から読める言葉を変えても、テストが握っているのは英語の `aria-label`（`lyric-phrase-status` 等）なので大半は壊れない。**例外は2か所**＝`apps/web/test/PianoRoll-lyric.test.tsx:315`（`"ちょうど"`）と `:323`（`"字余り3"`）が文字そのものを期待している。状態チップの言葉を変えるなら、この2行を先に直す。

### 4-1. 状態チップ（常時1行に出る言葉）

| いま | 出る条件 | 案1 | 案2 |
|---|---|---|---|
| **ちょうど**（`:319`） | 詞と音符の数が合っている | 据え置き | ぴったり |
| **字余り2**（`:316`） | 詞が2音ぶん多い | 据え置き | 詞が2音多い |
| **あと3音**（`:318`） | 音符が3つ余っている | **字足らず3**（字余りと対になる詩歌の語） | 詞があと3音 |
| **メロがまだ途中**（`:314`） | 範囲に1小節以上の空きがある | 据え置き | メロに空きがある |
| **メロなし**（`:312`） | 範囲に音符が1つも無い | 据え置き | 音符がまだ無い |
| **（言葉が無い＝チップが消える）** | 表記を直して反映していない | **まだ反映していません** | 読みが古いままです |
| **（歌詞が空）** | 句が無い | 歌詞を書く | ＋歌詞 |

- 「あと3音」だけ主語が曖昧（3音ぶん詞が足りない、の意）。**字余り／字足らず**は詩歌の対語で造語ではない＝並べたときに向きが読める。
- 「まだ反映していません」はボタン「読みを反映」と動詞をそろえた形＝**押すべきボタンの名前がチップから読める**。

### 4-2. 読みの様子（パネルの中に出る言葉）

| いま | 案1 | 案2 |
|---|---|---|
| 読み：とけいのはりがとまる（10音）（`:301`） | 据え置き | とけいのはりがとまる／10音 |
| 読みを取っています（`:297`） | 据え置き | 読みを取っています… |
| 読みが取れませんでした（`:299`） | 据え置き | 読みが取れませんでした（表記と音符はそのまま） |
| 読みを取ります（`:302`＝まだ押していない状態） | まだ読みを取っていません | 「読みを反映」を押すと読みます |

「読みを取ります」は宣言とも予告とも読めるので、**まだ起きていないこと**が読める形にしたほうが誤解が少ない（機械が勝手に動くように読めない）。

### 4-3. 操作の言葉

| いま | 場所 | 案1 | 案2 |
|---|---|---|---|
| 読みを反映（`:436`） | パネル | **据え置き（2026-07-29 裁定済み・この表では動かさない）** | — |
| クリア（`:505`） | パネル奥 | かなを消す | 音符のかなを消す |
| （無し＝「読みを反映」に統合済み） | パネル奥 | 読みを取り直す | 読みをもう一度取る |
| （未実装・存否は研究の監査待ち） | パネル奥 | 音符を割って詞に合わせる | 音符を増やして合わせる |
| 詞（`KindEditorBody.tsx:189`） | モード行 | **1音ずつ** | 詞を直す |
| 詞（`:444`） | 詞モードのバー見出し | 1音ずつ直す | この音符の詞 |
| 音符をタップして歌詞を編集（`:446`） | 詞モードのバー | 据え置き | 音符をタップすると1音ずつ直せます |
| かな（空=消す・ー=のばす）（`:454`） | 詞モードの入力欄 | 据え置き | — |
| 確定→次（`:463`） | 詞モードのバー | 据え置き | 次の音符へ |
| 韻律チェック（`:521`） | パネル奥 | 据え置き | ことばと音の高さの印 |
| 赤=アクセント逆行／黄=注意（`:525-526`） | 凡例 | 据え置き | 赤=高低が逆／黄=注意 |

- 「音符を割って…」の行は**存否そのものが未確定**（design §31-5＝「音楽的に成立する割り方を候補として出せるか」の研究＝`docs/research/2026-07-30-lyric-overflow-note-split-research.md` が独立監査中）。**作らない結論なら、この行ごと消える。**
- モード行の言葉（「詞」→「1音ずつ」）は件1の案Bを採る場合だけ効く。

### (d) 推し＝この一式

- 状態チップ：**ちょうど／字余り2／字足らず3／メロがまだ途中／メロなし** ＋ 新設 **まだ反映していません**（歌詞が空のときは「歌詞を書く」）。
- 読みの様子：**「読みを取ります」→「まだ読みを取っていません」**、他は据え置き。
- 操作：**「読みを反映」据え置き／「クリア」→「かなを消す」／モード行「詞」→「1音ずつ」／韻律まわりは据え置き**。

理由。①**変える数を最小にする**＝今の言葉は既に普通の日本語で、比喩も内輪語も入っていない。触るのは「意味の向きが読めない」ものだけ（あとN音・読みを取ります・詞）。②**押すべきボタンの名前が状態から読める**（まだ反映していません → 読みを反映）。③**字余り／字足らず**は対で並ぶので、どちらに転んでいるかを1語で見分けられる。
